# 文档地图

> 根目录只留四份长期文档；细节全部收在 `docs/` 下，按「要不要读」分层。

## 长期维护（根目录）

| 文件 | 什么时候读 |
|---|---|
| `README.md` | 第一次接触项目：是什么、几个页面、怎么跑、API 速查 |
| `PITFALLS.md` | **动手改代码前必读**：192 条踩坑铁律，几乎每条都对应一次真实事故 |
| `WORKFLOW.md` | 发布流程、排他约定（改仓库 = 排他操作）、收尾检查清单 |
| `ROADMAP.md` | 功能规划、做过的取舍、明确不做的方向 |

## docs/

| 目录 / 文件 | 内容 |
|---|---|
| `versions/` | **唯一版本真源**：每版一份 `vX.Y.md` + `README.md` 索引表 |
| `versions/README.md` | 版本索引（新→旧），一行一版，摘要即结论 |
| `sop/` | 抓取类 SOP（如 FR 源抓取流程） |
| `reports/` | 每日名单产物与专项评估报告；自动清理只保留最近 7 期 |
| `archive/` | 过期文档，仅作历史留存：`HANDOFF.md` / `CODEX-HANDOFF.md` / `CODEX-TASKS.md` / `DESIGN.md`（内容停留在 v10.0–v10.10，**不要当成现状**） |
| `archive-cleanup-2026-10-14/` | 09-20 / 10-14 两次清理的归档说明 |
| `ONLINE-DOWNLOAD-PLAN.md` | 云下载（v10.92）前置实测与实施计划；文首引用的两份调研稿已随清理移除 |

## 查什么去哪

| 想知道 | 看 |
|---|---|
| 这版改了什么 / 为什么改 | `docs/versions/vX.Y.md` |
| 某处代码为什么写成这样 | `PITFALLS.md`（按编号搜关键词） |
| 线上是不是最新 | `node tools/report.js`（比 md5，不看 200） |
| 还有哪些没做 | `ROADMAP.md` + 最新版本日志末尾的「待办」 |
| 数据从哪来、多久更新 | `README.md`「数据源」 + `daily-sync.js` |

# v10.100 仓库与 README 精简（纯文档改动，产品代码零变更）

> 用户口径：「帮我优化 github 的内容，以及 readme，尽量精简」

## 一、结论

| 项 | 改前 | 改后 |
|---|---|---|
| `README.md` | **1,568 行 / 143 KB**，前 476 行是 v10 / v9.3 / v9.1 / v9 / v8 五段历史叙述，版本摘要块 5 个 | **117 行 / 8 KB**，一屏读完：六页做什么 → 规模 → 快速开始 → 数据源 → 目录 → API 速查 → 测试 → 文档地图 → 当前版本 |
| 根目录 `.md` | 9 份（README / PITFALLS / ROADMAP / WORKFLOW / HANDOFF / CODEX-HANDOFF / CODEX-TASKS / DESIGN + 说明） | **4 份**（README / PITFALLS / ROADMAP / WORKFLOW） |
| 过期交接文档 | 停在 v10.0–v10.10 却躺在根目录，最容易被当成现状 | 全部 `git mv` 进 `docs/archive/`，历史留在 git 里，随时可 `git log --follow` |
| 文档入口 | 无 | 新增 `docs/README.md`：四份长期文档各读什么、`docs/` 每个子目录装什么、六个常见问题去哪查 |
| 根目录草稿 | `_preview-cards.html`（70 KB）+ `_preview-cards.js`（09-10 的一次性预览） | 归档为 `docs/archive/preview-cards-20260910.*` |

**为什么 README 要砍到这么短**：它的读者只有两种 —— 第一次打开仓库的人（想知道「这是什么、怎么跑起来」）和回来查接口的人。两种需求都不需要 34 个版本的历史叙述；版本史的唯一价值是「某版为什么这么改」，而它已经在 `docs/versions/` 里逐版写全了（99 份）。

## 二、README 保留了什么（判据）

只留能回答五个问题的内容，每个问题占一节：

1. **是什么** —— 一句话 + 「只做聚合、不托管文件」的定位
2. **有哪些页面** —— 六页表格（路径 / 做什么），一屏看完
3. **现在多大规模** —— 七行数据表，全部 2026-10-22 线上实测
4. **怎么跑起来** —— `npm i && npm start` + 直达参数 + 定时任务时间
5. **怎么查更深的东西** —— 数据源表 / 目录树 / 12 条常用 API / 测试命令 / 文档地图

删掉的是：v8–v10 的分版本叙述（已进版本日志）、逐条 API 全集（40+ 行，改指 `server.js` 注释）、目录树里每个文件的逐行注释（90 行 → 17 行，只标不可手改的派生页）、「输出/缓存目录」整张表（`.cache/` 清理红线已写在 `PITFALLS.md`）。

## 三、闸门同步（改判据，不是放宽）

精简会让三条既有断言**静默失真**，逐个改：

| 套件 | 原判据 | 现判据 | 为什么 |
|---|---|---|---|
| `test-doc-structure` | README 版本摘要块 `>0 && ≤6` 且排在 H1 之后 | **`= 0`** 且 H1 在 L1 | 版本摘要彻底离开 README。只写「=0」会被「README 被删空」满足 ⇒ 另加两条正向锚点：必须有「## 当前版本」+ 链到该版日志、必须有「## 快速开始」+ `npm start` |
| `test-doc-structure` | `H1_EXCEPTIONS` 登记 HANDOFF / CODEX-HANDOFF（各 2 个 H1） | **空表**（保留机制） | 两份已迁 `docs/archive/`，不再进入扫描范围；「陈旧例外」自检立刻报了这两条，正是它该干的 |
| `test-report` | 直接读根目录 `HANDOFF.md` / `DESIGN.md` 验证「已归档」标记 | 改读 `docs/archive/` 下同名文件 | 迁走 ≠ 可以冒充最新：它们照样会被搜索到。**路径改了，判据一条没删** |
| `test-report` | — | 新增「根目录只剩四份 md」正向锚点 | 否则上面几条在根目录也能全绿，归档会不会被「搬回来」没人守 |

## 五、没做的事（如实列出）

- **没有动 git 历史**：132 MB 的 `.git` 里有大量历史大文件（`data/mods.json` 等每日变更），压历史需要 `filter-repo` 强推，会破坏所有克隆 —— 收益只是克隆变快，不值。
- **没有删数据**：`data/`（业务数据）与 `docs/reports/`（每日名单，已有 KEEP=7 自动清理）保持原样。
- **没有改产品代码**：`public/**`、`server.js`、`data/**` 零改动，线上六页 md5 与本版前一致。

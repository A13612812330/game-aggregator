## 二、四个缺陷（每个都是**量出来的**，不是猜的）

| # | 缺陷 | 根因 | 实测影响（改前 → 改后） |
|---|---|---|---|
| **①** | `cpu_abi` 归了 `cpu`，**arch 维度永远缺** | `KEY_RULES` 顺序：`cpu` 排在 `arch` 前，而 cpu 的关键词里有**宽词** `cpu`（判据是 `k.includes(w)`）⇒ `cpu_abi` / `cpuarch` 被抢走，arch 那一行精心写的 `cpuabi` 成了**死词** | 只有 `cpu_abi` 的配置：arch **unknown 16,519（100%）** ⇒ 判定「待确认 **14,552** · 信息不足 240 · 不可跑 1,727」→ arch **fail 16,519（100%）** ⇒ 「不可跑 16,519」 |
| **②** | `VULKAN_VERSION:"1.3"` 被读成「**支持 DX 1.3**」 | 图形接口那段**无条件** `dxOf(raw)`；而 `dxOf` 的兜底正则会把**裸数字**当 DX 版本 —— 裸数字无法自证是 DX | `dxCap()` 上限被压到 **1.3** ⇒ 「不可跑 **8,505**」→「不可跑 **699**」= 消除 **7,806 款假阴性**；且与「同设备改挂 `vkd3d`」的参考组（流畅 10,080 / 可跑 5,739 / 不可跑 700）几乎完全一致 |
| **③** | `minRequirements.space` 不认识 | storage 关键词没有 `space`（只有 `diskspace` / `freespace` / `可用空间`） | 要求档存储 **null → 70 GB** |
| **④** | **机型认不出来** | `nameOf()` 只看**顶层字符串键** ⇒ `device.model`、中文 `机型` 都取不到 | 记录名 `''`（页面显示「记录 #1」，用户无法确认「你认没认出我这台机器」）→ `Xiaomi 24095PCADG` / `小米 15` |

字段识别率随之 **89.6% → 91.0%**。

### ★ 顺手堵掉一个「识别率虚高」的口子

`space` 进关键词后，`namespace` 会被 `k.endsWith('space')` 一起吃成**存储** ——
「未识别」被算成「已识别」，识别率就虚了。所以给规则加了 **规则级排除项 `not`**：
`namespace` / `workspace` / `keyspace` 直接不归 storage，老实留在 `unknown` 里。

## 三、口径变化（这条必须知道，别当成纯 bugfix）

`cpu_abi` 现在能读出「这是 ARM 设备」了，于是：

- **兼容层里写了 `box64` / `box86` / `FEX`** 的配置（解包工具最常见的导出形态）⇒ arch 判 **ok**，
  原先因 arch 缺而落「待确认」的**大批游戏变成可判** —— 这是直接收益。
- **没写任何 x86 转译层**的配置 ⇒ arch 判 **fail** ⇒ 整款「不可跑」。
  语义上站得住（ARM 无转译层确实执行不了 x86 程序，这也是 `spec-match.js` 里
  ★ 标注过的既有口径，有断言钉着），但**它改变了 14,552 款的结论**：从「待确认」变「不可跑」。

> 若你的口径是「**没给兼容层信息就该保持『待确认』**」，那要改的是
> `data/spec-match.js` 的 `cmpArch`（区分「明确列了层但没有转译层」与「压根没给层信息」），
> **不属于本次字段校准**。改之前请说一声 —— 现在有断言把现状钉住，改它必须一起改断言。

### ★ 反证当场抓出我 3 处错误（它存在的意义）

1. **第一条变异「只删 `cpuabi`」打不红** —— arch 的 kws 里还有更窄的 `abi`
   （`'cpuabi'.includes('abi')`）把结果兜住了。实现在这里是**两层防** ⇒ 变异必须两层一起拿掉。
2. **第二条变异「只把 `v` 那行退回无条件 `dxOf`」也打不红** —— 后面 `if (kind0)` 分支仍在把
   vulkan 键归成 vulkan（算出 `v` 却没人用）⇒ 真正的「旧写法」是**没有 `kind0` 这层**，变异得整体回退。
3. **第三条栽在逗号上**：替成空串后数组变成 `'architecture' '指令集'` ⇒ **SyntaxError** ⇒
   套件直接崩、**一行 FAIL 都没打印** ⇒ 反证工具只看到「没有任何 FAIL 行」。
   ⇒ 由此给套件加了 `dxV()` / `archRaw()` 等**防崩取值助手**：断言必须能**报出结论**，
   而不是自己被 `undefined.v` 崩掉（崩溃会被误记成「断言抓住了」，其实是两回事）。

## 3. 改了什么

### 3.1 骨架：固定侧栏 → 浮动侧栏
原来 `.side` 是 `position:fixed`，`.main` 用 `margin-left:230px` 让位。
现在 `.shell` 是 `12px` 内边距的整屏 flex，侧栏是 `230 × calc(100dvh - 24px)` 的圆角卡片
（`.main` 的 `margin-left` 已删）。主区圆角 `10px`，自身滚动，顶栏 `sticky` 吸顶。

### 3.2 新增页签条
`.tabsbar` + `.tab`，当前签下面 2px 主色条 —— 对齐参考站 `.tabs-view / .tab__bar`。
**文案由 `go()` 现写**，不是写死：切「磁力下载」时页签同步变（实测见第 4 节）。
没有做成「可关闭多页签」：这是单页 hash 路由，做多开是假交互。

### 3.3 环境徽标：按 hostname 现判
侧栏品牌行加 `.env-badge`：回环地址显示「本机」，其余显示「线上」。
不写死任何一个 —— 同一个文件既在本机 8123 跑、也在线上容器跑，写死会在另一边说假话。

### 3.4 统计卡改 4 列
原 `auto-fill minmax(160px,1fr)` 在 1440 宽下排成 6+2，第二行两张卡孤零零。
本页恰好 8 张 ⇒ 改 `repeat(4,…)` 后是整齐的 4×2，也与参考站列数一致。

### 3.5 对比度修了两处（主动偏离参考的地方，各写了原因）
- **主按钮底色**用 `--acc`(#bf6a50) 而不是参考的 `#e79379`：后者配白字只有 **2.6:1**，
  按钮文字看不清；同色系压深一档后约 4.4:1。
- **页码选中态**同样改用 `--acc`（白字实底）。
- 统计数字**改回正文黑**（参考站 `.stat-card__value` 就是 `--foreground`），
  原来染主色会让 8 张卡的数字都在抢注意力。

### 3.6 补齐一个漏网的控件
`.dlcfg`（下载器设置）里的「自动起种」是 `<select>`，原来没有任何样式，
掉回浏览器默认灰白控件 —— 与整套皮明显不搭，这版补上。

## 5. 踩坑

1. **换肤最容易"静默退回"**：样式改回去页面照样能开，功能测试全绿也发现不了。
   ⇒ 新增 `test-v10105-admin-theme.js` 守形状（浮动侧栏、4 列、页签钩子、hostname 判断），
   并加了反向断言：旧蓝 `#2563eb` / `#1d4ed8` / `rgba(37,99,235` 必须清零。
2. **反向断言会被注释咬**：本文件里解释「为什么不用蓝色」的注释本身就含 `#2563eb`。
   ⇒ 一律**先剥注释再判**（`stripComments`），并配一条阳性对照（剥完后 CSS 仍 > 8KB 且含 `.side`），
   防止剥注释这一步把整张样式表吃掉（铁律 201）。
3. **`$('vTab').textContent = t` 不能裸写**：老缓存里的 DOM 可能还没有这个节点，
   裸写会抛错把 `go()` 打断 ⇒ 整页白。已加判空，并用反向断言钉住。
4. **`.dlcfg input` 第一眼看"缺框"**：实际是 placeholder 太长被截断（`留空 = %USERPROFILE%\…`），
   量过尺寸 258×32 才确认它一直在 —— 不量就差点去改一个没坏的东西。

## 8. 部署体检时顺手捞出来的两件事（不是换肤，但不修会一直骗人）

### 8.1 本机根本没法「拉线上算 md5」⇒ 加 `/api/build`

按铁律判版要比 md5，可这台发布机上：

| 通道 | 实测 |
|---|---|
| `curl https://…/`（走代理） | `CONNECT tunnel failed, response 502` |
| `curl --noproxy '*'` | `Could not resolve host` |
| `Invoke-WebRequest` | `The remote name could not be resolved` |
| Node `fetch`（不读代理直连） | `fetch failed` |
| `curl https://example.com`（同代理） | **200** ⇒ 代理本身是好的，只是这个域名解析不了 |

也就是说：**发布机出不了网不是配置问题，是网络边界问题**，这条路永远断。
⇒ 让**线上自报**：新增 `GET /api/build`，启动时把 `public/*.html` 的 `md5`（前 10 位）与字节数
算好缓存，任何人（包括只走 Agent 网络的 WebFetch）都能拉到精确值与本地比。只回文件名/md5/字节数。

首拉实测（与本地逐项相同）：

| 文件 | 线上 md5 | 字节 | 本地 |
|---|---|---|---|
| admin.html | `5aea93b9b9` | 145,788 | ✅ 相同 |
| index.html | `6b75ecbe11` | 651,287 | ✅ 相同 |
| emulator.html | `878278eb69` | 716,146 | ✅ 相同 |
| unpack.html | `f2d2a081b8` | 688,498 | ✅ 相同 |
| resources.html | `79b78a5fde` | 701,009 | ✅ 相同 |
| extract.html | `4d5b18915c` | 691,451 | ✅ 相同 |

### 8.2 线上躺着一个仓库里从未有过的页面

`/api/build` 第一次拉回来 **7** 个 html，第 7 个是 `overview.html`（16,319B）——
可它在源码、载荷目录、`git log --all` **三处都不存在**，而线上 HTTP **200** 且内容完整
（一个「规模速览 / 功能 / 数据源」的旧总览页，数字还停在 19,397 / 8,943 那套旧口径）。

- 根因：发布是「**保留 + 覆盖**」——文件一旦进了容器就再没有代码路径去删它；
  而仓库里对它的引用是 **0**（grep 全站 + 全历史），所以没人会发现它还在。
- 处理：`DEAD_PAGES = new Set(['overview.html'])`，对外 **410**。
  名单只有这一份：410 路由与 `/api/build` 的扫描**共用**它
  （两处各写一份的话，自证清单会永远比本地多一页 —— 那是自己制造的、永远修不掉的差异）。
- 容器里的物理文件删不掉，但**对外表现与仓库一致**了。

### 8.3 差点被"缓存"骗去搞破坏（记一笔）

验证 `/api/build` 时连续三次拿到**同一个 `bootAt`**，据此判断「部署只同步文件、不重启进程」，
甚至准备走 `unpublish → deploy` 强制重建 —— 那是破坏性操作。
真相是**抓取通道对同一 URL 有 15 分钟缓存**：加 `?cb=…` 后 `bootAt` 立刻变了，
新代码一直在跑。

`bootAt` 这个量特别容易骗人：它**天生就该是不变的**，所以"三次都一样"看起来完全合理。
⇒ 通则：**用同一 URL 反复观测会变的量，必须先破缓存**；观测通道本身有缓存时，
它报告的"没变化"一律不可信（已写进 `PITFALLS` 铁律 204）。

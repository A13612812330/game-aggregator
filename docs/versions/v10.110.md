> 2026-10-23 · 只动 `public/index.html`（下载弹窗的渲染层）+ 四张派生页重建。
> 后端**零改动**：`/api/mods/match`、`/api/saves-yx/match`、`/api/trainers/match` 的返回结构不变 ——

## 0. 用户原话与定位

> 「② 下载入口均只展示前三条，若有多个下载源或下载内容则在下载弹窗中需要提供筛功能（类似目前已有网盘的筛选）」

这句里**前半句已经实现了**（v10.28 定的口径）：详情页 `#dlSlot` 的「本体 / Mod / 修改器」三块
每块只露前 3 帖（`DL_PREV_CAP = 3`），多的走「全部 N 帖 →」进弹窗。
所以本版做的是**后半句**：「弹窗里要能筛」。

| 页签 | 改前 | 改后 |
|---|---|---|
| 本体 | 有「盘口」chip（v10.29 起） | 原样保留，一行没动 |
| Mod | **零筛选**，最多铺 60 条机地帖 + Thunderstore 段 | 「来源 / 通道」两维 |
| 修改器 | **零筛选**，机地帖 + FLiNG/CheatScript 段 + GTrainers 段 | 「来源 / 通道」两维（来源有 4 类） |
| 存档 | **零筛选**，最多 20 条游侠文件 + GTrainers 段 | 「来源 / 通道」两维（通道含直链/网盘/迅雷/eD2K） |

## 1. 为什么是「两个维度」而不是一个筛选框

用户要挑的是两件不同的事：

- **来源** `src` = 这条数据从哪个站来（机地 / Thunderstore / 风灵月影 / CheatScript / GTrainers / 游侠）
- **通道** `ch` = 这条真正拿东西的路（直链 / 百度网盘 / 迅雷云盘 / 夸克网盘 / eD2K …）

合成一个下拉，会把「我想找能直接下的」和「我想找去百度取的」混成同一种诉求。
实测样本（赛博朋克2077）的 Mod 页签：通道 5 个 chip、来源只有机地一种（此时来源行不摆，见 §3）。

## 2. 实现

| 位置 | 内容 |
|---|---|
| `dlFltOf(k)` | 取某页签的筛选态；状态挂在 `dlUni.flt[kind]` |
| `dlFltOk(r, f)` | 单行判定：`src` 单值、`ch` **多值**（一行可有多条通道，有一路对得上就算通过） |
| `dlFltOpts(rows, dim, f)` | 某维度各值的条数，**只应用另一维度**的筛选 |
| `dlFltRow(...)` | 一行 chip；只有一个取值且未筛选时**不摆**（无效控件） |
| `dlFltBarHtml(kind, rows, names)` | 整个筛选条；有筛选生效时追加「清空筛选」 |
| `dlFltNoneHtml(kind)` | 筛完一条不剩的空态，自带清空出口 |

样式复用本体已有的 `.dl-bar` + `.dl-chip`（同一套视觉），只新增 `.dl-bar.dl-flt{position:static}` ——
本体那条是 `sticky; top:-12px`，Mod/修改器/存档三页有 `.dl-agg` 分段，吸顶条会横跨两段。

**打标方式**：四个段（机地 / TS / GCM / GT）按固定顺序拼成一条 `barRows`，用**同一组索引**分别取出各段的 keep 集合。
不这么做（每段各 filter 一次）就会出现「chip 写机地 3、列表只有 1 条」这种数字对不上。

## 3. 三个刻意的设计决定

1. **通道名保留源站全名，不剥「网盘 / 云盘」后缀**
   第一版按 `dlModLinkBtns` 的口径剥了，实拍发现存档页签同时出现「迅雷」与「迅雷链接」——
   一个是网盘通道、一个是 `thunder://` 协议，两个不同的东西读起来像重复。
   `.dl-chip` 本身 `white-space:nowrap`，取名全不折行，只是整行变宽后换行。

2. **只有一个取值时不摆该维度**
   「全部 5 / 机地 5」不切换任何信息，与 `dlBarHtml`「只有一个分区就不摆签」同一条判断。

3. **空态判据仍用**原始数据层的 `!c.items.length` / `!items.length`，**不是**筛后的 `keep`
   换成筛后的话，用户筛「Thunderstore」时会看到「机地没有收录 Mod」这句假话（机地其实有 60 条）。

## 6. 本轮踩到的三件事（已写进 PITFALLS 219–221）

### 6.1 改「筛后集合」时把 `kind` 条件一起改没了

原：`if (kind === 'modifier' && gtr.length) out.push(dlResSection(gtr, '修改器'));`
我改：`if (gtKeep.length) out.push(...)` —— 只换了数据变量，**顺手把 `kind === 'modifier'` 丢了**。
后果：`mod` 页签也会挂一段 GTrainers 聚合层（那一层本来只有机地一个来源 ⇒ 是个空段）。
`test-emulator-structure` 的「只对 modifier 挂 GT 段」当场变红。
⇒ **换变量名时，同一行里的语义条件要逐字核对**，不能只盯着被替换的那个词。

### 6.2 断言绑变量名，改实现就假红

`test-download` / `test-v1081-dl` / `test-v1083-mods` / `test-emulator-structure` 共 7 条断言，
判据是源码里出现 `items.slice(0, SVF_CAP)` / `d.ts.map(` / `dlResSection(gts, '存档')` 这类**变量名字面量**。
实现换成 `keep` / `tsKeep` / `gtsKeep` 后全部假红。
⇒ 这类断言应判「行为」而不是「变量名」：改成 `(?:items|keep)\.slice\(0, SVF_CAP\)`、
`(?:tsKeep|d\.ts)\.map\(` 这样认两种写法，**但把更强的约束（「展开基数必须是筛后集合」）
放进新套件 `test-v10110` 单独守**，避免放宽后没人管。

### 6.3 `run-all` 里 12 秒等待不够，0 行数据让整套崩成 exit=2

`test-v10110` 单跑 42/42，进 `run-all` 后 C1「Mod 页签 0 行」→ 后面 `chChips[0].textContent` 崩 → `exit=2`。
两个问题叠在一起：
- 84 套轮流压 8123 时 `/api/mods/match` 回得慢，12 秒不够 ⇒ 等到 **30 秒**（150 × 200ms）
- 数据没回来时**不许崩在 `pick.click()` 上** ⇒ 加空值保护，降级成「跳过」而不是异常退出

**为什么这条值得记**：整套崩掉会把「3 条假红」放大成「整个防线不可信」，
而排查时会先怀疑防线本身，反而找不到真正的问题（数据慢）。

### 6.4 借用别人的类名，撞坏了一个「语义判据」（浏览器层实拍才发现）

筛选条第一版写的是 `<div class="dl-bar dl-flt">` —— 只想蹭 `.dl-bar` 的行 / chip 样式。
`run-all --browser` 时 `test-v1025-dlstrip` ⑧c 变红（40/41）：

> 那条的红线是「**`.dl-bar` 已不在**」—— 它用这个类名的消失来证明
> 「用户真的从本体页签切走了、不是同一个画布换了高亮」。

Mod / 修改器 / 存档三个页签一旦也带 `.dl-bar`，这个判据当场把 Mod 页签认成「还停在本体」。
**这不是测试太脆，是类名有语义**：`.dl-bar` 在项目里一直是「本体工具条」的标识。

改法：新增独立类 `.dl-flt-bar`（不再继承 `.dl-bar` 的 position / backdrop-filter 覆写），
只保留 `.dl-lb` / `.dl-chip` 这两个本来全局可见的纯视觉零件；并加 `test-v10110` A4 钉子：

```js
ok('A4 ★ 筛选条用独立类 `.dl-flt-bar`，不占用 `.dl-bar`',
   /'<div class="dl-flt-bar">'/.test(src) && !/dl-bar dl-flt/.test(src));
```

> 静态层查不出这条 —— 它不违反任何结构约定，只有**跑起来点一遍**才会撞上。

## 3. 为什么这么做

**① 服务端不代理 aria2。** 线上跑在容器里，服务端的 `127.0.0.1` 是容器自己，不是用户的机器 ——
代理一定「永远未接入」；更糟的是等于给公网开一个打本机端口的跳板。
所以数据面（探活 / 加任务 / 进度）全部由**浏览器直连**本机，服务端只承担存配置与给元信息。

**② 未交付时给空态，不给假数据。** 0 条任务和「工具没装」是两件事。混在一起，
用户永远查不清「是我没装还是它没任务」。所以角标用「—」、任务区明说「这里不显示假数据」、
「加入下载」按钮禁用。

**③ 安装包留 `null`，不留 404 路径。** 死链比「暂无」更糟 —— 用户会反复点并怀疑自己网络。
工具端交付后只改 `meta.tool.setup` 一处（前端是条件渲染），不碰 UI 代码。

**④ 与前两版的关系。** v10.101 的协议唤起**保留**（降为第②级：装了但没常驻的用户只有这条路）；
v10.102 的三级链**不动**，本次只是在下载弹窗里把它「看得见」。

## 5. 遗留

1. **工具端未交付**：`meta.setup` 仍是 `null`，首页与管理页都显示「未接入」。这是**如实状态**。
2. **PNA 未在有头浏览器实测**：headless 下 HTTPS 页面打 `127.0.0.1` 返回 200 / 6ms，
   但事件流有 `ERR_BLOCKED_BY_PRIVATE_NETWORK_ACCESS_CHECKS`。必须在有头 Chrome + Edge 各验一次。
3. **未部署**：线上仍是 v10.99 产品代码。等工具端 zip 到位后一起发（改 `KM_SETUP` / `meta.setup` 两处）。
4. **管理页的下载配置在线上不生效**：配置写的是服务端 `data/`，而下载发生在用户本机 ——
   这是设计使然（配置是「本机偏好」的备忘 + 下发源），换机器要重设，设置面板里已写明。

# v10.54 —— 搜索改「模糊匹配 + 相关度优先」，结果分模块拉开间隔

> **一句话结论**：搜索此前是**四个库各写一份「包含」判定**、前端还有**第五份打分** ——
> 同一个查询，四个库能给出互相矛盾的答案：带空格的查询（「巫师3 狂猎」「艾尔登 法环」）
> **端游库 0 命中，而手游 / 修改器 / 云存档三库都有命中**（探针实测：**6 条带空格查询里 3 条端游 0 命中**）。
> 根因两层：① `gamesDb` 是四个库里**唯一没做归一化**的（只 `toLowerCase().includes()`），
> 中文标题里是 `：`/`—`、用户键盘敲的是空格 ⇒ 一枪不放；② 另外三库虽归一化了，
> 却**都没有相关度排序**，只按各自业务序返回。
> 本轮把匹配与打分收敛到**唯一真源** `data/search-rank.js`（分级 `EXACT/PREFIX/CONTAINS/TOKEN_ALL/TOKEN_SOME`），
> 四个库共用；前端删掉自算打分、改消费服务端下发的 `fit`；搜索结果四个分组之间加了**看得见的间隔**。
> 实测：带空格查询端游 0 命中 **3 / 6 → 0 / 6**，「赛博朋克 2077」**0 → 2**、「黑神话 悟空」**0 → 1**。

**「模糊搜索 + 准确较高权重更高」**、**「分模块明显一点有间隔」**。

### 1.1 分级相关度（`score` 越小越相关）

| 档 | 值 | 命中条件 | 走的层 |
|---|---|---|---|
| `EXACT` | **0** | 归一化键完全相等 | 全等 |
| `PREFIX` | **1** | 归一化键以查询开头 | 前缀 |
| `CONTAINS` | **2** | 归一化键包含查询 | 子串（靠 `normKey` 抹平「查询空格 vs 标题 `：`/`—`」） |
| `TOKEN_ALL` | **3** | 查询的**每一个** token 都在名字里 | 救**乱序**（「狂猎 巫师」） |
| `TOKEN_SOME` | **3 + (1 − cover)** | 覆盖比 `cover ≥ MIN_COVER` | 部分覆盖，按覆盖比插值 |
| `NONE` | `Infinity` | 都不满足 | —— |

前端只认三档 `fit`：`EXACT → 3`、`PREFIX → 2`、其余「命中但非前缀 → 1」、`null / NONE → 0`。
（`fitOf()` **必须先判空** —— `null < NONE` 在 JS 里为真，不判空会把「没有结果」误算成 `fit = 1`。）

### 1.2 查询分词 `tokensOf`：按**字符类别**切，不按空格切

- 逐字符判类别（CJK / 拉丁 / 数字），**类别一变就断**；
- 长度 **≥ 4** 的 CJK 段再按**不重叠 2-gram** 切开（< 4 的 CJK 段整段保留）。

实测（探针 `tools/_probe-v1054-doc.js`）：

| 输入 | `normKey` 后 | `tokensOf` 结果 |
|---|---|---|
| `巫师3狂猎` | `巫师3狂猎` | `["巫师","3","狂猎"]` |
| `狂猎巫师` | `狂猎巫师` | `["狂猎","巫师"]` |
| `赛博朋克2077` | `赛博朋克2077` | `["赛博","朋克","2077"]` |
| `艾尔登法环` | `艾尔登法环` | `["艾尔","登法","环"]` |
| `the witcher 3` | `thewitcher3` | `["thewitcher","3"]` |

⇒ 所以**「按空格切 token」是错的**：中文用户不敲空格，`巫师3狂猎` 会被当成 1 个 token、乱序层等于不存在。
反过来说，**拉丁段里的空格会被 `normKey` 抹掉**（`the witcher` → `thewitcher`），
所以「英文带空格」走的是 `CONTAINS` 层、不是 token 层 —— 这也是实测确认的。

### 1.3 `MIN_COVER = 0.7` 是**实测定标**出来的，不是拍的

`0.6` 时下面两条噪音会越过门槛；`0.7` 正好切在它们之上、而**该留的**那条在下面：

| 样本 | tokens | hit | cover | `0.6` | `0.7` |
|---|---|---|---|---|---|
| 「赛博朋克 2077」 vs **赛博朋克商店模拟器** | 3 | 2 | **0.667** | 过 ❌ | **挡** ✅ |
| 「黑神话 悟空」 vs **黑神话时空** | 3 | 2 | **0.667** | 过 ❌ | **挡** ✅ |
| 「生化危机4」 vs 生化危机4重置版 | 3 | 3 | **1.000** | 过 | 过 |
| 「生化危机4 重制」 vs 生化危机9：重制版 | 4 | 3 | **0.750** | 过 | 过（**该留的**） |

### 1.4 代际护栏接进**读侧**（只拒「查询有数字」这一向）

`rankOne` 里用 `genNums(name)` 做**单方向**拒绝：**查询里有数字 ⇒ 名字必须也含那个数字**，否则 `NONE`。
取数必须用**原始 `name`**、不能用归一化键（v10.36 踩过的坑）。

实测（`tools/_probe-v1054-doc.js` + 现测对照）：

| 查询 | `qNums` | 有护栏 | 无护栏 | 护栏挡掉 |
|---|---|---|---|---|
| `生化危机4 重制` | `["4"]` | **4** | 8 | **4** —— 恰是 `生化危机3：重制版` / `2：重制版` / `1：高清重制版` / `0：高清重制版` |
| `生化危机 重制` | `[]` | 5 | 5 | **0** —— 查询无数字 ⇒ 护栏不生效（证明它是**单方向**的） |
| `巫师3 狂猎` | `["3"]` | 3 | 3 | **0** —— 无过拒 |

★ 「`生化危机4 重制` 这一类 **cover = 0.750 ≥ 0.7**」是本轮反复用到的**关键样本** ——
它**能过门槛**，所以**只有代际护栏挡得住它**（见 §3 反证与 §5.3）。

### 2.3 ★★ 一处「数字口径」自查（**本轮自己纠正的**）

本轮中途记过一句「`生化危机4` 召回 **20 → 4**」。**现测不成立**：

```
生化危机4   无护栏=4   有护栏=4   ⇒ 护栏挡掉 0
生化危机    无护栏=20  有护栏=20  ⇒ 护栏挡掉 0
```

正确说法是：**「20 → 4」是「门槛还是 0.6、代际护栏尚未接」那个中间态的数字**。
- 那时 `生化危机4` 的 tokens = `["生化","危机","4"]`，与 `生化危机` 系列名 cover = 2/3 = **0.667 ≥ 0.6** ⇒ 放行 ⇒ 20 条；
- 接上护栏后 ⇒ 4 条；
- **再把门槛从 0.6 提到 0.7 之后，0.667 这一类先被门槛拦掉了**，护栏在这个查询上的**边际贡献变成 0**。

⇒ 所以**护栏的价值不能用这个样本证明**。它的价值改用 `生化危机4 重制`（cover **0.750**）证明（见 §1.4）。
这条正是铁律 58「断言名不许 over-claim」的**同一个毛病**：**名字比实际守护说得大**。
（本节保留两个数字，是为了记下「哪个数字属于哪个阶段」—— 见 v10.53 补的铁律 50。）

## 五、★★ 本轮真正的架构性收获

### 5.1 「同一个语义只允许有一份实现」—— 五份实现 = 四个互相矛盾的答案

匹配逻辑原先散在 **五个地方**（`gamesDb` / `mobilehub` / `trainers` / `saves` 各一份 + 前端 `paintSearchResult` 的 `fit()`）。
后果不是「有一处写得差」，而是**同一个查询四个库给出互相矛盾的答案**（§2.1 那张表：
端游 0 条、手游 1 条、修改器 2 条、存档 1 条）—— 用户看到的是「这个网站搜不到同名游戏」。
⇒ 判据：**同一件事在 N 个地方各写一遍时，先合并，再谈优化**。

### 5.2 归一化「做了一半」比「完全没做」更隐蔽

三库都做了 `normKey` 归一化，`gamesDb` **什么都没做** ——
症状表现出来却是「**端游库搜不到**」，很容易被误判成「端游库数据有问题 / 数据源没收录」。
而且**另外三库也不是全对**：它们归一化了、但**没有相关度排序**（按 `configs` / `lib` / `paths` 的业务序返回），
所以「准确度高的排前面」这条承诺**谁都没实现**。
⇒ 通法：**凡是有 N 个同类库的地方，先列一张「每个库都做了哪些层」的矩阵**，缺项一眼可见。

### 5.3 门槛与护栏是**两道闸**，断言名必须等于守护对象

本轮有**两道**降噪机制：`MIN_COVER` 门槛（覆盖比）与 `genNums` 代际护栏（数字一致性）。
它们**都能挡** `生化危机9：安魂曲` 那一类 ⇒ 拿它反证，**红的是谁说不清**。
只有 `coverage = 0.750 ≥ 0.7` 的样本（`生化危机4 重制` vs `生化危机9：重制版`）**过得了门槛**，
所以**只有护栏挡得住它** —— 这才是护栏的归因样本。
⇒ 这与铁律 58 是同一个毛病的两个面：**58 说「名字别比覆盖大」，这条说「归因别归错闸」**。

### 5.4 「门槛」与「长度阈值」必须按 CJK 定标，不能一把尺子量到底

- `tokensOf` 里 CJK 段的 2-gram 阈值取 **≥ 4**：3 字的 `安魂曲` 切了会碎成 `安魂`/`曲`，
  反而把 `TOKEN_ALL` 搞松；
- `MIN_COVER = 0.7` 是**实测切出来的**（0.667 噪音在下面、0.750 真召回在上面），不是拍的。
⇒ 与本项目跨源记忆里那条一致：**最小长度护栏必须按 CJK 区分**，
`length >= 3` 一刀切会整类误杀 2 字中文名（`剑星` / `鸣潮` / `仁王`）。

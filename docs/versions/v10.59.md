# v10.59 —— 下载弹窗本体行标题：XD 条目退回「游戏名-盘口」

> 用户原话：**「如果是没有 XD 官方盘口标题则（游戏名称-盘）」**。

承接 v10.58 的 ⑨（XD 条目不再显示「（无标题资源帖）」）：那次把它改成了
统一文案「XDGAME 官方盘口」，但**一款游戏 9~10 行还是全叫同一句**，只是把一句错话
换成了一句没用的话 —— 用户看不出哪行是百度、哪行是夸克。本版把行标题改成
**「游戏名-盘口全名」**，逐行可分辨。

---

## 一、改了什么（真实对照数据）

| 项 | 改前 | 改后 |
|---|---|---|
| XD 本体行标题 | 10 行**全是** `XDGAME 官方盘口` | 10 行**互不相同**：`天国：拯救2-百度网盘` · `-天翼云盘` · `-迅雷网盘` · `-夸克网盘` · `-阿里云盘` · `-移动云盘` · `-123网盘` · `-UC 网盘` · `-磁力下载` · `-正版购买` |
| 标题去重后条数 | **1**（10 行同一个字符串） | **10 = 行数**（重复 0） |
| 「（无标题资源帖）」行数 | **0**（v10.58 已修） | **0**（守住，未回退） |
| 机地本体帖（天国：拯救2 共 26 帖） | 各有各的标题 | **一字节不变**（顶部文案仍是「来自 **26** 个机地资源帖 + **10** 个 XDGAME 官方盘口」） |

改动范围：**1 个主源 + 3 张派生页**（`public/index.html` → `emulator` / `resources` / `unpack`，铁律 1）。
**数据侧一个字节没动** —— 这是纯显示层规则。

## 二、根因（为什么 v10.58 那句还是不够用）

XD 条目按数据结构**永远**取不到标题：

```
fetchers/download.js:129
  out.push({ server, serverUrl: abs, name: server, real: null, pwd: null, kind: 'downbtn' });
                                          ↑ name 就是 server，没有 postTitle
```

XD 的每一条是**源站详情页上的下载按钮**，不是帖子 —— 它压根没有「标题」这个概念。
所以 v10.58 的兜底文案「XDGAME 官方盘口」对**每一条都成立**，10 行长得一模一样。

★ 这一点决定了实现方式：不是「有标题就用、没有才兜底」的两分支，而是
**XD 支路必然走兜底**，兜底本身必须带上「这一行是哪个盘口」的信息才有区分度。

## 三、改法（三处，都是最小改动）

### 3.1 新增 `dlGameName()` —— 「当前在看哪款游戏」的唯一读法

```js
function dlGameName() {
  const a = String((dlUni && dlUni.ctx && dlUni.ctx.title) || '').trim();
  const t = a || String(dlSecTitle || '').trim();
  if (!t) return '';
  return splitName(t).zh || t;
}
```

两条入口指向同一件事，取**先有值的那个**：

| 入口 | 何时有值 |
|---|---|
| `dlUni.ctx.title` | 合并弹窗（对话框）那条路径 |
| `dlSecTitle` | 详情页「下载资源」三专区块（`loadDlBlock(d, fb, title)` 里赋值），它**不走 `dlUni`** |

⚠️ **两处都要覆盖**：`dlRow` 是三个渲染出口（弹窗 / 详情页预览 / `dlsec` 全部）**共用**的一行函数
（代码注释历来强调「两处各写一套必然漂移」），只认其中一个会让另一处退回旧文案。
⚠️ 名字取 `splitName` 的**中文段**：库里标题是 `天国：拯救2/Kingdom Come: Deliverance II` 这种
「中文/英文」形态，整串拼进标题会变成一长条认不出的东西。

### 3.2 `dlRow` 里的行标题（`gTxt`）

```js
const disk = g.links.map((l) => l.server).find(Boolean) || '';
const gn = g.src === 'xd' ? dlGameName() : '';
const gTxt = g.title || (g.src === 'xd'
  ? ((gn && disk) ? gn + '-' + disk : (disk || gn || 'XDGAME 官方盘口'))
  : '（无标题资源帖）');
```

**逐级降级，保证「不会比改之前更差」**：

| 有游戏名 | 有盘口 | 标题 |
|---|---|---|
| ✓ | ✓ | `游戏名-盘口`（用户口径） |
| ✗ | ✓ | `盘口`（仍比「XDGAME 官方盘口」有信息量） |
| ✓ | ✗ | `游戏名` |
| ✗ | ✗ | `XDGAME 官方盘口`（**保留旧文案**，不许变空白） |

★ **盘口名取 `links[].server` 原值**，不用 `DL_BRAND_NAME`：那张表是筛选 chip 用的
**短名**（「百度」），拼进标题会拼出「潜水员戴夫-百度」，与用户口径不符。
`server` 本身就是全名 —— 实测 xdgame 详情页 10 条：
`百度网盘 / 天翼云盘 / 迅雷网盘 / 阿里云盘 / 夸克网盘 / 移动云盘 / 123网盘 / UC网盘 / 磁力下载 / 正版购买`。

### 3.3 只动 XD 那侧

机地帖的「（无标题资源帖）」是**另一个意思**（那帖真的没名字），不能合并。
反证 E 专门守这条（详见第五节）。

## 四、顺手删掉两处**不可达**的代码（都是我自己先写出来的）

| 写出来的东西 | 为什么删 |
|---|---|
| `DL_DISK_FULL` 盘口全名表（11 个键） | `dlBrand()` 的**唯一输入**就是 `server` 串 ⇒ `server` 为空时品牌也推不出来，这张表 100% 是死代码 |
| `disks.slice(0, 2).join('/')`（同组多盘口取前 2 个） | XD 的归帖键是 `it.postId \|\| it.postUrl \|\| ('u:' + it.real)`，XD 条目既无 `postId` 也无 `postUrl` ⇒ 键就是**它自己的地址** ⇒ 不同盘口**必然是不同组**，一组恒为 1 条链接。这条分支**构造不出来**（想造多链接只能让两个盘口的地址相同，那不是真实形态） |

两条都是先写了「防御性代码」、再用实测数据证明它不可达 ⇒ 删掉，并把**为什么不可达**写进注释，
免得下一轮又有人「补一个更周全的分支」。

★ 这一条同时也是**给断言纠错**：第一版为「取前 2 个」写了一条断言，实测红在
「构造不出多链接的组」——**是断言的前提错了，不是代码错了**，改成钉机制（三个不同地址 ⇒ 三个组）。

## 六、踩到的坑（4 条）

### 6.1 ★★ 实拍探针的 `BASE` 写死 8123 = **常驻旧进程**

探针原本 `const BASE = 'http://127.0.0.1:8123'`。而 8123 是长期驻留的服务（靠计划任务保活），
**改完代码不会热加载** ⇒ 拿它做实拍，测的是**上一版代码**：
要么假红（新文案在旧进程里当然不存在），要么更糟 —— 假绿（旧进程恰好也满足断言）。
★ 项目里已记过这条（「套件 BASE 默认写死 8123，本版直接跑出过假红 11 条」），
本版把它改成**可用环境变量覆盖**：`PROBE_BASE`。默认值保持 8123 不破坏既有习惯，
但**换了代码就必须指向新实例**。

顺带记一个连带现象：后台起的 `node server.js &` 会**随该 shell 退出被回收**，
所以「起服务」与「跑探针」必须放在**同一条命令**里，否则探针报 `ERR_CONNECTION_REFUSED`。

### 6.2 ★★ 改了被 `new Function` 求值的函数 ⇒ **求值环境要同步**

`dlRow` 现在会调 `dlGameName()`，而它要读 `dlUni.ctx.title` / `dlSecTitle` 并调 `splitName` ——
这三样在 `tools/test-v1027-dlpop.js` 的 `new Function(...)` 沙盒里**都不存在**。

失败形态很坑：**求值那一步是成功的**（`ok(true, '能从主源取出并求值…')` 照常绿），
**一调 `dlRow` 才崩** `ReferenceError: dlUni is not defined`，报错栈指向 `dlRow` 内部，
完全指不到「求值环境缺绑定」这个真因。

修法：注入两个状态变量（`let dlUni = null; let dlSecTitle = '';`）+ `pickDef('splitName')`，
并给断言导出 `setGame()` / `setGameVia()` 两个入口（分别模拟详情页与弹窗两条路径）。

### 6.3 守卫里**不许写死「当前版本号」**

`tools/_verify-payload.js` 里 v10.58 收尾时加的那句「载荷代码文件 **v10.59 残留 0 处**」——
那是为**那一次漂移**专门加的。本版推进到 v10.59 后，同一句立刻变成**假红**（v10.59 成了合法版本号）。
⇒ 改成动态判据：从 `docs/versions/` 取最高版本，代码文件里不许出现**比它更高**的版本号。

★ 教训与 6.1 同族：**判据里写死一个会随时间变化的量**，维护成本会转成「明明对却报红」，
而假红和假绿一样贵 —— 误报会训练人忽略防线。

### 6.4 用户可见文案改一行，**旧断言与旧反证会一起失效**

- 旧断言：`ok(/XDGAME 官方盘口/.test(xdRow), 'XD 条目显示「XDGAME 官方盘口」')` —— 直接假红，按新口径重写；
- 旧反证：`patch()` 要求目标**恰好命中一次**，而 `gTxt` 由一行式三元变成多行降级链后，
  两个 patch 串一个**命中 0 次**（直接抛）、一个**命中 2 次**（新增的 `const gn = g.src === 'xd'` 撞车）。
  ★ 这个「命中次数必须恰好 1」的保护**是对的** —— 它把「静默跳过一条反证」变成了显式报错。

⇒ 规矩：**改用户可见文案时，顺手全仓找「写死了旧文案的断言与 patch 串」**，别等 CI 红了再找。

## 七、未做的事（如实说明）

1. **没有把 XD 行标题做成可配置**（例如用户想改成「盘-游戏名」）—— 本版按用户口径写死一种；
2. **没有给 XD 行加盘口图标**（`.acts` 里的 chip 已有盘口短名与配色，重复展示无收益）；
3. 详情页预览 / `dlsec` 弹窗**共用 `dlRow`**，因此**自动继承**本版改动 —— 这符合项目既有约定
   （两处各写一套必然漂移），但**没有为这两处单独做实拍**（只有弹窗那条路径有实拍）；
4. 遗留未变：「（无标题资源帖）」在**机地支路**仍会出现 —— 那是**帖真的没名字**，不是本版范围。

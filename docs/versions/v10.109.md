## 2. ① 冷门口径：加第二道判据

### 2.1 改前是什么

`hot=0 且非近 90 天新游`（v10.84，2026-10-19 拍板）⇒ 现测隐藏 **8,568 / 19,764**。

问题是它把「没热度但社区一直在做 MOD/修改器/存档」的游戏也一起藏了 —— 那类游戏**是有人要的**。

### 2.2 改成什么

```
判冷 = hot ≤ 0
       ∧ 非近 90 天新游（热启动期保护，不动）
       ∧ 没有任何可用资源（MOD / 修改器 / 存档）
```

现测（2026-10-23 现算，不抄结论）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 冷门隐藏 | 8,568 | **7,459** |
| 可见 | 11,196 | **12,305** |
| 被资源救回 | — | **1,109** |

### 2.3 为什么是「注入」而不是直接 require

`res-groups → gamesDb → cold-hide` 已经是一条**真实依赖链**。
`cold-hide` 反向 `require('./res-groups')` 就是循环依赖 —— Node 会把半初始化的 exports 交出去，
症状是「平时好、启动早期炸」，最难查的那一类。

⇒ `server.js` 启动时 `coldHide.setResourceProvider(() => Set<libId>)`。
未注入时 `hasResource()` 恒 `false` ⇒ **行为退回 v10.84 口径**，不会因为缺依赖把全库都藏了。

`Set` 而不是数组：判冷要对全库逐条问一次，`Set.has` O(1)；数组 `includes` 在列表过滤里会变成 O(n²)。

TTL 30 分钟：`daily-sync` 每天重建一次资源表，长驻进程不重启，不能只在注入时算一次。
重建代价实测 **1.6s**（`resGroups.build()` 要解析并关联三份源），所以 TTL 不能太短。

### 2.4 为什么 stats 多了一个 `rescuedByRes`

隐藏数从 8,568 掉到 7,459 —— **数字变小必须有原因可查**，否则下轮会以为规则失效。
`rescuedByRes` 就是这个原因。同时 `rule` 文案同步改成
`hot=0 且非近90天新游 且 无可用资源(MOD/修改器/存档)`，仪表盘那行口径说明也跟着改。

## 3. ④ 新游检测

### 3.1 它是「决策台」，不是第二个列表

用户口径是「**我来决定是入库**」⇒ 与 `daily-sync` 的增量索引**目的相反**：

| | 增量索引（`/api/library/index/incr`） | 新游检测（本模块） |
|---|---|---|
| 目标 | 让库变全 | 让库变 **经用户确认后才全** |
| 扫描时写库 | 是（抓到就 upsert） | **否**（只比对 + 记账） |
| 写入时机 | 抓取时 | 用户点「入库」时 |

⇒ 扫描阶段**绝不写 `games.json`**（`test-v10109` 的 B3 静态钉住了这一条）。

### 3.2 判定与状态机

- 判定：源站最近 N 页 → 与 `gamesDb.byIdGet(id)` 比对 → 差集进候选池
- 三态：`pending`（等你决定）/ `admitted`（已入库）/ `ignored`（记账，之后扫描不再列出）
- 扫描对**已知候选只刷新源站字段，不动 status** —— 否则已忽略的会被下一轮"复活"

### 3.3 入库做了什么

① `gamesDb.upsert()` → ② `coldHide.setOverride(id,'show')` → ③ 尝试 `xdgamer.detail()` 补字段

顺序不能换：先落下"已入库"这个事实，补资料是可选增强（失败静默）。

**③ 补的是"准数"不是"简介"**：实测全库 19,765 条字段集里**没有 `desc` / `shots`**
（详情走 `/api/detail` 实时解析，库不是它们的落点）。真正有价值的是 **`score`** ——
XD 列表页没解析到评分时填默认 5，详情页给的是真值（实测 `16898`：列表 5 → 详情 **8.2**）。

### 3.4 两个实测踩到的坑

| 坑 | 表现 | 根因 |
|---|---|---|
| `detail` 传了 url | `detailFilled` 恒 0 | `xdgamer.detail(id, host)` 收**数字 id + 可选域名**，不是完整 url；传 url 会被拼成 `…/game/https://…html.html` ⇒ 404。且域名要按 url 判：列表页给 `xdgame.com`，detail 默认 `xdgamer.com` |
| 入库后立刻查不到 | 返回 200 但库里没有 | `upsert` 内部 `persistSoon()` 有 **800ms 防抖**。⇒ `admit` 返回前显式 `persist()` |

### 6.2 ★★★ kalvo 一次改版把「联网补全」整条打死（两跳都静默返回空）

`test-v1018` 三条红：Honor MTN-NX3 / moto g(20) 都补不到芯片。根因**两处独立改版**：

| 跳 | 旧 | 新（2026-10-23 实测） | 后果 |
|---|---|---|---|
| 搜索 | `{result:true, response:[…]}` | `{items:[…], total, searchUrl}` | `searchMarket()` 恒返回 `[]` |
| 设备页 | `div.cont > table > tr > td` | `section.datasheet-group > dl > div.datasheet-row > dt+dd` | `parseSpecs()` 恒返回 0 组 |

两跳都**不报错**，上层只看到 `reason:'not-found' / 'parse-empty'` ⇒ 界面上一直是「未收录」灰徽标。

修法三条：
1. **双结构并存**（不是替换）：搜索两种返回体都认，规格页两套选择器都解析；
2. **传输层失败不落缓存**：新增 `_stat.netError` 计数，本次请求里出现过非 JSON / 空响应就返回
   `reason:'net-error'` 且跳过 `cachePut` —— 分清「上游说没有」与「我们没取到」；
3. 清掉已经被毒掉的缓存条目（`data/device-specs.json` 10 条失败、`data/device-fill.json` 4 条空结果）。

修后实测：`Honor MTN-NX3 → Qualcomm Snapdragon 6 Gen 4`、`motorola moto g(20) → Unisoc T700`，

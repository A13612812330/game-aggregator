# v10.95 机地本体链接「只显示 XD」—— 失败被缓存成了结论

> 用户口径：「且机地有很多免费的下载本体的链接，为什么不显示（现在只显示 XD 的，
> 但是机地有很多网盘的下载源）」

## 一、结论（先给答案）

**不是没抓到，也不是机地没资源 —— 是一次偶发失败被当成「机地确实没有」缓存了 30 分钟。**

实测证据（2026-10-21，同一台机器、同一分钟内，tid `640827939`《星砂岛》）：

| 走哪条路 | 结果 |
|---|---|
| `/api/download?url=…/topic/detail/640827939`（命中缓存） | `engine=api` · 本体 `count=0` · **error: `/api/misc/post_list HTTP 405`** |
| 直连抓取器 `jidiPosts.topicPosts()`（现抓） | 本体 **3 帖 / 2 帖带链 / 5 条网盘链接**（百度、迅雷、夸克） |

同一话题连打三次：**5 条 → 0 条（405）→ 5 条**。可见 405 是**偶发**的，
而我们把「0 条」当成了正常结果写进缓存 —— 于是接下来半小时，
每个打开这款游戏的人都只看到 XD 的盘口。

## 二、三个根因

| # | 根因 | 为什么以前没被发现 |
|---|---|---|
| 1 | `/api/download` 对**整份载荷**统一缓存 30 分钟，不区分「成功但确实没有」和「这次没取到」 | 缓存键是 `dl:jidi::<tid>`，失败和成功长得一样 |
| 2 | 取 env 那一步（`getEnv('/topic/list')`）偶发拿到挑战页 ⇒ `signedPost` 直接抛错，**没有重试** | 错误被 `allSettled` 收进 `sections[].error`，接口照样 `ok:true`，前端看到的是「0 条」 |
| 3 | 三个专区**并行**发起；机地对并发突发更敏感（实测并行时偶有一个被挑战），而失败的专区不会补抓 | `topicPosts` 用 `allSettled` 保证「不整轮白跑」，但也没人去救失败的那一个 |

## 三、改法（四处，各管一段）

### ① 缓存时长按结果决定 —— `data/dl-cache-ttl.js`（新增）

| 情形 | 缓存多久 | 理由 |
|---|---|---|
| 机地完整成功（三专区无 error） | **30 分钟** | 原行为，资源列表几小时不变 |
| 机地有专区带 `error` | **60 秒** | 失败不许锁定半小时，下一个人打开就自愈 |
| 机地走 SSR 兜底（`engine='ssr'`） | **120 秒** | 能看，但只有首屏约 10 帖，覆盖不全 |
| XD 来源 | 30 分钟 | 不受机地规则影响 |
| 空载荷 | 60 秒 | 不把空当结论 |

★ 判据是「有没有 `error`」，**不是**「有没有链接」。
机地确实存在「帖在、但帖里没写网盘」的正常空结果 —— 那种要照常缓存，
否则每次打开都重打一遍源站，反而更快触发限流（`test-v1095` 的 A6 钉住这一条）。

★ 单独成模块是为了**能被单测**（`data/game-dedupe.js` 同一套路），
不再需要在测试里抄一份逻辑来比字符串。

### ② `refresh=1` —— 用户能自己按的重试

`/api/download?…&refresh=1` 先 `cache.delete(key)` 再重抓，与 `/api/detail` 同一个开关语义。
前端「↻ 重新抓取机地链接」按钮就调它。

★ **不自动重试**：机地按请求数限流，自动连打会把偶发失败放大成真限流。

### ③ 机地抓取的两层重试

```
signedPost()   失败 → envCache.delete(path) → 强制重新取 env → 再打一次（退避 250ms）
topicPosts()   并行批次跑完后 → 对失败的专区**串行**补抓一次（间隔 400ms）
```

为什么两层都要：
* 只加 ①（signedPost 层）不够 —— 两次尝试可能都落在同一个挑战窗口里（实测发生）；
* 只加 ②（串行补抓）也不行 —— 重试时会复用那份带病的 env，等于重放同一个错。
* 都只做**一次**：机地按请求数限流，多轮重试会把偶发失败放大成真限流。

### ④ 前端：说「没取到」，不说「没有」

| 场景 | 改前 | 改后 |
|---|---|---|
| XD 正常、机地 405 | 页面看着一切正常，只有 XD 盘口 —— **用户只能得出「机地没资源」** | 顶部加一块「机地这次**没取到**本体链接：`/api/misc/post_list HTTP 405`。这不是「机地没有」」+ 重试按钮 |
| 两侧都空 | 笼统一句「可能是改版或临时故障」 | 带上真实错误原文（等宽、可选中，方便直接贴给排查） |

顺手修了一个**会咬人的顺序问题**：重试按钮的委托判断必须排在 `[data-dl-open]` 之前 ——
它长在弹窗内部，冒泡上去会被当成「再开一次弹窗」，白闪一下却不重抓。

## 四、边界（这些情况机地确实没有，不属于本 bug）

* 库里 19,732 条 = XD 16,036 + 机地 3,696；XD 里 **13,448 条**有 `jidiUrl`（孪生），
  **2,588 条没有**（16%）—— 这些从来没有机地入口，不是今天才没有。
* 抽样 12 款有孪生的游戏：**11 款**能取到机地本体链接，1 款（《节奏狂怒》）源站该话题
  本体 0 帖 —— 那是真的没有。

## 五、踩坑

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| 1 | 修完 `cached()` 的函数态 TTL 后，一次弹窗仍打了 3 次机地 | `ttl` 是函数时 `typeof t === 'number'` 为假 ⇒ 跳到下面**再建一个 builder**，并发去重整段失效 | 函数态一律视为「还在跑」，直接 `return hit.value` |
| 2 | 探针 C2 首次红（重试后机地仍 0 条） | 连打时第二次仍落在挑战窗口里 | 探针允许连点 3 次；断言「这条路走得通」而不是「源站保证每次都通」 |
| 3 | 只加 signedPost 重试不管用 | 两份带病 env 会让两次尝试同时失败 | 补 `topicPosts` 的串行补抓（不再并发） |

## 六、验证（现测）

| 项 | 结果 |
|---|---|
| `test-v1095-jidi-body-links`（新，32 条） | **32 / 32** |
| `test-v1093-downloads` | **97 / 97** |
| `test-v1094-ux-fixes` | **64 / 64** |
| `test-pages-sync`（四张派生页重建后） | **58 / 58** |
| `test-doc-structure` | **322 / 322** |
| `_probe-v1095`（真实浏览器） | **12 / 12** |

实拍（《星砂岛》`xd-13376`，双源都有资源）：

```
共 14 个可直接打开的网盘地址（来自 2 个机地资源帖 + 9 个 XDGAME 官方盘口）
本体 3 帖 / 5 个地址 —— 百度 / 迅雷 / 夸克
默认页签 = 本体（机地），而不是 XD 盘口
```

失败态注入实拍：出现「没取到」+「不是『机地没有』」+ 重试按钮；
点重试 → 请求带 `refresh=1` → 机地 5 条回来（1 次成功）。

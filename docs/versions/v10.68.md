### 2.2 逐项

**① hero 压到 ~300px。** 关键是找到「谁在占高」：冠军卡 174px + 榜单块 **244px**。
- 冠军卡：`padding 16/20 → 12/16`、缩略图 `228×128 → 172×97` ⇒ **174 → 131px**
- 榜单块：`grid-template-columns: repeat(5,…)`（原 3 列）+ 小卡缩略图 `→46px` + 标题**单行**
  ⇒ 整块 **244 → 47px**
- `.stage .in` 内边距 `28/32 → 16/18`、`h1` `clamp(20,2.4vw,27) → clamp(17,1.7vw,20)`
- 榜单截断 `list.slice(1)` → **`list.slice(1, 6)`**（原本渲染全部前 9 名）；骨架同步
  `height:121px` + `repeat(5)` + `height:47px`（**骨架必须跟真卡同步**，v10.30 立过的规矩）

> ★ **排布方式与拍板描述不同，如实标出**：拍板选项写的是「榜首大卡 + 右侧 **2×2** 小卡」，
> 实施时选了 **5 列 × 1 行**。理由是小卡改单行后每张 47px：一行 5 张**整块 47px**；
> 按同一份实测推算，2×2 排布为 2 行（≈104px），hero 会停在 ≈**332px**、逼近 340 的闸门。
> ⇒ **目标（≤300px）达成**，但若要求恢复 2×2 的视觉，需要再拍板。

**② 行密度 B 档 76px。** 行高由谁主导要先搞清楚：改前 `.row-card .th{width:158px}`（16:9 ⇒
89px 高）> 标题两行预留（`--cd-t2` = 2.8em ≈ 41px）⇒ **缩略图主导 112px**。
缩略图 `158 → 96px`（⇒ 54px 高）⇒ 仍由缩略图主导，但落到 **74px**。
- 中文名 + 英文名**合并一行**（`rowCard()` 里把 `.en` 并进 `.tt`）
- `.row-card h3` 从「固定预留两行」改为**单行 + ellipsis**，完整名留在 `title` 属性
  ★ 这是**有意偏离** v10.30 的「全站卡片标题统一预留两行」规范，理由写在 `index.html` 注释里；
  同时把 `.row-card .th` 定死 96px —— **卡片等高**现在由「缩略图固定宽度 ⇒ 16:9 推出恒高」保证。
- 骨架同步（`.skeleton` gap/padding/`.sk-th` 宽度），否则「骨架→真卡」会跳一截
- 断点缩略图：760 → 84px、420 → 76px（骨架一并同步）

**③ 秩序语言全采纳。** `h1` 前加 `<span class="sec-no">01</span>`、区块头加 `02` + `.sec-sub`；
新增 `.sec-no` / `.sec-sub` / `.date-sep::after`（虚线）/ `.sec-h h2{font-size:15px;font-weight:600}`
（对齐参考站实测的 15px/w500）/ `@media(min-width:1061px)` 下 `.grid2::after` 画中缝虚线。

**④ 移动端 hero 压到 ~420px。** `@media(max-width:760px)`：冠军卡改横条（`104×59`）、
`.rk-grid` 改**横滑行**（`.rk-card{flex:0 0 74%}` + `overflow-x:auto`）、`.sec-sub{display:none}`；
**420 断点**再收一档（`92×52`、`.stage-h h1{font-size:16px}`）。实测 **312px**（超标达成）。

## ③ ★ 顺手修掉一个**实测到的真缺陷**（不在拍板四项内）

**移动端 `.cat-row` 被撑到 181px。** 现场：分类行本身 `.cat-row{flex-wrap:nowrap;overflow-x:auto}`
已经禁止换行，但**它挡不住子级自己换行** —— 内层 `.statline{display:flex;flex-wrap:wrap}`
作为 flex item 默认 `flex-shrink:1`，被压窄后**在它内部换行**，把 `.cat-row` 从 34px 顶到 **181px**。
这与 v10.30 的 `.rel-it` 是**同一类坑**（父级 nowrap 挡不住子级 wrap）。

修法（两处，缺一不可）：`.cat-row .statline{flex:none;flex-wrap:nowrap;white-space:nowrap}`
+ 移动端 `.sec-sub{display:none}`。修后 `.cat-row` **181 → 32px**。

★ 这条修复**同时**在守首屏 —— 反证的坏法 B 给出完整证据链（见 ④）。

## ⑤ 本轮踩的坑（三条已升级为铁律 88–90）

**坑 1 ★★★ 断点内的断言按「字符距离」取作用域 ⇒ 假红。**
`test-emulator-structure` 里一条 v10.52 的断言写成
`@media(max-width:760px)[\s\S]{0,4000}?\.d-rail{display:none}` —— 意思是「从断点起往后数 4000 字符」。
我在 760 断点**内**补了两条规则（`.cat-row .statline` / `.sec-sub`），把 `.d-rail` **推出了窗口** ⇒ 报红。
**归因方法**：先拿 `git show HEAD:public/index.html` 对**同一条正则**跑 —— regex1 旧版也 true、
regex2 旧版 true / 新版 false ⇒ 才敢定性「是我加规则导致的假红」。
**修法**：新增 `mediaBlocks(src, query)`，从查询串起做**花括号配平**取完整块体，返回**数组**
（同名断点在同一个文件里出现**两次**，只取第一段同样会取错）⇒ 铁律 **88**。

**坑 2 ★★ 对照预览按「并排」渲染 ⇒ 把宽度不足的假问题当成设计问题。**
A/B/C 三档**并排**时每档只剩 **456px**，而真实容器宽 **836px** ⇒ 预览里出现「标签换行」
「名称被挤成『涂…』」，差一步就去改一个**根本不存在**的问题（真实宽度下两档都正常）。
**修法**：改**纵向堆叠 + 每档显式 `width:836px`** ⇒ 铁律 **89**。

**坑 3 ★★ 取样取错了元素 ⇒ 一组断言全绿但全错。**
新套件第一版用 `#libList > *` 取「第一行」—— 而第一个子元素是**日期分隔行** `.date-sep`（20px）：

| 指标 | 取错样本 | 真值 |
|---|---|---|
| 行高 | **20px** | 74px |
| 首件 top | **690px** | 718px |
| 首屏完整可见 | **4 条** | 3 条 |

三个数全错，而「行高 ≤ 86」这种上界断言**全绿**（20 < 86 当然成立）。
**修法两条一起**：① 选择器收窄到 `.row-card`；② 补一条**与设计规格无关**的
「取样合理性」断言（行高 ≥ 40px），它唯一的职责就是把「取到了分隔行」单独照出来 ⇒ 铁律 **90**。

**坑 4 ★★ 记忆文件顶破 3000 字硬闸。** 实测 **6283 字** ⇒ 多轮精简到 **3000 字**（`<=` 通过）。
迁出机制的意义就是「别再胖回去」，而它确实会慢慢胖回去 —— 需要靠 `test-report.js` 兜住。

**坑 5 ★ 子级 wrap 不受父级 nowrap 约束**（见 ③）。同一坑 v10.30 在 `.rel-it` 上踩过一次。

# v10.45 —— 下载弹窗合并成四模块（本体 / Mod / 修改器 / 存档）+ 存档卡面去路径 + 广告链清洗

## 一、需求（用户原话，三条）

> ① 「部分游戏并未匹配：比如 The Elder Scrolls V: Skyrim Special Edition，他有 Mod/存档等，
>    但是在手机专区中点击查看游戏详情页并没有下载存档/修改器/Mod 等功能」
> ② 「我认为可以将下载弹窗合并成一个，并分模块展示即可（本体/mod/修改器/存档）」
> ③ 「游戏下载本体中 有个其他：元素为 `<img src="//static2.52jidi.com/.../icon_from_xunlei_helper.5340f93c2572994d8cf5.png">`
>    实际是一个广告链接，帮我清洗掉」

另有两条夹在中间的补充（一并做掉）：

> ④ 「其次存档位置显示有点多以及杂（先优化存档页面中的卡片，不在卡片中显示位置）」
> ⑤ 详情页底部入口形态 → 用户拍板：**底部只留一个「⬇ 下载与资源」按钮**（不是保留三个按钮）
> ⑥ 存档卡片点开后的落点 → 用户拍板：**卡面留按钮，点开合并弹窗的「存档」模块**（不是原地展开）

## 二、根因（全部实测定位，不是推断）

### 1. Skyrim 详情页看不到 Mod / 存档 / 修改器 —— 入口的可见性被**另一个数据源**牵着

底部三个按钮（下载本体 / 修改器 / Mod）的**显隐与条数**都只从 `/api/download` 的 `dlSecs` 推：

```
loadDlBlock() → /api/download → dlSecsOf(j) → dlSecs
              → setDlCounts(cnt)：dlSecs 空 ⇒ 三个按钮全 hidden
```

而 XD 对部分游戏**要求登录**才给网盘地址 ⇒ 8 个盘口全 `real:0` ⇒ `dlSecs` 空 ⇒ 按钮整块消失。

| 实测（2026-10-09，服务 8123 现测） | 值 |
|---|---|
| `/api/download?url=https://www.xdgame.com/game/2765.html` | 8 个盘口全 `real:0`，`error: 源站要求登录 / 权限` |
| `/api/mods/match?t=The Elder Scrolls V: Skyrim Special Edition` | `count 60`（`counts.mod` **59** / `counts.modifier` **1**） |
| `/api/trainers/match?t=…` | 1 条（GCM 元数据） |
| `/api/saves/match?t=…` | `hit` 有，`libId: xd-2765` |

⇒ **Mod 明明有 59 条，用户连「这款游戏有 Mod」都看不到。** 这是本轮真正要修的东西 ——
不是「补一个入口」，而是**拆掉「入口可见性 ↔ 本体能不能取到」这个错误耦合**。

### 2. 存档位置又多又杂

`tools/resource-sections.js` 的 `svCard()` 把 3 条路径 + 2 条注册表**直接铺在卡面**上，
24 张卡片 = 一屏几百行等宽字体路径。

### 3.「其他」那个按钮是广告

实测那条 = `https://52leiqu.com/problemTutorial`（迅雷「雷区」问题教程页），
是机地资源帖正文结尾的固定引导句。`shared.js` 的 `extractLinks` 只滤
`INTERNAL_HOST_RE`（jidiyouxi / 52jidi / xgamer）—— **没滤姐妹站 `52leiqu.com`** ⇒
不属于任何网盘 ⇒ `kind` 退成 `'其他链接'` ⇒ 前端渲染成一个名叫「其他」的下载按钮。

## 四、落地形态

### 1. 四模块合并弹窗

页签条 `#dlModTabs` **常驻**（挂在 `.dlpop-h` 与 `.dlpop-b` 之间，不随内容滚走），
四个模块各自取数、各自给空态：

| 模块 | 取数 | 为什么 |
|---|---|---|
| 本体 | `/api/download`（XD 逐个跟随 302，3–8 秒） | 只有这条路有「本体」这一档；**最贵，留给按需取** |
| Mod / 修改器 | `/api/mods/match`（本地索引，毫秒级） | 机地社区帖，覆盖比 `/api/download` 全 |
| 修改器（附加段） | `/api/trainers/match`（GCM 元数据） | **不含下载地址**，与「能点开的社区帖」视觉上分开（`dl-gcm` 虚线段） |
| 存档 | `/api/saves/match`（Ludusavi, MIT） | 给的是「放哪」不是「下什么」，逐条带复制键 |

打开时 `for (const k of ['mod','modifier','save']) dlUniLoad(k);` 并行预热三个便宜的模块，
页签条数尽早填上；未回来显示 `·`（= 还不知道）而不是 `0`（= 结论），两者不能混。

## 六、踩过的坑

1. **反证脚本自己的还原自检恒真**（最值得记的一条）。第一版用「`bad` 串是否还出现在文件里」判残留，
   而第 ⑥ 例的 `bad` 是裸的 `需登录源站` —— 这个词**本来就是正确内容的一部分**
   （修好后的三元表达式里也有它、注释里也有它）⇒ 条件恒真，把「已正确还原」报成「仍残留变异」。
   **改法**：开跑前存**字节快照**，收尾逐字节比；并给这个判据本身加一条自检（故意改一个字节，必须判出不一致）。
   > 教训与铁律同源：判「有没有被改坏」要比**字节**，不要比关键词。

2. **空态徽标 over-claim**（自查发现的实现缺陷）。第一版把 `cnt` 写死成「需登录源站」，
   而 `items: []`（源站这次没给）与 `needAuth`（要登录）是**两件不同的事** ——
   用户去登录后照样没有，会以为是站点坏了。已按 `needAuth` 分叉，并**补了一条断言**钉住它。

3. **`fn.bind(null, x)` 过不了 puppeteer 的 `evaluate` 序列化**。`evaluate` 是把函数**源码**
   送进页面执行的，绑定参数在序列化时就丢了 ⇒ 必须走 `p.evaluate(fn, arg)` 这条路。

4. **旧断言与「新行为」冲突时，先判断哪一边才是需求**。`test-related-dl` 那条
   `#dlSlot.innerHTML === ''` 一开始看着就是「回归」，但它的**形式**正是用户抱怨的东西
   （整块下载区凭空消失）⇒ 不能为了让套件变绿把说明改回去，只能改判据。

5. **既有假红要先证明是既有**。`test-v1017` 两条（9 台 → 8 台）与本轮改动无关 ——
   `git show HEAD:data/bhparams.json` 里 `ULTIMATE_MARVEL_VS__CAPCOM_3` 的唯一机型**已经**是 6 台，
   摘要 6 台求并集同样是 8 ⇒ **在 HEAD 上就会红**。复核后按断言自己的要求（「变了要复核数据」）
   更新样本值并附上复核依据，**判据本身一条没放宽**。

6. **★★ 本轮最有价值的发现：防线自己在报假数**（`run-all.js` 的汇总口径）。
   起初实测全量是「40 套 / 2,922 条」，但在逐套核对时发现 `run-all` 把
   `test-related-dl.js` 记成 **8/8**，而该套件自己打印的是 **42** —— **整套少算 34 条**。
   根因：`run-all` 当时的规则是「取输出里**最后一个** `n / m`」，而 `test-related-dl` 的收尾写成
   `✅  42 通过 / 0 失败` —— **数字中间夹着「通过」**，`\d+\s*\/\s*\d+` 匹配不上，
   于是 regex 取到了上面 PASS 明细里的「多标签游戏…共享至少一个标签 —— **8/8**」，
   一个**明细串**把整套成绩顶掉了。

   > **为什么这条比「某条断言写错」更危险**：它**不会让任何一条断言变红**，
   > 只会让「通过 N 条」这个数字长期偏低 —— 而所有人拿它当防线规模的唯一口径。
   > v10.44 日志里那处「未能定位到具体是哪套多了 3 条」，**同源**（明细换输出 ⇒ 取到的数字跟着换）。

   **两条一起改**（缺一条这个坑下次还会以别的形式回来）：
   - `run-all.js`：优先认**收尾汇总行**（同行含「通过 / 失败 / pass / fail」且带 `n / m`），
     从**整份输出**倒着找（不设「末 N 行」窗口 —— 实测 `test-alias-guard.js` 的汇总后面还跟着
     一长串样例映射，窗口一卡就找不到）；认不出则记进 **warnings 并计入退出码**，不静默降级。
   - `test-related-dl.js`：收尾改成与同伴同款 `n / m 通过`。

   **结果**：全量由 2,922 → **2,959**（正好补回被少算的 34 条），
   并已**逐套求和交叉核验**：`40 套条数之和 = 2,959 = run-all 自报值`（连续两次运行一致）。

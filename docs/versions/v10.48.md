## 一、改了什么

### ① 「查看全部 N 条」：原地铺开 → 弹窗 + 弹窗内搜索（三个分区统一）

旧实现 `grpExpand()` 是**原地铺开**（上限 300 条，`gl.innerHTML` 整块换掉）。
用户口径「不要展开」⇒ 改为打开 `#dlPop` 弹窗列全量，顶部一个搜索框做**本地过滤**。

| 口径 | v10.47 | v10.48 |
|---|---|---|
| 按钮文案 | 「展开全部 N 条 ▾」 | 「**查看全部 N 条 ▸**」（箭头从「向下」改「向右」） |
| 点击行为 | 原地铺进卡内 `.gl` | 打开 `#dlPop` 弹窗 |
| 单次展示量 | 上限 **300** 条（`truncated` 时按钮改成说明文案） | **全量**（实测 717 条） |
| 检索 | 无（只能 Ctrl+F） | 弹窗内搜索框 `#grpAllQ`，本地过滤，显示「命中 N / M」 |
| 可逆性 | 破坏性 —— 铺完回不到「前 3 条」 | 关弹窗即回，卡内始终 3 条 |
| 服务端 `items()` 上限 | 500 | **1000**（覆盖实测最大组 717） |

- 搜索栏用 `position:sticky`（**不是 fixed**，本项目禁 fixed）贴在 `.dlpop-b` 滚动区顶部。
- 弹窗底部写明「点右上角 ✕ 或按 Esc 关闭」；关闭复用既有 `closeDownload()`（ESC / 遮罩 / ✕ 三路都通）。

### ② 修改器「第三方来源」跳转链（`official_url`）

**这不是新增数据源，是补回被丢掉的字段。** 上游 `gamezonelabs.com/api/data/gcm` 的单条记录本来就有
`official_url` / `author` / `custom_name*`，本地缓存 `_gcm-raw.json` 里也一直存着 ——
是 `tools/fetch-trainers.js` 写 `trainers.json` 时只挑了 11 个字段，把它们全丢了。

| 项 | 值（实测） |
|---|---|
| 上游 `official_url` 覆盖 | **3,597 / 3,875 = 92.8%** |
| 入组后覆盖 | **3,451 / 3,683 = 93.7%**（新增 `stats.withUrl` / `urlPct`） |
| 有署名 `author` | **555** 条（386 个不同作者） |
| 新增字段 | `officialUrl` · `siteLabel` · `siteCls` · `author` · `toolName` |

来源站分布（top10）：`CheatScript 1845` · `风灵月影 1154` · `FearlessRev 93` · `3DM 85` ·
`小幸 52` · `B站 40` · `MrAntiFun 33` · `Nexus 22` · `GitHub 15` · `MegaGames 14`。

**通道配色按三档收**（主机十几个，逐个配色反而看不出差异）：`--ch-fling` / `--ch-cheat` / `--ch-src`，
定义仍在主源 `:root`（唯一真源），卡内 `.gl-lk a.bd-*` 与详情页 `.d-res-lk.bd-*` 两处都认。

**行标题也改了**：GCM 条目优先显示**工具自己的名字**（「物品编辑器」「数据查询修改工具」）+
署名，最后才回落游戏名 —— 一卡一游戏之后，卡内再重复游戏名等于每行都一样（22 条修改器分不出区别）。

## 二、根因（4 个，都是「看着像没数据，其实是没取」）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 第三方修改器「没有跳转链接」 | `fetch-trainers.js` 的 `items.push` 只挑了 11 个字段，把 `official_url` 丢了。**数据一直在缓存里** |
| 2 | 点来源按钮跳到的是游戏详情，不是来源站 | `res-groups.js` 的 `fromGcm()` 原先写 `page: x.libUrl` —— 那是**端游库的 xdgame 链接** |
| 3 | 补了来源链后「可下载占比」会虚高 | 来源链与下载链是两种东西。若沿用「links 非空即有下载链」，`trainers.linkPct` 会从 **58.9% 跳到 96.4%** ⇒ 来源链显式打 `ch:'src'`，口径分开统计 |
| 4 | 弹窗本地搜索会静默搜不全 | `items()` 的 limit 上限 **500 < 最大组 717（赛博朋克2077）** ⇒ 提到 1000，覆盖全部组 |

## 四、踩到的坑

1. **`.grp-pop .emu-card.grp` 被圆角闸门抓红**（`check-card-rules.js`，3 页各 1 条）：
   列表容器挂 `emu-card grp` 两个类是为了**复用卡内行样式**，但 `border-radius:0` 属「确实该不同」
   ⇒ 登记进 `RAD_EXCEPT` 并写理由（列表没外框，走 `--cd-r` 会画出四个孤零零的圆角）。
   **闸门是对的**：这正是它存在的意义。

2. **`groups()` 的 limit 硬上限 200 骗到我自己一次**：诊断脚本传 `limit:100000` 只回 200 组，
   算出的「gcm 条目 265」与真实的 3,683 对不上 —— 一度以为 `items()` 有 bug。
   实际是**脚本口径错**，数据没问题。⇒ 读 `groups()` 做全量统计时不能信 `opts.limit`。

3. **同 `source` 下混十几个站**：`community` 一个 source 里同时有 `mrantifun.net` /
   `nexusmods.com` / `bilibili.com` / `github.com` / `playground.ru` …
   ⇒ 来源标签与配色必须按**主机名**判定，按 `source` 只能给一个笼统标签。

### 2.1 决定产品形态的三条硬事实

**① 三个镜像站没有「文件直链」，全是落地页。**

| 镜像站 | 实测响应 |
|---|---|
| `datanodes.to/<id>/<file>.rar` | `302 → https://datanodes.to/download` |
| `filekeeper.net/<id>/<file>.rar` | `302 → https://filekeeper.net/download` |
| `fuckingfast.co/<id>#<file>.rar` | `403` + `<title>Just a moment...</title>`（Cloudflare 挑战） |

⇒ 服务器「代下」就要过 CF 挑战与落地页 JS，**不做**。
⇒ 按钮语义只能是「把你带到镜像站的文件页」，所以弹窗里那句
「实际下载在镜像站网页里完成（不是本站代下）」是**必须写的**，不是免责声明套话。

**② 磁力里的文件与网页分卷是两套东西。** 用真种子只取元数据实测（本机 aria2 1.37.0）：

| repack | 网页分卷 | 磁力内文件 |
|---|---|---|
| Astrobuilder | 2 卷 rar | **7 项 / 2.70 GB**：`fg-01.bin` 2561 MB、`fg-02.bin` 200 MB、`fitgirl-bins.md5`、`QuickSFV.EXE/.ini`、`setup.exe` 4.1 MB、`Verify BIN files...bat` |
| Arma 3 | 48 卷 rar | **19 项 / 86.10 GB**：`fg-01.bin` **71,427 MB** + `fg-02..08.bin` + setup.exe |

⇒ 磁力的「文件选择」粒度是 `fg-0N.bin`（安装数据块），**不是**「选第 12 卷」。
⇒ 下一阶段做文件选择器时，两条路径必须用**两个模型**，不能共用一个目录树。

**③ 体量**：Arma 3 单任务 **86.10 GB**。服务器代下再转发 = 双份出口流量 + 86 GB 常驻磁盘。
⇒ 单任务体积上限、每用户并发、TTL 淘汰、磁盘水位保护是**必做项**，不是优化项。

## 三、实现

### 3.1 只改主源，四张派生页由生成器同步

`public/index.html` 的 `<style>` / `OVERLAY`（`#mask` → `</nav>` 之间）/ 内联脚本三处都是
`tools/page-assets.js` 的共享资产 ⇒ 改主源后跑：

```bash
node tools/build-emulator-page.js && node tools/build-unpack-page.js
node tools/build-resource-page.js && node tools/build-extract-page.js
```

`test-pages-sync` 58/58 守住「派生页没有落后于主源」（本轮实测抓到过一次：拆函数后忘了重建，
闸门报「缺函数 fgDlBodyHtml, fgDlFootHtml」——这正是它存在的意义）。

### 3.2 行内两个按钮

```html
<button class="fgbtn dl" data-fg-dl="<slug>" data-fg-title="<title>">⬇ 直链下载</button>
<button class="fgbtn mg" data-fg-magnet="<slug>">⧉ 磁力链</button>
<a class="fgorg" href="<原站>">↗ 原站</a>
```

- 「原站」不能删：帖子里还有安装说明、截图、语言包说明；但它不是下载动作，降级成小字。
- 旧的「▸ 分卷清单」行内入口**整条删除**，不留两条并行路径（`test-v1089` E4 守）。

### 3.3 直链弹窗 `#fgDl`

```
#fgDl (z-index 120，复用 .dlpop 外壳)
  ├─ .fgdl-hint      「三站是同一套文件的镜像…实际下载在镜像站网页里完成」
  ├─ .fgdl-set × N   主包 / 变体 / 可选附件
  │    ├─ .fgdl-row      [主包] 组名 14 卷
  │    ├─ .fgdl-mir      datanodes.to | fuckingfast.co | filekeeper.net
  │    ├─ .fgdl-acts     ⧉ 复制全部 14 条 | ▾ 展开分卷
  │    └─ .fgdl-list     #1 xxx.part01.rar …（max-height 290px，默认 hidden）
  └─ .fgdl-foot      「1 组 · 主包 14 卷（单站口径）· 现抓」+ 关闭
```

设计取舍：

| 取舍 | 理由 |
|---|---|
| 弹窗而非行内展开 | Arma 3 主包 48 卷，行内会把「下载与资源」顶到几千像素，且插在列表中间会让滚动位置乱跳 |
| 每组独立镜像 | 三站是镜像（实测 564 条里 2/3 重复），一次只渲染当前站；但**组间不能共用**同一选择，否则主包与变体混站 |
| 分卷默认收起 | 48 卷铺满一屏；展开后 `max-height:290px` 内部滚动 |
| 复制用实际条数 | 文案「复制全部 N 条」的 N = 当前镜像下的真实 URL 数，不是 `set.parts` 的声明值（两者理论上相等，实测必须以后者为准） |
| 渲染拆成纯函数 | `fgDlBodyHtml(j)` / `fgDlFootHtml(j)` 不碰 DOM ⇒ `test-v1089` 能用 `new Function` 直接验三类形态，不必起浏览器 |

### 3.4 `GET /api/admin/env`（只读自检）

回答「这台机器能不能跑下载引擎」，全部**并行 + 单项 2.5s 超时**：

```
env:    platform / arch / node / cpus / cpuModel / memTotalMB / memFreeMB / cwd / isRoot / hasApt
disk:   cwd + root 的 totalGB / freeGB（statfsSync）
bin:    aria2c 是否在 PATH（sh -c 'command -v aria2c && aria2c --version'）
egress: dns / https / tcpTrackers×2 / udpDht×2（UDP 发一条 KRPC ping，看有没有回包）
tmp:    可写性（写一个带 pid 的临时文件再删）
```

本地实测：`200 / 2592 ms`，`win32/x64 · node v22.22.2 · 12 cpus · 32556MB`，
`disk 931.5/606.2 GB`，`aria2 未找到`，`dns ok / https ok / tcp ok,fail / udp ok,fail`（两个公共 tracker 只有一个回）。

## 四、踩坑

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 部署「独立探针」把**主站替换掉了** | 部署工具按**工作区**绑定 appId（不是按目录）：传不同目录 = 用新目录替换同一个线上应用 | 立刻重发 `_deploy-gamehub` 恢复，六页 md5 全 MATCH 后才继续（见铁律 166） |
| 2 | 探针部署失败「服务没在 3000 端口响应」 | 探针把 6 个网络探测**串行**放在请求里，最坏 30s+ 才吐首字节，平台 60s 健康检查判死 | 全部改并行 + 单项超时（见铁律 167） |
| 3 | `test-pages-sync` 报「缺函数 fgDlBodyHtml / fgDlFootHtml」 | 拆纯函数后忘了重建四张派生页 | 跑四个 `build-*-page.js`；这条闸门本来就该这么用 |
| 4 | 新 fixture 让 A5 显示「复制全部 0 条」 | 旧 fixture 的变体 `byHost` 是空的，而新实现按**实际条数**出文案 | fixture 补上 `byHost`（真实回包一定有） |
| 5 | 实拍 A8 假绿 | 选择器取 `#dlBody .dl-note`，命中的是**机地网盘段**的说明 | 限定 `#dlBody .dl-gcm .dl-note` |
| 6 | 空 sets 时后端吐的 warning 被吞 | `sets.length===0` 提前 return，warning 拼在后面没执行 | 空分支也带 `warn`（有警告 ≠ 什么都没有） |
| 7 | run-all **前置闸** `check-stdio-guard` exit 1（「未处理 2 处 UNKNOWN」） | 新加的 `execFile(cmd, args, {timeout}, cb)` 是**回调式**，守卫只取「最后一个顶层实参」当 options ⇒ 读到的是回调 ⇒ 判 UNKNOWN | 改用 `promisify(execFile)`，`options` 落到最后一位并带 `stdio: ['ignore','pipe','pipe']`（见铁律 168）；复跑前置闸 **3/3** |

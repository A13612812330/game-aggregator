# v10.99 卡底按钮 = **完整下载弹窗**（默认本模块页签）；详情页底栏恢复原样

> 用户口径（v10.98 上线后当场纠正，两句）：
> ① 「我说的是点击卡片是弹出详情页，这个没问题，但是〔详情底栏那颗「查看本体资源」〕
>    这个我不需要，还是原来的样式」
> ② 「卡片下的按钮，我要求是点击后弹出下载弹窗（**完整的下载弹窗**，但是默认页是根据点击页面
>    进行默认设置，比如我在修改器点开的，我需要他**默认显示修改器的下载页**）」

## 一、结论（先给答案）

| # | 改了什么 | 效果（现测） |
|---|---|---|
| ① 详情页底栏 | 撤掉 v10.98 新增的「📦 查看本体资源 / 🧩 查看 MOD 资源 / 💾 查看存档资源 / 🛠 查看修改器资源」，恢复**只有一颗**「⬇ 下载与资源」 | `.ds-res` 归零；`#dlStrip .ds` 数 = **1**（四区都是） |
| ② 卡底按钮 | 四区卡底按钮（`[data-grp-more]` / `[data-bd-more]`）改开主站那套**四页签 `#dlPop`**，默认页签 = 本分区 | mod→`mod` · saves→`save` · trainers→`modifier` · body→`body`（四区实拍逐条命中） |
| ③ 按钮文案 | 「查看 N 条下载 ▸」/「查看 N 个资源帖（M 个盘口）▸」→ **「⬇ 下载与资源 ▸」**（不印条数） | 卡面 `.meta` 仍有「N 条」胶囊；按钮不再承诺一个可能对不上的数 |
| ④ 旧弹窗下线 | `#grpAllList`（只列本组全部条目 + 弹窗内搜索）与 `.grp-pop*` 样式**整组删除** | 反向断言：`#grpAllList` / `#grpAllQ` / `.grp-pop-s` 全为 0；卡底按钮开的弹窗四页签齐全 |

**为什么上一版方向错**：v10.98 把「模块语境」寄存在**详情页**——点卡进详情、详情底栏再长一颗
模块按钮。用户的实际心智是「卡片下面那颗按钮就该给我下载」，详情页只负责**看游戏**。
⇒ 模块语境跟着**来源卡**走，不进详情页；一个详情页只能有一颗主动作按钮。

## 二、实现（两处代码 + 一条保留能力）

### 1. `tools/resource-sections.js`：两个入口合并成一个落点

```js
function grpDownloadPop(card) {          // MOD / 存档 / 修改器 组卡
  const cat = card.dataset.cat || 'mod';
  const tab = RES_UNI_TAB[cat] || 'body';
  openUniDownload({ title: card.dataset.libt || card.dataset.name || '', id: card.dataset.lib || '', tab });
}
function bdDownloadPop(card) {           // 本体卡（有话题 URL，直接给 url）
  openUniDownload({ title, url, tab: 'body' });
}
```

- `RES_UNI_TAB` 是**唯一**的「分区名 → 页签键」翻译表（`saves→save` / `trainers→modifier`）。
  传错**不报错**：`openUniDownload` 对非法 tab 静默落回 `body`，表现成「从修改器卡点开停在本体」。
- 组卡**不传 url**：MOD/存档/修改器卡只按游戏聚合，没有源站详情页地址；本体页签由
  `dlUniFetchBody` 内部的 `dlUniResolveItem`（libId → 库记录 → url）反查。拿不到就给
  「这一条没有源站详情页」的明确空态，**不会**把「没查」说成「没有」。
- 本体卡**传 url**（话题页地址就在卡上），本体页签直接走 `/api/download`（服务端 30 分钟缓存）。

### 2. `public/index.html`：删回 v10.97 的形态

- 删 `RES_UNI` / `resBtn`（详情底栏那颗按钮）与 `.ds-res` 五条 CSS；
- 删 `detailResTab` 变量与 4 处赋值（`openDetail` 第 4 参 / `closeDetail` / `openDetailById` 第 3 参）；
- `[data-dl-open]` 委托里的 `tab: b.dataset.dlTab` **保留**（通用能力：谁带 `data-dl-tab` 就落哪个页签）；
- 删 `.grp-pop` / `.grp-pop-s` 九条 CSS（弹窗外壳已无消费者）。

## 三、踩过的坑（三条，全部有数字）

### 1. 按钮上的条数与本模块页签**不是同一个口径**

现测（2026-10-21，`/api/res/groups` 与弹窗页签角标）：

| 游戏 / 分区 | 卡面 `count` | 弹窗页签角标 | 两边各是什么 |
|---|---|---|---|
| 剑星 · 修改器 | **2** | **5** | 卡面 = GCM 清单 2 条（Cielos / 剑星）；页签 = 机地修改器帖 4 + GCM 1 |
| 剑星 · 存档 | **15** | **15** | 两边同源（游侠文件 + GTrainers） |

⇒ 按钮印「查看 2 条下载」、点开是 5 条，用户只会认为其中一处是错的。
**铁则**：入口的计数只能来自它将要展示的那份数据；拿不到就先不写数字（条数留在卡面 pill 上）。

### 2. 换弹窗 = 换断言；旧渲染器的标记必须跟着删

`#grpAllList` 一删，`test-resource-page` 里 **23 条**以 `.gl-i` / `.gl-lk a` / `#grpAllQ` 为锚的
断言立刻失效。处理方式不是删掉了事：

- **守行为的**（每条有可点出口 / 通道是真外链 / 原贴入口 → `/api/res/post` → 正文弹窗）**搬到**
  下载弹窗的 `.d-dl-it` / `.svf` 上，判据换成新标记；
- **守旧形态的**（盘口配色 `bd-*` 类、行 `title`、弹窗内搜索）随渲染器一起删除，
  并各配一条**反向断言**（`#grpAllList` / `#grpAllQ` / `.grp-pop-s` 不许回来）——
  只删不加 ⇒ 哪天有人把旧弹窗恢复，没有任何东西会响。

### 3. 「加载中」也算「有内容」

新套件验「默认页签里真的有数据」时，第一版判据是
`#dlBody.textContent.trim().length > 20` —— 结果 `正在读取存档…`（10 个字 + 省略号）直接过关，
**三张卡全红**才暴露：红不是因为没数据，而是因为判据把**占位文案**当成了数据。
⇒ 判据必须 `长度 > 20 && !/正在读取/`，并且轮询等待到数据回来为止。

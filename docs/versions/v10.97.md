## 二、热度从哪来（这是本轮唯一需要新增数据的部分）

`data/res-groups.js` 原先**没有任何游戏级热度字段**：分组只有条数，条目只有下载量。
四区要统一按热度排，只能找一个**跨四区可对齐**的量。最终定了三层取值：

| 优先级 | 来源 | 覆盖率（现测） |
|---|---|---|
| ① | 端游库记录自带 `hot`（`sync-jidi-library` 合并时写入） | 9,869 / 19,732 |
| ② | `jidiId → tid → jidi-topics.json.dpv`（机地话题浏览量） | 热门组命中率高 |
| ③ | 严格同名兜底（只对 `normKey` 完全相等） | mod 200 抽样：124 库内 + 65 同名 + 11 无 |

**为什么需要 ③**：端游库 13,448 条有 `jidiId`，但热门组（剑星 / 泰拉瑞亚 / 消逝的光芒）
的 XD 记录**没有 appid ⇒ 从没被合并过**（`sync-jidi-library` 靠 appid 对齐）。
靠 tid 走不通，只能按名兜底 —— 而按名匹配必须三道护栏：

1. `normKey` **完全相等**（不做包含、不做相似度）；
2. 名字在话题库必须**唯一**（撞名记 `'AMB'` 丢弃）；
3. 长度护栏 `nameKeyOk()`：CJK ≥ 2 字 / 拉丁 ≥ 4 字符。
   ⚠️ 一刀切 `length >= 3` 会整类误杀 2 字中文名（剑星 / 鸣潮 / 仁王）。

**两种量纲不能直接比大小**：话题浏览量常见 10 万级，条目下载量合计常见千级。
`hotPair()` 用两级键 `[有话题热度=2 / 只有下载量=1 / 都没有=0, 数值]`，
否则「下载量大的冷门游戏」会压过「热度已知的热门游戏」。

卡面 tooltip 写明这个数的来源（`hotSrc: topic | dl`）——
不标来源的话，「为什么这个 348,068、旁边那个 2,300」没法解释。

### 保留 / 新增的

| `.grp-more` | 卡底整宽按钮「查看 N 条下载 ▸」→ `#dlPop` 弹窗（全量 + 搜索） |

### ⚠️ `.emu-card.grp .gl` / `.gl-i` 这组样式**必须保留**

它现在只服务弹窗（`.grp-pop .emu-card.grp` + `glRow`）。删掉弹窗里就是一坨没排版的文字。
已在 `test-resource-page.js` 与 `test-emulator-structure.js` 各加一条正向断言钉住。

### 分流顺序（顺序错了就是 bug）

`[data-grp-more]` → `.cov-btn` → 整卡兜底，前两个都必须 `stopPropagation`。
否则点「查看 N 条下载」会同时触发整卡兜底 —— 一次点击两次请求。

## 四、一个被默认排序「撞出来」的搜索跑偏（v10.97b）

改完默认热度排序后，`test-resource-page.js` 立刻红了一条：搜「赛博朋克」第一张卡是 **剑星**。

根因不是排序写错，是**搜索本来就是两条路**：
① 组名命中；② 组内条目标题命中（用户搜「整合包」也要搜得到）。
两条路的组混在一个池子里按热度排 ⇒ 剑星（348,068）只因组里有一条
「武士运动服 赛博朋克2077」就压过了赛博朋克2077（238,529）。

修法：`q` 非空时加**相关性分层** `rel()` 作为主键（名称命中优先），
其余排序键在各自档位内照旧；`q` 为空时 `nameHit = null`，排序与纯热度**完全一致**。

```
搜「赛博朋克」→ 赛博朋克2077 / 剑星 / 巫师3 / 致命解药 / 生化危机3
```
后四个仍在结果里（②那条路没被砍），只是排在后面 —— 断言**正反两条都写了**，
单断第一条会被「过滤到只剩 1 个」作弊满足。

## 五、后台弹窗：从「日志」改成「文章」

九段结构（对应参照页）：大封面 → chip 行（板块 · 原作者 · 时间 · 👁 浏览量）→ 原链 →
正文（小节 / 步骤 / 段落）→ 结构化 steps → 截图墙 → 字段 kv → 数组字段 → 链接列表。

### 三个「不报错的错」（本轮踩到并已守）

| # | 坑 | 后果 | 判据 |
|---|---|---|---|
| ① | 先 `esc` 全文再正则替换 URL | `&` 变 `&amp;` 再拼进 href，浏览器二次解码；URL 里出现 `&#39;` 之类就解错 | `rmvInline` 必须**先切 URL 再分别 esc**；断言 href 只转义一次 |
| ② | `String(对象)` | 存档 `paths` 元素是 `{raw, shown, notes, tags}` ⇒ 弹窗里 44 行全是 `[object Object]`，**不报错** | `arrText()` 对象优先取 `shown`；断言正文里无 `[object Object]` |
| ③ | 「短行即小节标题」 | 正文里「分享文件：xxx」「链接：xxx」很多，整类当标题会把正文切碎 | `rmvIsHead()` 保守白名单：只认 `【x】` 整行 / ≤18 字且以小节词结尾且无句末标点 |

另外两条小口径：`收藏 0` 不占位（0 值当空值）；无封面 / 无正文的条目**不画空壳**
（留白比空框干净）。

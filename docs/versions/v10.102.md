# v10.102 磁力点击改走本机 RPC（Komo-Magnet 页面端）

## 用户原话

> 「只使用其中的磁力链下载，并对应的生成名为 Komo-Magnet，相当于后续作为 GameHub 专用下载工具。
> 现在就是 GameHub 首页看游戏等，后台进行管理游戏资料等，然后工具是辅助下载磁力链接」
>
> 「你负责页面端即可，我将该任务交给另一个 agent」

## 做了什么

**页面端把「唤起协议 + 2.2 秒失焦猜」换成「先探本地 aria2 RPC」**，协议唤起降为第二级兜底。

1. 新增 `KM_SECRET / KM_PORTS / KM_PROBE_MS / KM_CALL_MS / KM_MISS_TTL` 五个常量
   （端口 6800–6805，secret 与工具端约定 `komomagnet-local`）
2. `kmRpc(port, method, params)` —— JSON-RPC over `http://127.0.0.1:<port>/jsonrpc`，
   带 `AbortController` 超时，失败一律 resolve(null)，不抛
3. `kmProbe(force)` —— **并发**探 6 个端口（`Promise.all`），命中即缓存；
   全不通时记 `kmMissAt`，30 秒内不重复探测
4. `kmAdd(magnet)` —— `aria2.addUri`，返回 `{port,gid}`；端口变了强制重探一次再试
5. `kmTrack(port, gid, title)` —— 每 1 秒 `tellStatus`，右下角浮层显示百分比 / 已下 / 速度；
   完成、失败、被移除即停，6 秒后自动隐藏
6. `kcTryHandoff(slug, title)` 三级链：
   **① RPC 直连入队 → ② 协议唤起后重探（800ms 窗口）→ ③ 返回 false 交给云下载**
7. 新增 `kmBusy` 锁：连点只入队一次
8. 新增 `.km-dock` 浮层样式，`z-index:145`（低于 toast 150，高于抽屉 110）

## 为什么

| 方案 | 判断「装没装」 | 耗时 | 误判 |
|---|---|---|---|
| v10.101 协议 + 失焦 | 靠页面失焦反推 | 2.2s | **会**（用户切窗口即误判成功） |
| v10.102 RPC 探测 | 探到端口就是装了 | **6ms**（不通 350ms 封顶） | 不会 |

浏览器没有任何 API 能读「协议是否注册」，这是 v10.101 只能猜的根因；而常驻 RPC 把这件事
从「猜」变成「问」——能连上就是装了，连不上就是没装。顺带还能拿到进度，这是协议唤起做不到的。

## 踩的坑

1. **测试 mock 把 REST 回包套进 jsonrpc 信封** ⇒ 页面拿到的 `ok` 变 undefined，
   磁力取空、直接返回 false，11 条断言全红但错误信息只说「返回 false」。
   根因：同一个 `reply()` 同时服务 RPC 与磁力接口，而两者信封不同。改为 `plain()` 分开。
2. **签名从 1 参变 2 参**，v10.101 里按 `kcTryHandoff(a.dataset.fgMagnet)` 写死的三条正则失配 ——
   换签名要同步换断言，不能只改代码。
3. **串行探测会线性累加**：6 端口 × 350ms = 2.1s，比旧的 2.2s 还慢；必须并发。

# v10.104 本体「0 条」的两个真根因：磁力链接整类丢失 + env 空壳页误判为改版

> 2026-10-22 · 分支 `feat/v10.92-fitgirl-download-ui`
> 一句话：**接口一直是好的，坏在「我们没认出源站给的两样东西」**——
> 一是只有 `magnet:` 的帖被整类丢掉，二是源站 SSR 降级时吐的 1.2KB 空壳页被当成「改版」直接判死。

---

## 1. 用户原话

> 「还是很多问题，我发现本体获取很多遗漏
> 比如渔力全开：`https://jidiyouxi.com/topic/detail/2117239899`，
> `https://www.xdgame.com/game/15568.html`，机地中有很多下载源，但是未获取到」

截图现场：弹窗「本体 **0**」，提示
「源这次没有返回可用的跳转地址……原因：机地页签名未取 env（可能改版）：`/topic/list`」。

---

## 2. 先证伪：「机地真的没有」不成立

同一时刻直连接口（`/api/misc/post_list`，`tid=2117239899`）：

| 请求 | 结果 |
|---|---|
| `resource_type=1`（本体） | `ret:1` · **count 35** · 取回 35 条 |
| `resource_type=2`（mod） | `ret:1` |
| `resource_type=3`（修改器） | `ret:1` |

⇒ 源站有 35 条本体帖，**取数链路本身没坏**。用户「未获取到」是两件事叠加。

---

## 3. 根因 ①：`extractLinks` 只认 `https?://`，磁力帖整类变空

本体 35 帖里 **4 帖正文只有一行磁力**：

```
magnet:?xt=urn:btih:13c35e31f2c8022cbc036f717c805c9c509b5ec2&dn=How.to.Fish.rar
```

旧正则是 `/https?:\/\/[^\s"'<>）)】\]，,。；;]+/g` —— `magnet:` 一个字符都不匹配，
于是这 4 帖的 `links` 是空数组，前端按「没资源的帖」处理。

**改前 / 改后实测（同一 tid）**

| 指标 | 改前 | 改后 |
|---|---|---|
| 本体帖 `withLinks` | 31 / 35 | **35 / 35** |
| 本体地址数 | 78 | **84** |
| 磁力条数 | 0 | **6** |
| 无链接帖 | 4 | **0** |

（磁力 6 条 > 纯磁力帖 4 条：另 2 帖是「网盘 + 磁力」双通道，旧逻辑只留了网盘。）

### 三处必须同时处理的细节

1. **磁力不能走 host 过滤**：`dropInternal` 那条会 `new URL(u).hostname`，
   磁力没有 host ⇒ `catch` 后直接 `continue`，等于白加。
2. **尾标点规则不能共用**：http 那条会把结尾的 `.` 一起剥掉，
   而磁力串里 `How.to.Fish.rar` 的 `.` 是文件名的一部分。磁力只剥 `。；;，,】])>`
3. **去重按 info-hash**：同一种子换个 tracker 列表就是另一串，整串比对会重复入列；
   取 `btih:` 后的小写值作键。

### 前端配套（`public/index.html`）

- `DL_BRAND` 新增 `[/磁力|magnet/i, 'magnet', '磁']`，**排在最前** ——
  XD 的盘口名就叫「磁力下载」，排在 `/迅雷/` 之后会被判成迅雷；新增 `--ch-magnet:#7C3AED`。
- 磁力渲染成 `<button data-km-magnet>`，**不是 `<a href>`**：
  浏览器拿到 `magnet:` 只会弹「要打开 xx 吗」，点取消就什么也没发生（v10.101 踩过）。
  点它先走 `kmHandoff`（探本机 Komo-Magnet → 入队 → 显示进度），
  探不到就**复制到剪贴板**并提示用迅雷 / 比特彗星打开 —— 复制是唯一确定能成功的动作。
- 从 `kcTryHandoff` 里把「磁力到手之后」那段抽成 `kmHandoff`，FitGirl 与机地帖共用一条链路。
  同一条路写两份，迟早一边修好一边还是旧的。
- 分区标题写「35 帖 · 含 6 条磁力」：磁力帖按热度排在后段，常落在「前 12 帖」之外，
  不写出来用户仍会以为没有。
- 文案口径修正：下载条从「共 N 个网盘地址」改成「共 N 个下载地址（含 M 条磁力）」；
  未检测到工具时的提示不再写「磁力仍可直接云下载」（**云下载只服务 FitGirl 那条线**）。

## 4. 根因 ②：env 页返回 1188B 空壳，被当成「改版」

### 空壳页长什么样（实测抓到的正文，HTTP **200**）

```html
<div id="app"></div>
<script>window.APP_INITIAL_STATE={}</script>
<script src="//static2.52jidi.com/game-community-web-outland_test/app.a682720d99.js"></script>
```

1188 字节、没有 `<script id="appState">` —— 源站的 **SPA 骨架兜底页**（SSR 没渲染出来就直出骨架）。

### 触发条件（决定性证据）

| 实验 | 结果 |
|---|---|
| 连续 12 次 GET 列表页（间隔 500ms，带 / 不带 cookie 各 6 次） | **12/12 正常** |
| GET 列表页 → POST 接口 → **立刻** GET 列表页 | **必空壳** |

⇒ 与频率、cookie 都无关，是「页面 + 紧接着的接口请求」这个组合下的 SSR 降级。
所以「加 cookie」「放慢」都不是解，**只有「认出来并换一次」是解**。

### 另一条实测结论：env 跨页面通用

用 `/modify/list` 的 env 去打 `post_list`（同 tid，`resource_type=1`）：

```
http=200  ret=1  count=35      ← 与 /topic/list 的 env 结果完全一致
```

⇒ 主路径空了可以换页面取，不必死磕同一个 URL。
`/modify/list` 实测最稳（718KB 完整 SSR，12/12）；
`/` 首页**不能**当兜底：要么 1188 空壳，要么 appState 只有 7 个键且**没有 host**。

### 改法（`fetchers/jidiSigned.js`）

| 项 | 改前 | 改后 |
|---|---|---|
| 空壳识别 | 无（一律报「可能改版」） | `classifyPage()` 分 `ok / shell / no-appstate / empty` |
| 重试 | 外层 `signedPost` force 重取 1 次，间隔 250ms | `getEnv` 内部：同路径重试 → **换页面兜底**，共 ≤3 次，间隔 400ms |
| 并发 | 三专区并行各自取 env（同时打同一页面 3 次） | **单飞**（同路径共享 Promise）＋ `topicPosts` 先预热一次 |
| 失败语义 | 一句话「可能改版」 | `EnvError{kind, fatal}`；`no-appstate` 标 fatal，让上层立刻放弃 |
| 错误文案 | 「机地页面未内嵌 env（可能改版）」 | 「已试 3 次：/topic/list=shell → /topic/list=shell → /modify/list=shell。这是源站 SSR 偶发降级，不是改版」 |

`fatal` 的用途：env 结构真变了时，外层再重试只会 3×2=6 次页面请求 ——
在机地身上足以把偶发故障放大成真限流。

**兜底实测**：把主路径故意指向 `/`（已知空壳）⇒ **1.6s 后从 `/modify/list` 取到 env**。

## 6. 遗留

- **磁力按钮目前止于「复制」**：Komo-Magnet 工具端未交付，`KM_SETUP` 仍为空串（不渲染死链）。

- **XD 侧（15568）仍是 `needAuth`**：源站要求登录，实测条目全带
  `error: 源站要求登录 / 权限`，这是 XD 的策略，不是抓取缺陷。
- 机地 SSR 降级本身无法消除（源站行为），只能靠「认出 + 换页重取」把影响压到一次点击内。

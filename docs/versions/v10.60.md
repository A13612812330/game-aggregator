## 二、根因：不是「没做归一化」，是**归一化被写了第四份**

`data/name-normalize.js` 早在 **v10.36** 就把商标号 `™®©` 收进了 `SYMBOLS`：

```js
const SYMBOLS = /[™®©°′″·・:：,，.。!！?？'"“”‘’()（）\[\]【】<>《》|｜/\\~～\-–—_+*&#@$%^;；＊]/g;
```

而前端 `public/index.html:3067` 的归并键是**自写的一份**：

```js
function smKeyOf(it) { return splitName(it.title).zh.toLowerCase().replace(/\s+/g, ''); }
```

**只去空白、一个符号都不剥** ⇒ `古惑狼™ 4：时机已到` 的键留下 `™`，与 `古惑狼4：时机已到` 对不上。

这条规矩项目里早就写下来过 —— `tools/test-twin.js:190`：

> `ok(!/function sameGame\s*\(/.test(idx), '★ 前端不再自带 sameGame（同一语义只留后端一份）');`

v10.18 把 `sameGame` 从前端搬回后端，**但 `smKeyOf` 这份漏网了**。本轮把同一个搬法再做一次。

## 三、改法

### 3.1 真源新增**第二族**字符类：`GROUP_DECOR`（窄类）

`data/name-normalize.js` 现在持有**两族**，别用混：

| 族 | 常量 | 用途 | 有无第二道闸门 | 宽度 |
|---|---|---|---|---|
| A | `SYMBOLS` | **匹配**（`normKey`） | 有（`sameGame` 包含护栏 + `numMismatchByTitle` 数字闸） | 剥**全部**标点 |
| B | `GROUP_DECOR` | **展示归并**（`decorKey`） | **没有** —— 键相等就直接并成一行 | 只剥商标号/书名号/中点 |

★★ **为什么不直接复用 `SYMBOLS`** —— 这不是洁癖，是实测：

| 用哪一族 | 新并组数 | 其中假并 |
|---|---|---|
| `SYMBOLS`（宽） | 20 | **2 组** |
| `GROUP_DECOR`（窄） | 3 | **0 组** |

两处假并（全库 19,465 条逐组核验出来的）：

- `空中骑士：永不屈服/Aerial_Knight's We Never Yield`（**续作**）被并进
  `空中骑士永不屈服/Aerial_Knight's Never Yield`（**前作**）—— 只差一个 `：`
- `他们来了/It Reaches` 被并进 `他们来了！/They Are Coming!` —— 只差一个 `！`

⇒ 归并只剥「在任何语境下都不改变游戏名语义」的三类：
① 商标号 `™®©`（**用户点名的正是这一类**）② 书名号/引号包裹 `《》〈〉「」『』【】`
③ 中点 `· ・ •`。
**`： : ！ ! — - ～ ~` 一律保留** —— 它们在游戏名里是实义分隔符，且实测正是假并的来源。

新增符号时的规矩写在常量上方：**拿不准就只加进 `SYMBOLS`**（那道有闸门兜着，归并这道没有）。

### 3.2 `data/twin.js` 新增 `groupKey(title)` —— 归并键的唯一算法

```js
function groupKey(title) {
  return decorKey(splitName(title).zh);   // zh 段语义沿用 v10.25 定的口径
}
```

沿用「标题第一个 `/` 之前那段」的既有语义（不是整串标题）：
`艾尔登法环/A` 与 `艾尔登法环/B` 同键；`艾尔登法环 黑夜君临/…` 不并（那是另一款）。
`groupKey` 放在 `twin.js` 是因为 `splitName` 在那里 —— **不重写拆分逻辑**。

### 3.3 服务端下发 `nkey`（三处喂 `smRows` 的接口）

`server.js` 新增 `withNKey()`：

```js
function withNKey(g) {
  const k = twin.groupKey(g && g.title);
  return k ? Object.assign({}, g, { nkey: k }) : g;   // ★ 键为空**不挂**字段
}
```

挂在 3 条链路上（共 6 个落点）：

| 接口 | 落点 | 喂给谁 |
|---|---|---|
| `/api/library?q=` | `map((x) => withNKey(withBh(x)))` | 联想面板（用户截图那处） |
| `/api/search/all?q=` | 端游桶 `map((x) => withNKey(withRes(x)))` | 「端游库 · 全站收录」组 |
| `/api/search?q=` | headless / 普通 两分支 × XDGAME/机地 两源 = 4 处 | 实时查源站的两组 |

★ 键为空时**不挂**而不是挂空串：空键会让**所有**条目并成一行（比不并更糟）。
实测当前库里空键 **0 条**，但护栏留着。

### 3.4 前端只消费

```js
function smKeyOf(it) {
  if (it && it.nkey) return it.nkey;
  return '~' + splitName(it.title).zh.toLowerCase().replace(/\s+/g, '');
}
```

取不到 `nkey` 时退回**旧键**并加 `~` 前缀（避免与真键撞车）：宁可**少并**，不能错并。
**不在前端补符号类** —— 那就是第五份归一化了。四页（主源 + 三张派生页）同步。

## 五、未做的事（如实说明）

   把它们在**数据层**合成一条是另一件事（`data/twin.js` 的孪生对齐），本轮不碰。
2. **主行标题仍显示 `™`**（`古惑狼™ 4：时机已到`）——那是库里的真实标题，
   与 `data/game-name.js` 的显示层命名是两回事。本轮不改，避免混进第二个话题。
3. **不在榜的组没查** —— 只逐组核验了「本轮**新并**的那 3 组」+「宽类会假并的那 2 组」，
   原有的 1,055 组沿用 v10.25 以来的口径，未重审。
4. **`twin.js` 的 `normTitle` 仍缺 `™®©`** —— `server.js:195` 的注释早就记着这件事
   （`Train Sim World® 7` 的 `®` 不在清洗范围内）。它影响的是**孪生对齐**那条路，
   本轮改的是**展示归并**这条路，两者不是同一件事。**未修**，留给下一轮单独评估

   能区分来源但区分不了版本。不属本轮范围。

## 六、踩到的坑（2 条）

### 6.1 ★★ 实拍探针：数据全对，**截图却是首页**

第一版探针用 `p.click('#searchInput')` 开搜索弹窗。但 `#searchInput` 平时在 `#smask` 里、
`#smask` 没有 `show` 类（隐藏）—— **点它不会打开弹窗**，而 `input` 事件照样会跑
⇒ `/api/library` 发了、`showSug()` 也渲染了、DOM 读出来的行数**全对**，
**截图里却是没弹窗的首页**。差一步就把「没看见」当成「已验证」。

修法：直接调 `window.openSearch()`，并**加一条判据 `#smask.classList.contains('show')`** ——
让「弹窗真的开了」也成为断言的一部分，而不是靠人眼看图。
★ 同族教训已记过（`_live-xdlabel` 那轮的 `PROBE_BASE`）：**探针自己要能证明它测的是那个界面**。

### 6.2 断言写死了「调用形状」⇒ 必然每轮都要改

`test-emulator-structure.js` 那条 v10.52 的断言原本是：

```js
/pc = \{ count: r\.count, items: r\.items\.map\(withRes\)/.test(srvSrc)
```

本轮给同一行套了 `withNKey`（形状变成 `map((x) => withNKey(withRes(x)))`）⇒ 红了。
而这**已经是第二次**：v10.54 给同一对象加 `fit` 字段时也红过一次，当时注释里写着
「钉 `map(withRes)` 即可，不该因为后面多一个字段就变红」。

⇒ 判据改成**只判两个词**：该行**有** `withRes(`、**没有** `map(withBh(`。
意图（端游桶挂 `withRes` 不挂 `withBh`）不变，以后再套一层也不用改这里。
**教训：断言要钉「意图」，别钉「形状」** —— 钉形状的判据不是防线，是每轮的欠账。

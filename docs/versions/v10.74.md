## ① ★★ 这一版的地基是一个**实测出来的数据源硬约束**：源站给不满 13 个

先把「能不能凑够 13 个」这件事查清楚，再谈布局。**结论：凑不够，而且差得不小。**

| 源 | 档 | 实测可拿条数 | 依据 |
|---|---|---|---|
| XD 官网 | 周 / 月 / 全站 | **10 / 10 / 10 → 10 / 10 / 9** | `.hot-soft .plate-list` 三档 **`li` 总数实测都是 10**（cheerio 直接数，不是猜）；全站榜剔掉 1 条「XDGAME游戏运行库检测工具」⇒ **只剩 9** |
| 机地 | 社区档 | **12** | `hotRanks()` 自己有 `slice(0, 12)` 上限 |

★★ **也实测排除了「源站还有更多可拿」这条路**：`/rank/` · `/top/` · `/hot/` · `/paihang/` ·
`/rank.html` · `/hot.html` —— **全部 404**（XD 官网没有独立排行榜页）。
⇒ 想凑满 13 个，**只能补位**，没有第二条路。

## ② ★★ 补位必须**可区分**，否则用户看到的是「真榜从第 11 名才开始」

这一节是本版真正的设计难点，起因是一条实测数字：

| 实测项 | 结果 |
|---|---|
| 榜单条目本身带热度值的比例 | 周 **0 / 10** · 月 **1 / 10** · 全站 **3 / 9**（源站榜行不带热度，库里对应条目也大多没有 `hot`） |
| 补位池（`hot > 0`）条数 | **9,869** |
| 补位池最高 `hot` | **348,068**（剑星） |
| 补位池有封面的比例 | **9,869 / 9,869 = 100%** |

⇒ 如果补位条目**照常**显示「🔥 34.8 万 热度」，它会比第 1–10 名**还显眼**
（真榜条目连热度值都没有）—— 用户看到的观感是「**榜单从第 11 名起才变真**」。
所以补位条目**必须**有两道可区分标记：

| 标记 | 落点 |
|---|---|
| ① 卡片虚线边框 + 浅底 | `.rk-card.libsrc{border-style:dashed;background:#FCFDFF}` |
| ② 副行措辞换掉 | 「📚 库内 x」而不是「🔥 x 热度」（卡片与轮播**两处都要换**） |

★ 池子质量决定了「`cover` 是不是必需」：实测 `hot > 0` 的条目**100% 有封面**，
所以 `cover` 这条要求**不牺牲条数**。仍然要求它 —— 首页展示位出现首字色块卡，
观感代价远大于「少补一条」。

## ③ 实现（四段改动）

### `data/rank-fill.js`（新建，纯函数）

放 `data/` 而不是 `server.js` 里，理由与 v10.70 的排序口径同一个：**纯函数才能离线回归**。

```js
const RANK_SHOW_N = 13;   // 首页榜单总展示数（轮播 5 + 卡片 8）
const RANK_CAR_N  = 5;    // 轮播位条数
const TOOL_RE = /(运行库|检测工具)/;
```

补位池的过滤条件（**少一条都会以「补错了」的形式静默出错**）：

```js
.filter((g) => g && Number(g.hot) > 0 && g.cover && g.url
  && !TOOL_RE.test(g.title || '')
  && !seenUrl.has(g.url) && !seenTitle.has(String(g.title || '').trim()))
.sort((a, b) => (Number(b.hot) || 0) - (Number(a.hot) || 0));
```

★★ **去重必须同时按 `url` 与 `title`** —— 只按 `url` 会被「**同款不同 url**」漏过去
（同一款在机地是 topic 页、在 XD 是游戏页），首页上就会**同一款占两个位**。
这与 `cleanPlate` / `twin.groupKey` 是同一条教训：**归并键要多一道**。

### `server.js` —— `/api/rank` 接上补位

```js
const rankFill = require('./data/rank-fill');
// ...
const f = rankFill.fillRank(mapped, dbAll);
return { p, meta: { ...RANK_META[p], dropped: …, srcN: f.srcN, filled: f.filled,
  showN: rankFill.RANK_SHOW_N, carN: rankFill.RANK_CAR_N }, list: f.list };
```

- 机地档的上限由写死的 `slice(0, 12)` 改成 `slice(0, rankFill.RANK_SHOW_N)`
  —— 原来「12」与「首页展示数」是**两个各自写死的数**（改一个忘一个就静默少一条）。
- ★★ **顺序**：先 `map` 出源站条目、**再整体补位**。先 slice 再补会补在错的位置。
- `meta` 如实下发 `srcN / filled / showN / carN` —— 前端靠它说明「含几条库内补位」。

### `fetchers/xdrank.js` —— 拿掉那个**从来没生效过的**写死 10

```js
-  rows: clean.slice(0, 10).map((x, i) => ({ ...x, rank: i + 1, srcRank: x.rank })),
+  const capped = Number(max) > 0 ? clean.slice(0, Number(max)) : clean;
+  rows: capped.map((x, i) => ({ ...x, rank: i + 1, srcRank: x.rank })),
```

★ 为什么必须拿掉：实测源站每档**就 10 行** ⇒ 那个 `10` **从来没生效过**，
但它会**悄悄砍掉源站未来多出来的条目**；而它与「首页展示 13 个」是**两个各自写死的数**。
⇒ 截断职责上移到展示层（`rank-fill.js` 的 `slice(0, target)`）：
**fetcher 忠实返回源站给的全部，展示多少由展示层定**。`max` 保留成**可选**护栏。

## ④ ★★ 三个必须写进注释的设计约束（都是踩过或差点踩的）

### ① `.cur` vs `.on` 的**语义分离**（差点踩）

`.on` 在本项目是 `rankMark()` 给「**当前打开的详情**」加的通用激活类
（`$$('#rankList [data-url]').forEach(o => o.classList.toggle('on', o.dataset.url === url))`）。
而 slide **也带 `data-url`** ⇒ 如果轮播的可见性也用 `.on`：

> 打开任意一个详情 ⇒ **所有 slide 一起被点亮**（它们在 CSS 里都靠这个类控制 `opacity`）。

⇒ 轮播当前张一律用 **`.cur`**（CSS 与 JS 两处）。断言 D4 / D5 / D6 三条一起守它。

### ② ★★ 定时器纪律：**任何重渲之前先 `rkCarStop()`**

切档（周 → 月 → 全站 → 社区）会整体重渲 `#rankList`。旧 `interval` 若不停，
会继续操作**已被替换掉**的 DOM —— 表现为内存泄漏、以及「**手动点一次却跳了两格**」
（旧定时器与新定时器同时在推同一个索引）。

⇒ 规则写死：**任何重新渲染之前先 `rkCarStop()`**，而不是指望「反正 DOM 换掉了」。
落点覆盖了**所有**会换掉 `#rankList` 内容的出口：`paintRank` 开头、`refreshRank` 开头、
骨架／错误块分支。D7 用**位置断言**（`rkCarStop()` 必须出现在 `el.innerHTML` **之前**），
不是裸子串 —— 裸子串拦不住「挪到后面但代码还在」。

### ③ ★ 轮播 DOM 必须由 **JS 现创建**

`page-assets.scriptForSubpage()` 会把主源脚本**整段抽走**给派生页，而 `#rankStage`
节点只在首页存在 ⇒ 静态写在 HTML 里的轮播容器在派生页会变成**孤儿**（v10.73 的浮层踩过同一条）。
D14 因此判「出现次数 + 位置」，E6 判「只有首页有 `rankStage`」。

## ⑦ ★★★ 反证照出 **1 条假绿**（本版最有价值的一节）

`tools/test-v1074-rank-carousel-counterproof.js` 13 个打坏点，每个都要求**精确到断言**变红。
首轮 **12 / 13**，唯一没变的正好是设计上最该守住的那条：

| 打坏点 | 期望变红 | 首轮实测 |
|---|---|---|
| ④ ★★ 补位条目照常显示「🔥 x 热度」（去掉卡片侧的措辞区分） | `D13` | ❌ **套件仍是 57 / 57 全绿** |

**根因**：`D13` 的判据写成「`it.filled ? '📚 库内 ' + hot : '🔥 ' + hot` 在**整份文件**里出现」——
而轮播模板 `rkSlideHtml` 里**也有一份**（写成 `… + hot + ' 热度'`，**前缀完全相同**）
⇒ 把**卡片侧**那处打坏后，判据仍被轮播那一份满足。

**修法**：**收窄到目标段** —— 从 `rankCard` / `rkSlideHtml` **各自的函数体**里取段，
**两侧都必须有**；再加一条 `D13a` 阳性对照（两段都取到、且**不是同一段**），
防止「收窄」本身失效后判据变成恒真。

> ★ 这是本项目反复出现的一族坑：**作用域太宽既会假绿（本条）也会假红**
> （别的函数把判据撑成命中）。凡「同一段文案在两处实现」的判据，**必须分段断言**。

修完复跑：**反证 13 / 13 全绿** + 还原后复跑 **58 / 58**（`✅ 还原干净`）。

★ 另外两条**纪律性**的坑（都在本文件里）：

1. ★★ **多行锚点必须容忍 CRLF** —— `public/*.html` 是全 CRLF（实测 7951 个 CRLF / 7951 个 LF），
   而反证文件用 `\n` 写多行锚点时**一条都不会命中**。实测被「靶子存在性预检」拦住了一次
   （⑩ 锚点没命中）。拦截本身是对的，代价是整轮白跑 ⇒ 多行锚点一律写 `\r?\n`。
2. ★★ **反证不许在浏览器层全量跑的时候跑** —— 本反证会改 `public/index.html`，
   而 8123 常驻服务是**按请求现读磁盘**的 ⇒ 浏览器套件会加载到被故意打坏的页面。
   这比铁律 113（不许与其他反证并发）**更宽**：反证是「改仓库的排他操作」，
   **先确认没有别的实测在跑，再动**。

★ `test-v1074-carousel-live` 的判「两个定时器并存」手法（值得记下来）：
**不数 `setInterval` 的个数**（它们藏在主源内联脚本的模块级 `let` 里，外部拿不到），
而是**量相邻两次切张的间隔** —— 单定时器恒 ≈5000ms；两个定时器同时推会挤成 ≈2500ms。
判据取「全部间隔 ≥ 4000ms」，不依赖具体实现值，只依赖「没有第二个推手」这个事实。

★★ 观察器还有两处**同一次任务内先摘后加**造成的取样假象必须过滤（第一版就是这么写错的）：
`rkCarGo` 是 `slides.forEach(toggle)`，**先摘旧张的 `cur`、再加新张的**，中间有一瞬 **0 张**。
那一刻浏览器**根本没绘制**（同一个同步任务里）⇒ ①「每个变异都要 1 张」会被判红（**假红**）；
② 同一原因 `findIndex` 在中间态返回 **-1**，照单全收会把**一次切换记成两个时刻**（间隔 ~0ms），
C2/D2 就**永远红**。⇒ 只在「恰好 1 张 `cur`」的稳定态里判定换人；`curN` 记全，
用来守「**任何时刻都不许 ≥2 张同时亮**」这条真判据。

## ⑩ 铁律 119–122（本版新增）

119. ★★ **同一段文案在两处实现 ⇒ 判据必须分段断言**（v10.74 反证 ④ 照出来的假绿）。
    「补位条目换措辞」在**卡片**与**轮播**各有一份，且轮播那份写法是卡片那份的**前缀**
    ⇒ 判「整份文件里出现过」时，把卡片侧打坏仍全绿。
    ★ 同上一条族的另一面：作用域太宽**既会假绿也会假红**。凡判「某处有 X」，
    先问「**还有谁也有 X**」。
120. ★★ **量「有几个推手」不要数定时器个数，去量周期**（v10.74）。
    `setInterval` 的 id 藏在模块级 `let` 里（主源内联脚本），外部拿不到；
    但「间隔是否恒为一个周期」是**可观测**的：两个定时器同时推 ⇒ 间隔被挤成一半。
    ★ 前提是把干扰源移开（本版：鼠标移出轮播，否则悬停暂停把间隔拉长 ⇒ 判据**假绿**）。
121. ★★ **MutationObserver 会报出「同一次任务内的中间态」**（v10.74 两处假红/假红候补）。
    `forEach(toggle)` 这类「先摘后加」的写法会留下一瞬的**空状态**，
    而那一刻浏览器**根本没绘制** ⇒ 不能拿它当「用户看得到的状态」判。
    ★ 判据要落在**稳定态**上；同时把中间态也记全，用来守「任何时刻都不许 ≥2 个同时亮」这类真判据。
122. ★★ **浏览器层批次里的红，必须单跑复现再定性**（v10.74 实测 3 套异常退出）。
    本轮 3 套里只有 1 套是真的（口径连带）：另外 2 套在**单跑时全绿**、

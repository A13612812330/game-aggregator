# v10.98 端游资源卡点击层级纠正：卡 → 详情 → 「查看 \<模块\> 资源」→ 同一下载弹窗

> 用户口径（v10.97 上线后当场纠正）：
> 「不是的，我的意思是端游模块的卡片点击是弹详情页，然后有个按钮 ——
> 是点击查看对应模块的弹窗（同下载按钮，不过默认页面自动选择到默认模块）」

## 一、结论（先给答案）

| # | 改了什么 | 效果（现测） |
|---|---|---|
| ① 整卡点击 | 四区（本体/MOD/存档/修改器）整卡点击 → **游戏详情抽屉**；`.cov-btn` 与整卡走同一条路 | 点卡 → `#drawer.show`；同一刻 `#dlPop.hidden === true`（一次点击只做一个动作） |
| ② 卡底按钮 | `[data-grp-more]`「查看 N 条下载」保留，直达该模块条目弹窗（不冒泡） | 不变 |
| ③ 详情底栏 | 新增「🧩 查看 MOD 资源」等按钮，开**同一个** `#dlPop`，默认页签落该模块 | mod → `.dlm.on[data-dlm=mod]`；save/modifier/body 各自正确 |
| ④ 本体区岔路 | 本体卡**不走** `openDetailById`（库覆盖仅 21%），改走 `openDetail(url, fb)` | 四区链路全部跑通，无「本地库未收录」死点 |

v10.97 的方向错在**层级**：那次把整卡点击让给了「全部条目弹窗」，
等于从卡片直接跳到下载列表、跳过了游戏本身。正确层级是
**卡 → 详情（游戏信息）→ 该模块的下载弹窗**，且弹窗默认就停在你刚才看的那个模块。

## 二、实现（三处代码 + 一条映射）

### 1. `data-lib` 的语义：分组 libId ≠ 详情页 fb.id

模块按钮的 `data-dl-id` 取 **卡上的 `data-lib`**（`ctx.id` 优先），不是详情页的 `fb.id`：

- 赛博朋克2077 的 **717 个 MOD 挂在 `xd-191`**；
- 而详情页 `fb.id` 可能是**机地那条** `jidi-3277800`（同一个游戏两条库记录）。

拿后者去 `/api/mods/match` 会查空，只能靠名称模糊兜底 —— 那是运气不是设计。

### 2. 分区 → 页签键：**两套键名不同名**

```js
const RES_UNI_TAB = { body: 'body', mod: 'mod', saves: 'save', trainers: 'modifier' };
```

- 资源分区叫 `saves` / `trainers`；
- 合并弹窗页签叫 `save` / `modifier`（见 `index.html` 的 `DL_UNI`）。

`openUniDownload` 对**非法 tab 静默落回 `body`** —— 传错不报错，
表现成「从存档卡点进去，弹窗永远停在本体页签，按钮看着还挺对」。
这正是本项目最怕的那类「不报错的错」，所以单独一条铁律（186）。

### 3. 详情页的模块语境 `detailResTab`

- `openDetailById(id, title, resTab)` → `openDetail(url, fb, fromSearch, resTab)`；
- `openDetail` 里 **`detailResTab = resTab || null`**（没有就清空）；
- `paintDetail` 读到它才渲染 `.ds-res` 按钮，`data-dl-tab` 由它决定；
- `closeDetail()` 里清空。

为什么放在模块作用域而不是塞进 `fb`：`fb` 是**库内记录**的镜像（字段与
`/api/library/item` 一一对应），混进「用户从哪个页面点进来的」这种会话信息后，
下一个人读 `fb.xxx` 会以为它是库字段。

**为什么必须在 `openDetail` 里赋 `resTab || null`**：同一次会话里先点资源卡、
再点搜索结果，若只在有值时覆盖，第二个详情页会带着上一个模块的按钮。

### 4. 本体区为什么绕开 `openDetailById`

本体卡是机地**话题**（`tid`），要开详情得先有库记录：

```text
话题 17,220 条 → 有端游库记录 3,621 条（21.0%）
```

走库 id 会有近八成点开就报「本地库未收录」。`openDetail(url, fb)` 直接吃源站 URL，
本来也是全站详情的统一入口（搜索 / 榜单都走它），所以本体卡走这条，
`fb` 由话题字段现拼（title / cover / size / score / genres / releaseDate / jidiUrl）。

### 5. 按钮上**不写条数**

第一版写了「查看 MOD 资源 · 190」，看起来更完整，但四个模块里有一个对不上：

| 模块 | 资源页条数（GTrainers + GCM / 游侠 / 机地） | 弹窗页签条数 | 一致？ |
|---|---|---|---|
| MOD | 190 | 190 | ✅ |
| 存档 | 15 | 15 | ✅ |
| 修改器 | **22**（GTrainers + GCM） | **2**（机地修改器帖） | ❌ |

按钮写 22、点开页签写 2，等于把一处**既有口径差**直接摆到用户眼前。
条数交给弹窗页签自己的徽标去说；按钮只写模块名。
（口径差本身是历史问题，未在本轮改动 —— 记进待办。）

### 防线怎么改的（不是放宽，是换判据）

| 旧断言（v10.97） | 新断言（v10.98） |
|---|---|
| 点整卡 → 打开 `#dlPop` | 点整卡 → 打开 `#drawer`；**反向**：`#dlPop` 没开 |
| 整卡点击那次弹窗里有行 | 详情底栏有 `.ds-res` + `data-dl-tab=mod` + 点它才开弹窗且页签=mod |
| — | 关详情后**用普通入口再开一次**，底栏没有 `.ds-res`（语境已清） |

⚠️ 最后一条踩了个坑：不能「关掉抽屉后判 `.ds-res` 消失」——
`closeDetail()` 只去掉 `.show`，抽屉 DOM 还是上一次那份，那条判据**必然红**（铁律 188）。

另外两处顺手修的**假红**（不是本轮回归，是取样时机问题）：

- 「页签数字胶囊已回填」：`fillTabNums()` 是 boot 后的异步请求，固定 `sleep(2800)`
  在机器忙时会取到「—」；改成**轮询等最多 6s**，语义仍是「最终必须回填」。
- 「点封面按钮 → 打开详情」：详情是**两跳异步**（先 `/api/library/item` 再
  `/api/detail/merged`），固定 `sleep(1500)` 会取样到「还没开」；改轮询等待。

## 四、新增铁律

| # | 铁律 |
|---|---|
| **186** | 分区名 ≠ 弹窗页签键（`saves/trainers` ↔ `save/modifier`）。非法 tab 在 `openUniDownload` 里**静默落回 body**，不报错 —— 映射必须显式成表并写断言。 |
| **187** | 「入口数」不能跨数据源比。资源页的修改器（GTrainers+GCM，22 条）与弹窗的修改器页签（机地帖，2 条）是两份数据；把 A 的数字印在开 B 的按钮上，就是自己制造矛盾。 |
| **188** | `closeDetail()` 只去 `.show`、不重绘 DOM ⇒ **不能**用「关闭后元素消失」当断言（必红）。要验语境清空，用「下一次打开」验。 |

## ② 性能：搜索防抖 + gzip 传输

- **搜索 180ms 防抖**：原版每敲一键全量扫 2.1 万行 + zh `localeCompare` 排序；
  现在 `clearTimeout` + `setTimeout` 统一出口，连打 5 键只重绘 1 次（探针 MutationObserver 实测）。
- **gzip 直出（零依赖）**：部署载荷不带 node_modules ⇒ 不引 compression 包，
  `gen-roster.js` 构建期 `zlib.gzipSync(level 9)` 产出 `public/roster/index.html.gz`（**唯一生产者**），
  `server.js` 在 `express.static` 之前加中间件：GET · accept-encoding 带 gzip ·
  **同名 .gz 文件真实存在** 三条同时满足才直出。实测：10.88MB 明文 → **2.67MB**（-75%）；
  不带 gzip 正常走明文 200；首页不受影响；`--path-as-is` 穿越探测 404。

## ③ 交互：URL hash 状态 + 列显隐

- **hash 状态**：q / kind / res / mode / sort / dir / page / size 全写进 URL hash
  （`history.replaceState`，不产生历史噪音也不触发 hashchange 回环）；刷新不丢、可直接分享定位。
  读侧**全参数白名单校验**，脏 hash 不炸页面；`hashchange` 监听外部变化。
- **列显隐**：来源/大小/热度/更新时间四列可藏（`table.c-xxx` + `nth-child` CSS，JS 不参与重排）；
  `localStorage` 记忆，读写都 try/catch（file:// 隐私模式会抛）。
- 小毛病：弹窗「直接打开资源弹窗」的直达参数 `dl=1` → **`dl=body`** ——
  旧值一直靠服务端「非法值兜底 body」活着，写明写对不依赖兜底。

## ④ 弹窗重排：双栏网格 + 头部元信息行

## ⑥ 新坑（本轮真实踩到）

1. **「并排」的几何判据别写 `abs(A.right - B.left) > 50`**：grid gap 布局里
   `A.right − B.left = −gap`（负数），abs 恒小于阈值 ⇒ 探针假红。
   正确形状：**同一行（top 相近）且 `A.right ≤ B.left + 2`**（判形状≠判语义的几何版）。
2. **hash 页码恢复的行为探针别用「窄筛选组合」造 hash**：`q=刺客&kind=pc&res=trainers`
   筛完不足一页 ⇒ 页码被**合法地**钳回 1，探针自己假红。用全量 2.1 万行 + 纯排序/分页造锚。
3. **临时探针的旧值判据会咬新口径**：`_probe-roster-ui.js` ⑭ 还钉着 `&dl=1` ⇒ 新页面被误判 ❌。
   探针虽是 _ 前缀不入库，也要跟着口径走，否则下一轮被它的红带偏。
4. **跨行锚点钉 `\n` 再次被 CRLF 反咬**（J8 第一版，v10.75 铁律已记过一次）⇒
   server.js 的锚点分段 include + 下标比顺序，不跨行。

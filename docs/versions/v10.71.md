## ① 先立事实：这事到底多常见（全部现测，非估计）

### 1.1 拿到手的是「压缩包」还是「网盘地址」——先分清两条通道

| 通道 | 落点 | 实测结论 |
|---|---|---|
| `/api/download` | **网盘地址**（夸克 / 百度 / 迅雷） | 服务端**拿不到**（要客户端 + 登录）⇒ 解压只能发生在用户机器上 |
| `data/saves-youxia.json` 的 `files.direct` | **真直链** | **1,987** 条（rar **1443** / zip **499** / 7z **45**）；抽测 **4/4** 可下，**且全是压缩包** |
| `data/gtrainers.json` 的 `direct` | 301 中间页 | 跟随重定向后也是压缩包（**9,235** 条，**98.8%**） |

⇒ 所以用户说的「下载直链的压缩包」指的是**第一类真直链**。这一条能由服务端直接抓、直接解。

### 1.2 真实场景当场复现（不是构造样本）

拿一条真直链跑端到端：

```
L0  直链下载                        2,583,569 B
L1  解开 a.rar            →  [ALI213.txt, "Save File-….rar", …]
L2  在**本次产出**里再扫 →  ["Dynasty Warriors Origins Save 99%/"]  ← 里面就是那个 .rar
L3  无压缩包 ⇒ 固定点到达
```

★ 用户描述的「压缩包中含有压缩包」**就在这条链上**：第一层解出来的 `.rar` 才是存档本体。
★ 直链抓取**不需要代理 / 不需要 Referer**，支持 Range（实测 206）。

## ③ 判定口径（★ 全部现测，这是本版的核心资产）

这一节值得单独成章：**7z 的退出码单独用必然误判**，下面每一条都是实测出来的。

### 3.1 ★★ 退出码 2 是**三义**的

| 情形 | 退出码 |
|---|---|
| 加密包 + 错密码 | 2 |
| 坏 zip | 2 |
| 根本不是压缩包 | 2 |
| 加密包 + **不给** `-p` | **255** |

⇒ **只看退出码和下结论是错的**。可靠判据是 `7z l -slt` 输出里的 **`Encrypted = +`**：
加密 zip 退出码是 **0** 且能读出该字段；坏 zip 退出码 2 且**没有**该字段。

### 3.2 ★★ 密码对错必须用 `7z t`（完整性测试），不能用 `7z l`

对 zip，**文件名是明文**，所以：

| 命令 | 对密码 | 错密码 |
|---|---|---|
| `7z l -slt -pXXX` | rc=0 + `Encrypted = +` | **rc=0 + 照样有 `Encrypted = +`** ⇒ **区分不了** |
| `7z t -pXXX` | rc=0 | **rc=2** + stderr `ERROR: Wrong password : inner.txt` |

不给 `-p` 时 `7z t` 是 **255**；无密码包给任意 `-p` 是 **rc=0**（不会误伤）。

### 3.3 ★★ `-aos` 会造成「假成功」——所以密码闸门必须在**解压之前**

`-aos` = 跳过已存在的文件。实测：**同一个已解过一遍的目录**，拿错密码再解 ⇒
7z 把活儿**全部跳过** ⇒ **rc=0** ⇒ 我们判「成功」。这就是「假成功」。

而 `7z t` **不受「目标文件已存在」影响**（对密码 rc=0 / 错密码 rc=2 都照旧）
⇒ 所以流程是 **先 `7z t` 卡密码，通过了才 `7z x`**。

### 3.4 ★★ 失败必须回滚

实测：错密码解压之后，目录里留下了一个 **0 字节的 `inner.txt`**（正确解出的是 **27 B**）。

不回滚有两层危害：
1. 污染用户目录；
2. 下一次再解时它已经「存在」，会被 `-aos` 跳过 ⇒ **坏文件永久留在那里且不再报错**。

修法：`snapshotTree` 快照差集 → 删本次新产生的文件 → 删新目录（由深到浅）。

### 3.5 嵌套识别按**魔数**，不看扩展名

实测直链里出现过扩展名 `.zips` **实为 ZIP**（魔数 `504b0304`）的包。
表里刻意**不放** iso（`CD001` 在 0x8001 取不到）与 arj（`60ea` 仅 2 字节会撞普通文件）。

### 3.6 分卷只解首卷

实测 `-v6k` 生成 `.7z.001~004`：

| 喂给 7z 的 | 结果 |
|---|---|
| `.001` | rc=0，内容**完整** |
| `.002` | rc=2 + 「系统找不到指定的文件」 ← **与坏包同码** |

⇒ 不做特判就会把**中间卷报成损坏**。分卷族：`.7z.001` / `.part1.rar` / `.z01` / `.r00`。

## ④ 实现（三层，解析逻辑**只有一份**）

```
data/extractor.js        ← 解析层唯一真源（7z 调用 / 魔数 / 分卷 / 密码闸门 / 回滚）
  ├─ server.js           ← 站内页的 7 条 API   ┐
  └─ tools/extract-cli.js← 桌面拖放 CLI        ┘ 两者都 require 它，不重写 7z 调用
```

### 4.1 站内页 `/extract.html`（新增第 5 张派生页）

- 两种输入：**下载直链**（服务端下+解，进度 0~40 下载 / 40~100 解压）· **文件夹**（扫描 → 递归解压全部）
- 7 条 API：`env` / `scan` / `download` / `run` / `task` / `password` + 404 兜底
- ★ **熔断**：连续 3 个 `reason === 'error' || 'unreadable'` 就停下并如实报告（长跑不许无脑跑挂）
- ★ **目录护栏** `EX_BLOCKED_DIR`：拒绝盘符根 / Windows / Program Files / ProgramData / 用户目录根 / UNC（解压=写盘）
- ★ **并发上限 2** + 任务保留 24 个 + 事件最多 200 条
- 「再次解压」手动出口：对**上一次的目标**重跑

### 4.2 桌面拖放工具（`解压助手-拖放.cmd` / `-静默.vbs`）

拖包或文件夹到图标上 ⇒ 递归解压 ⇒ **自动弹 HTML 报告**。

- `tools/extract-cli.js`：`--dest= / --depth= / --pw=（可重复）/ --no-open / --json`
- `tools/extract-report.js`：**纯函数**渲染器（报告对象 → 单文件 HTML）
- 退出码：**0** 全好 ｜ **3** 有失败 ｜ **4** 有待解密 ｜ **1** 没给目标
- ★ **报告必出**：采集层抛异常时也照渲染照落盘（失败路径恰恰最需要报告）
- ★ 报告里的「再跑命令」是**只带加密包**的那几条，路径加双引号（实测包名常含空格与中文）
- 报告落点 `_extract-out/`（已 gitignore：含用户本地绝对路径）

**渲染与采集分离**（沿用 `.ref/` 那套纪律）：渲染是纯函数才好断言，采集才碰磁盘和 7z。混在一起测一次就要跑一次真实解压，防线会慢到没人愿意跑。

## ⑤ 踩过的坑（八条，全部真实发生在本轮）

### 5.1 ★★★ `sniff()` 全线静默失效 —— 我自己造的坑

初版匹配条件写成 `sig.length <= 6`，本意是「短签名要额外校验」。
但 `sig` 是 **hex 字符串**，长度是字节数的 **2 倍** ⇒
`504b0304`(8) / `526172211a0700`(14) / `377abcaf271c`(12) 全被这个条件排除，
**所有压缩包都返回 null**，整套解压逻辑静默退化成「不是压缩包，跳过」。

★ 最阴的地方：「纯文本不该误判」那条断言当时**是绿的** —— 因为什么都认不出来。

⇒ 两条教训：① hex 长度 ≠ 字节长度；② **断言必须配阳性对照**。

### 5.2 ★★★ 页面脚本一行非法 token，整页交互全废

```js
const FMT_TX = { zip: 'ZIP', rar: 'RAR', 7z: '7Z', … };
//                                       ^^ 数字开头的 key 在对象字面量里非法
```

浏览器只丢一句 `Invalid or unexpected token` 就什么都不执行 ——
环境条永远停在初值「正在检测解压器…」、所有按钮全废。

★★ **而构建器当时那一堆自检全绿**：节点都在、样式都在、入口数也对 ——
因为它们检查的是**文本存在性**，不是**可执行性**，全是「**存在 ≠ 生效**」的变体。

**修法（根因，不是补丁）**：给 `page-assets.js` 加 `assertScriptSyntax(html, what)` ——
把产物里每个裸 `<script>` 抽出来交给 `vm.Script` **编译**一次（只编译不执行），
编译失败 = **构建失败，页面根本没机会写出去**；并接到**四张派生页**的全部构建器上，
位置在 `writeFileSync` **之前**。

它同时守三件事：语法错 · `<script>`/`</script>` 标签不配对（脚本里藏了字面量 `</script>`）· 产物里压根没有脚本块。

### 5.3 ★★ 用大段新路由替换掉了 404 兜底

写解压那段路由时，我用一大段 `app.post(...)` **直接替换**了原来的
`app.use((_req, res) => res.status(404).json(...))` ⇒ 之后**所有未知路径挂起不响应**。

补回，并把断言升成两条：① 404 兜底**仍在**；② 它**位于解压路由段之后**。

### 5.4 ★★ 我加的注释把结构防线照红了（假红）

favicon 那段注释里写了「放在 `<style>` 之前」，而 `test-emulator-structure.js` 是**数 `<style>` 出现次数**的 ⇒
五张页全部报「`<style>` 不唯一（实际 2）」。

⇒ 修法**改我的注释**（不写出样式标签的字面量），**不动那条有效断言**。
★ 反过来看：如果当时顺手去放宽断言，就是拿「合法输入」去迁就「我写的注释」。

### 5.5 ★ `unpackOne` 的 args 里 `file` 出现了两次

加 `-bso0/-bsp0` 时多推了一次 `file`（它本来就在第 2 位）⇒ 传两个文件参数给 7z，
**rc 仍是 0 但产出为空**。这类「不报错但结果错」是最难查的一种。

### 5.6 ★ 挂死：`execFile` 的 stdin 是 pipe 且没人关

第一次跑 7z 能力探针时脚本被 SIGTERM 杀掉、**连版本号都没输出**。
根因：`execFile` 把 stdin 挂成 pipe 又不关，7z 解加密包时一直**等密码输入**。

修法：`spawn` + `stdio: ['ignore','pipe','pipe']` + 自带 kill 超时 + `-sccUTF-8`。
★ 这条正好命中本项目铁律 6（EBUSY 的真因是 stdin 是 pipe），
而且 `check-stdio-guard.js` 前置闸**当场揪出 5 处**（4 处是新提升的套件 + 1 处 CLI）⇒ 全部改成显式 `stdio`。

### 5.7 ★★★ 防线「报假红」：宿主安全删除守卫（**根本不是套件的 bug**）

三个 v1071 套件各自用 `fs.rmSync(WORK, { recursive: true, force: true })` 清自己的临时目录。
单独跑**全绿**；全量连跑时第三个直接崩：

```
Error: [safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
{"count":69,"threshold":50,"scope":"turn","targets":["…\_test-out\v1071-api"]}
```

WorkBuddy 的 node 包装注入了 `node-safe-delete-shim.cjs`，`rmSync` 会先过 `safe-delete-bulk-guard`：
**本 turn 累计删除的文件数超过阈值（默认 **50**）就拦**。跑全量时 54 套子进程共享同一个 tool call 的
状态目录 ⇒ 前面各套删删删，累计到 69 时撞线。

★★ 最贵的不是「删不掉」，而是**症状指向完全错误的代码**：`run-all` 报
「异常退出：`test-v1071-extract-e2e.js` (exit 1)」—— 看起来像那个套件有 bug，
**而它一行都没错**。我第一次跑全量就是这么去查 e2e 的（查了半天才发现是守卫）。

⇒ **修法**：防线套件与发布脚本**不许递归删大目录**。工作目录按 `process.pid` **唯一化**
（天然就是干净起点，于是**根本不需要删**）；或「**保留 + 覆盖**」（v10.66 载荷重建已用此招）。
★ 代价如实写：`_test-out/` 会累积目录（已 gitignore），**由人工偶尔清**。

★ 该 shim **只在 WorkBuddy 包装环境里注入** ⇒ 用户在自己的 Windows 会话跑 `run-all.js` **不会遇到**；
但我这边跑防线必须按上面写，否则每次全量都会挂一条假红。

### 5.8 ★★ 防线「报假数」：我写的收尾行让成绩被静默猜

本轮新建的 4 个套件收尾都写成 `通过 N / 失败 M`。而 `run-all.js` 取成绩用的是
「同行含「通过」且带 `\d+\s*\/\s*\d+`」—— `87 / 失败 0` 里斜杠后面是**失败数**，
**匹配不上** ⇒ 退化成「从明细里倒着找最后一条 `n/m`」，实测把这套件的 **87 条记成 3/4**（少算 84）。

★ 这类 bug **不会让任何一条断言变红**，只会让「通过 N 条」这个口径长期偏低 ——
而所有人拿它当防线规模的唯一口径（与 v10.70 那条「让防线自己报假数」同族）。
⇒ 四处统一改成 `通过 n/m（失败 f）`。
★ 这次能发现，正是因为 v10.70 给 `run-all` 加了「**认不出汇总行就记 warnings、不静默降级**」——
否则它会安安静静地把 87 记成 3，谁也不会知道。

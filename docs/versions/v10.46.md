## 五、落地形态

### 1. 存档模块主区 = 文件卡（`.svf`）

- 标题行：`💾 存档文件 N 个` + 右侧 `📍 存档位置（N）`
- 卡片：文件名 + 大小徽标 + 通道按钮行（直链做成**主按钮** `.pri`，网盘/eD2K/thunder 为次按钮）
- 一个文件都没有时，给「去源站页面取 ↗」而不是空卡
- ★ **截断**：单款最多 215 条（鬼谷八荒，逐条核对全为真匹配 `bracket`）⇒ `SVF_CAP = 20` + 明说总数 + 展开/收起（`svfAll` 会话态，换游戏重置）

### 2. 位置 = 右上角按钮 → `#svLoc` 二级弹窗

- `z-index` **120**，高于下载弹窗的 110
- 复用弹窗骨架样式（`dlpop-h/dlpop-b` 双类名），因此**主源改一处、四页同步**
- 独立事件监听（`#svLoc` 是 `#dlPop` 的**兄弟节点**，冒泡到不了）+ ESC 优先关上层 + 父关子关
- 打开时若数据未回，**等 busy 落下**再渲染（否则会把「还在读」画成「没有记录」的假空态）

### 坑 2：反证**先抓出了我自己的错**

| 反证用例 | 第一次跑的结果 | 真因 |
|---|---|---|
| ⑦ 期望文案写错 | A 组（直接调 helper）没红，红的却是 B 组与反向锚点 | ⑦ 改的是**调用点**，A 组测的是 **helper 本身** ⇒ 期望文案必须跟着判据走 |
| ⑩ **一条都没红** | 变异后重算结果**一字不变** | 顺带发现 **分支① 的护栏是死代码** |

**分支① 为什么是死代码**：其检索键 `first` 按定义就是「标题首个空白前那一段」，所以它后面必是空白 ⇒ `^(\d)` 永不成立。旧代码在这里调护栏，是真的从未生效过。

**那要不要「跨空白取数」把它救活？实测否掉**：

| 口径 | 匹配 | 被拒 | 多拒的逐条核对 |
|---|---|---|---|
| 不跨空白（**采用**） | 2,043 | 23 | —— |
| 跨空白再取一位 | 2,012 | 54 | **多拒的 31 条逐条全是真匹配**（`1号/6号/8号升级档`、`4职业`、`8.0`） |

⇒ 结论：**只有「同一段里紧贴」才算代际**；分支① 不做代际判定，并把这个边界写进注释与断言。

### 坑 3：探针与实现同源 ⇒ 查不出实现已经变了

### 坑 5：我自己的汇总正则漏了一种格式

本项目套件的成绩行有**两种**格式：`通过 155/155（失败 0）` 与 `结果：50 / 50 通过`。
只写 `[0-9]+ / [0-9]+ 通过` 会把 36 套读成「无成绩行」—— 于是差点把「没读到」当成「没通过」。**数字类汇总必须两种都认。**

### 坑 6：★ 本环境「假红」的真因 —— **stdin 是 pipe**（我第一轮归因错了，已纠正）

**真因**：沙箱里 node 起子进程时，**`stdin` 若为 pipe（node 的默认值）⇒ `EBUSY`（errno -4082）**。
判据**只看 stdin**，stdout/stderr 无关：

```
不写 / 'pipe' / ['pipe','pipe','pipe']   ⇒ EBUSY
'ignore' / ['ignore','pipe','pipe']      ⇒ OK
```

修法即给该调用加 **`stdio: ['ignore', 'pipe', 'pipe']`**（stdout 留 pipe 以便读输出）。

**★★ 我第一轮的归因是错的**：当时写成「`NODE_OPTIONS` 注入的 `node-language-shim.cjs` 拦了
`child_process`」，理由是「清空 `NODE_OPTIONS` 无效、提权无效、换系统 node 也无效」——
**这三条恰恰只证明"与 `NODE_OPTIONS` 无关"**，我却把它们当成了"就是 shim 写死的"。
破案的是一句**对照**：`run-all.js` 用**同一个** `execFileSync(process.execPath, …)` 跑通了 37 套，
我的探针却 100% 失败 ⇒ 差异在 **options** ⇒ 逐项二分 ⇒ 锁定 `stdio`。

**后果（最坏的地方）**：这个坑**让防线自己说谎**。
`try{…}catch(e){out=e.stdout+e.stderr}` 会把 EBUSY 吞成 `out=''`，
反证读到"打坏后一条都没红" ⇒ **把"没测到"报成"护栏是假绿"**。
本轮实测：`_counterproof-v1046.js` 修复前 **0 / 11 成立**，修复后 **12 / 12 成立**
（⑫ 是**新加的第 12 例，专门反证守卫自己** —— 铁律：从不报错的闸门＝不存在的闸门）。

**新守卫**：`tools/check-stdio-guard.js`（静态扫描全部子进程调用，括号配对取 options，
例外表自检陈旧）。一次揪出 **29 处**：24 个反证脚本 + 4 个临时脚本 + **上线代码**
`server.js`（`/api/bh/refresh`）· `tools/daily-sync.js`（**每日自动化每一步**）·
`tools/restart-server.js`（`netstat` 起不来 ⇒ 静默返回 `[]` ⇒ 误判"端口没人占"）·
`tools/refresh-bannerhub.js` · `tools/fetch-soc-*.js` · `tools/test-daily-sync.js` ·
`tools/check-inline-syntax.js`（**它自己也中招** ⇒ 上一版报的"3 个文件语法错"就是这么来的）。

**修复后的真实成绩**：`41 套 · 前置闸 3 / 3 通过 · 通过 3039 / 失败 0 · 异常退出：无`；
逐套求和 **42 行全绿 / 3,043 条**。

### 坑 7：取样不当导致的假红（`test-resource-page.js` 78/79）

断言「主区铺出的是文件卡（`.svf`）」时抽了**第一张卡**。但存档网格里的游戏是 Ludusavi 那份（只有路径），`.svf` 来自游侠那份（有文件），两份库**交集不是全部** ⇒ 抽到没有游侠存档的游戏就平白变红。

## 二、① 封面完整显示

```css
/* 旧 */.cv{width:38px;height:50px;object-fit:cover}
/* 新 */.cv{width:66px;height:40px;object-fit:contain;background:#eef2f7}
       .fxrow .cv{width:64px;height:42px}   /* 行高 56px 不变 */
       .mh img{width:76px;height:44px;object-fit:contain}
```

- `cover` 只适合「容器比例与图一致」；横图放进竖框必然裁切。
- `contain` 保证「整张图都在」，留白用底色补。
- 后台实测（Playwright）：`object-fit=contain`，`64×42`。

## 三、② 同款折叠（`data/game-dedupe.js` 新增）

### 折叠键：两级归并

| 级别 | 规则 | 为什么 |
|---|---|---|
| ① 主键 | 核心名前两段（中文名 \| 英文名），去商标符/标点/空白 | 精确。**不能用首段**：实测会误并 **14 组**（见下方反例） |
| ② 补并 | **单段标题**（无英文名，如「星露谷物语」）按首段并入**唯一**的两段组；首段归一化长度 ≥ 4 | 机地话题记录常常只有中文名，不补并就会单独成行（实测 80 条） |

反例（这四对看起来同系列，实际是不同游戏 —— 合并它们就是数据损坏）：

```
游戏商店模拟器/Console Shop Simulator   ≠  游戏商店模拟器/Game Store Simulator
烟花模拟器/Fireworks Mania             ≠  烟花模拟器/Fireworks Simulator: Realistic
殖民者/The Colonists                   ≠  殖民者/Colonize
逃离病娇/Escape from Yandere            ≠  逃离病娇/Saiko no sutoka
```

### 代表项与保留信息

- 代表项：**XD 源优先**（有站内详情页）→ 热度 → 更新时间。
- 其余条目收进 `alts`（id / title / size / hot / url），**不丢数据**：
  - 后台游戏库：标题后显示 `+N 版本`（悬停列出各自标题与体积）。
  - 名单页：弹窗里显示「同款 N 条已合并」。
- 折叠**只影响展示**：`data/games.json` 一个字节没动，按 id 仍可查，详情页 / 搜索 / 人工覆盖不受影响。

### 生效范围

| 页面 | 是否折叠 | 说明 |
|---|---|---|
| 后台游戏库 `#games` | ✅（`?group=1`） | 以「游戏」为主键 |
| 后台页面管理 `#pages` | ❌ | 那一页的职责就是看**每一条爬回来的帖子** |
| 名单页 `/roster/` | ✅（生成期折叠） | 行数 21,206 → **20,393** |
| 前台搜索 / 详情 | ❌ | 公开语义不变，避免影响既有链接 |

**折叠必须在「排序后、分页前」**：先分页再折叠会让某页少几行、`total` 与实际翻页对不上，而且不报错。

## 四、③ 模块查看弹窗

- 每行加「查看」，弹窗渲染：**正文全文**（标注字数）→ 字段 → 数组字段（存档路径/注册表/云平台）→ 链接（带网盘类型）。
- **不二次请求**：列表接口本身带 `content`（实测 8,942 / 8,943 条有正文），点开即出，不受源站限流影响。
- 结构化来源（FitGirl / Thunderstore / 修改器库 / 存档）如实写「源站没有正文段落 — 下面的字段与链接就是全部内容」，不假装有。
- `def.norm()` 原来只挑 `gameId/title/cells/links` 四个字段 ⇒ 正文被丢掉；现在保留 `raw`。

## 五、④ 名单页：只展示游戏 + 打开即抓取

- 生成期折叠（与后台**同一份** `game-dedupe`），`pcIds` 必须用**折叠前全量**（否则手游同款会被重复列一行）。
- KPI 端游库下方标注「同款已并 1,010 条」—— 少了 1,010 条必须给得出解释。
- 打开弹窗**自动**调 `/api/download` 抓本体（原来要再点一次「实时查询本体」）。服务端有 30 分钟缓存，反复点开不会重复打源站。
- `r[10]` 可手游标记改为**看整组**（代表行可能正好是没关联手游的那条，实测少 152 行）。

## 六、⑤ 云下载：一键打包 ZIP（`data/zip-stream.js` 新增，零依赖）

### 为什么自己写

| 方案 | 否决理由 |
|---|---|
| `archiver` / `adm-zip` | 发布载荷**故意不含 node_modules**（沙箱按 package.json 装），多一个依赖 = 多一个「装不上就整站起不来」的失败面 |
| 先打包落盘再给链接 | 30 GB 任务要再占 30 GB 磁盘，且打包期间用户只能干等 |
| deflate 压缩 | 源文件本身已是压缩包（BT 分卷），再压只烧 CPU 不省体积 |

### 实现要点

- **store（method 0）+ ZIP64**：单文件与总量都可能 > 4 GB。
- **一遍流式**：`local header` 置 bit 3（data descriptor），CRC32 边读边算 —— 先算 CRC 再写要读两遍盘（30 GB → 60 GB）。
- **UTF-8 flag（bit 11）**：中文文件名不标就乱码。
- **central directory 一律带 ZIP64 extra（0x0001）**：统一路径，不按大小分支。
- 客户端断开立即停读（`res.destroyed` + `close`），不让服务器白读几十 GB。

### 实测（本地 + 线上）

| 项 | 结果 |
|---|---|
| 单文件（69 B） | `HTTP 200 / application/zip / 375 B`，Python `testzip()` 无错 |
| 多文件（1 MB + 中文名 + 子目录） | `HTTP 200 / 1,051,192 B`，3 个文件、CRC 全通过、中文名正确、`.NET Expand-Archive` 解压正常 |
| Content-Disposition | `attachment; filename="Chained Together [FitGirl Repack].zip"; filename*=UTF-8''…` |

前端：就绪后**一个**主按钮「⬇ 打包下载全部（N 个文件）」；单文件时自动退回普通保存按钮；清单每行右侧有「单独下」（要续传就用它 —— **打包流式不支持 Range**，界面上明写）。

## 九、边界与待办

- **同款不等于同资源**：折叠后用户看到的是「这一款有 N 个版本」，具体下哪个由他进弹窗决定 —— 不做自动挑版本。
- **打包不压缩**：ZIP 体积≈原始体积。要小就下载后再自己压，服务器不替用户压 30 GB。
- **打包不支持 Range**：断了要重下。要续传用「单独下」。
- ⬜ 折叠规则仍可能漏掉「中文名不同但同款」的情况（如港台译名），需按实际误判样本迭代，不预先扩大规则。
- ⬜ 后台模块弹窗目前只读；如需要「就地编辑/下架」再补写接口。

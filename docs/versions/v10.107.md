# v10.107 · 四个模块收成一个「资源管理」入口

> 2026-10-23 · 信息架构收口。只动后台的组织方式与列表排版，不碰业务与接口。

## 0. 用户原话

v10.106 收尾时我问：「参考站的资源是一个『资源管理』入口，我们拆成了本体/MOD/修改器/存档
四个菜单（页内本来就是子源页签）。要不要也收成一个？收完侧栏是 7 项。」

用户回：「可以」。

## 1. 为什么该合

不是「为了少几项菜单」，而是**四扇门本来就通向同一个房间**：

| 事实 | 证据 |
|---|---|
| 四个视图共用一个 section | `#view-resm` 只有一个，四个入口只换 `rmMod` 一个变量 |
| 共用一套渲染器 | `resmReload()` 一份代码，`RM[rmMod]` 决定列定义与子源 |
| 共用一套接口 | 差别只在 `SRC_DEF[k].url()`，没有按模块分叉的端点 |
| 层次本来就有两级 | 模块内还有子源页签（FitGirl / 机地 MOD 帖 / Thunderstore …） |

⇒ 侧栏那四条是**同一条信息的四种切法**，不是四个页面。v10.90 把它们从
「六个 rm-* 条目」收成「四个 m-* 条目」时是对的（当时确实少了三条重复），
但那一层重复并没有消灭，只是从 6 变 4。

## 2. 改了什么

### 2.1 侧栏 10 → 7 项

```
仪表盘 / 游戏库 / 资源管理 / ── 覆盖与缺口 / 操作日志 / 磁力下载 / 设置
```

- 删除 `m-base` / `m-mod` / `m-trainer` / `m-save` 四条
- 新增 `rm`（资源管理）一条
- `res` 的文案从「资源覆盖」改成「**覆盖与缺口**」——
  它和「资源管理」并排时，两个「资源」开头的名字分不清谁是谁；
  而那一页做的事就是「子源命中率 + 缺口清单」，叫缺口更准

### 2.2 页内两级页签

| 层级 | 元素 | 长相 | 内容 |
|---|---|---|---|
| 一级 | `#rmModTabs`（`.mtab.mod`） | 底边 2px 主色、无边框、带数字药丸 | 本体 · MOD · 修改器 · 存档 |
| 二级 | `#rmTabs`（`.mtab`） | 描边小按钮 | 该模块下的子源 |

两级**必须长得不一样**：原来「切模块」在侧栏（浅色条目）、「切源」在页内（描边按钮），
层次靠位置区分；现在都在页内，只能靠样式区分，否则用户不知道自己切的是模块还是源。

### 2.3 老链接一律当别名

`#m-base` / `#m-mod` / `#m-trainer` / `#m-save` 曾经是能直接打开的地址，
可能有人加了书签、发过链接。所以：

- `HASH_ALIAS` 把旧 hash 折成「`rm` + 该模块」
- `#rm-<模块>` 也认（新格式）
- `go()` 统一处理；`hashchange` 也认别名
  —— 旧写法 `if (VIEWS[v]) go(v)` 对 `#rm-mod` 会**静默忽略**：地址变了、界面没动
- 写回 hash 时带上模块（`#rm-mod` 而不是 `#rm`），刷新/复制地址仍停在同一格

### 2.4 数字搬家：侧栏角标 → 页签药丸

四个模块的条目数口径不同（帖子数 / 包数 / 存档项），**加起来没有意义**，
所以侧栏不挂任何数字；真实数字挂在各自页签上：

```
本体 5,813 · MOD 12,156 · 修改器 4,856 · 存档 11,967
```

口径没变（与 v10.90 一致）：本体=FitGirl 条目；MOD=MOD 帖+Thunderstore 包；
修改器=CE/风灵月影+机地修改器帖；存档=存档位置+云存档。数字仍由
`/api/admin/overview` 的 `domains` 现算，不写死。

**拿不到数字时不印 0**，页签只显示名字 —— `0` 会被读成「这一类一条都没有」，
而实际是「还没拉到统计」。

### 2.5 顺带修掉三个排版问题（合并后才暴露出来）

| 问题 | 改前 | 改后 |
|---|---|---|
| 操作列挤 | `120px` 装「查看 + Repack 页 ↗」⇒ 每行折两行，整表行高翻倍 | `178px` + `#rmRows td:last-child{nowrap}` |
| 标题与 id 粘连 | `使命召唤7/Call of Duty4` + `<small>xd-237</small>` 同行 ⇒ 读成「Call of Duty4xd-237」 | id 另起一行、等宽、弱化（`.fxrow td > small`） |
| 长标题折行 | 折两三行，行高参差不齐 | 单行 `max-width:300px` + 省略号 |

> ★ id 那个 `<small>` 是 `.lnk` 的**兄弟节点**，不是子节点。
> v10.107 第一版写成 `.fxrow .lnk small`，选择器根本不会命中（靠 `.lnk{display:block}`
> 把兄弟挤到下一行，看着像生效了）—— 这类「看起来对了」的样式必须实拍确认，
> 不能靠读代码判断。

## 3. 实测

无头浏览器在 `127.0.0.1:8124` 逐项走一遍（`tools/_probe-rm.js`）：

| 操作 | 结果 |
|---|---|
| 首次进 `#rm` | 落在**本体**，标题「资源管理 · 本体」，面包屑「内容 / 本体 · FitGirl Repack」，子源「FitGirl Repack」，50 行，hash 归一为 `#rm-base` |
| 点「MOD」页签 | 标题/面包屑/页签条三者同步成「资源管理 · MOD」，子源变「机地 MOD 帖 / Thunderstore」，50 行，hash `#rm-mod` |
| 老链接 `#m-trainer` | 进「资源管理 · 修改器」，hash 归一为 `#rm-trainer` |
| `#rm-save` | 进「资源管理 · 存档」，50 行 |
| 在存档页点侧栏「资源管理」 | **仍在存档**（不弹回本体） |
| 页面错误 | `pageerror` + `console.error` 均为 0 |

新增 `tools/test-v10107-rm-merge.js`（36 条）：

反证 3 条（改坏 → 变红 → 还原 → 回绿）：
① 删掉别名表里的 `'m-trainer'`；② 侧栏恢复成四条 m-*；③ 去掉 `resmReload()` 里的页签重绘。

> ★ 第 ③ 条第一次是「假绿」：当时改的是 `go()` 里的 `paintModTabs()`，
> 而 `resmReload()` 里还有一次 —— 删掉它行为完全不变，测试当然不红。
> 这暴露的不是断言弱，而是**那行本来就是冗余的**（已删），
> 顺手也说明「同一函数被两个入口各调一次」会同时制造「改了没效果」和「改坏了不红」两种假象。

## 5. 没做

- **没动配色**：上一版（v10.105）已经把参考站 cream 主题整块搬过来，本版只管组织方式。
- **没合「覆盖与缺口」**：它是跨模块的**报表**（子源命中率 + 缺口清单），
  不是「某模块的条目列表」，合并会把两种用途塞进一页。
- **没做模块级的 URL 参数**（`?mod=mod`）：hash 已经能表达同一件事，多一套参数只会两处漂。

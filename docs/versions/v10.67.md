## ② ★★ 真 bug：详情页「修改器 / 存档」两块，此前**永远是空白**

这不是版式问题，是**所有用户路径**都受影响的功能缺失。

### 三条证据（互相独立）

| 检查 | 结果 |
|---|---|
| 探针 hook `window.fetch` 打出详情页**真实发出的请求**（`tools/_probe-trblock.js`） | `?id=110&t=群星%2FStellaris` —— **丢了 `xd-` 前缀** |
| 同一款换正确 id 直调接口 | `?id=xd-110` → trainers **30** / saves **1**；`?id=110` → **0 / 0 / 0** |
| 服务端兜底逻辑 | `/api/res/game` **只在 `id` 为空时**才按 `t`（标题）搜库；`id` 有值就直接拿它查 ⇒ 裸 id 静默返回 0 条 |

### 根因

资源分组是按**本地库 id**（`xd-110`）归组的（`resGroups.libIdsFor()` 的键来自 `data/xref` 与 libId），
而 `loadTrBlock` / `loadSvBlock` 取的是 **`d.id` = 源站裸 id**（XD 的 `110` / `3668`）。
旁边四个兄弟函数（`loadBhBlock` / `loadReqBlock` / `loadRelated` / `loadDlBlock`）**都收 `fb`**，
只有这两个漏了 —— v10.23 给兄弟函数补 `fb` 时没同步到它们。

```js
/* 改前 */ const gid = String((d && d.id) || '');
/* 改后 */ const gid = String((fb && fb.id) || (d && d.id) || '');
```
调用点同步：`loadTrBlock(d, title, fb)` / `loadSvBlock(d, title, fb)`。

### 修后实测（`tools/_probe-railitems.js`，1440×1000）

| 指标 | 改前 | 改后 |
|---|---|---|
| 发出的请求 id | `?id=110`（裸 id） | `?id=xd-110`（本地库 id） |
| 「修改器」区块 DOM | `''`（0 字符） | `#trBlock` **224px** |
| 「存档」区块 DOM | `''`（0 字符） | `#svBlock` **224px** |
| 外层 `#trSvSlot` | **12px**（空壳） | **224px**（真分区） |
| 卡头「全部 N →」按钮数 | **0** | **1**（艾尔登法环 `xd-3668`：修改器 7 / 存档 63 / 按钮 3） |

★ 为什么这类 bug 特别值得记（已入铁律 84）：它**看起来和「这款游戏确实没有修改器」一模一样** ——
页面不报错、接口回 200、区块只是不渲染（`if (!items.length) { slot.innerHTML = ''; return; }`）。
**200 ≠ ok** 的又一种形态。而且它是被**探针点名**的，不是靠读代码看出来的。

## ⑤ 补样本覆盖：为什么必须再加一个「零资源款」

这套 `#trSvSlot` 的 12px 空壳**只在「没有修改器/存档」的款上存在**。
而 v10.67 之前，两个套件用的都是**有资源**的样本（该块是 224px 真分区）——
**结构上就测不到**这个缺陷（已入铁律 85）。

而且「落点几何」这一条路在要守的场景上**会假绿**：条上挂着 12px 空壳项时，
点它滚到的位置紧跟着就是真分区 ⇒ 几何取到的仍是 ≥24px 的分区 ⇒ 通过。

⇒ 两条补救（`test-v1025-rail.js`）：

1. **零资源样本**（`ZERO_GAMES` 候选表动态挑，本轮挑到 `xd-106` 荒野大镖客2）：
   `⑤c′` 断言「条上每项的目标节点都 ≥24px」；
2. **阳性对照** `⑤c″`：先断言该样本的 `#trSvSlot` **确实存在且确实是 <24px 的壳**
   —— 否则「条上没有它」可能只是因为这一款压根没渲染这个元素 ⇒ 断言**空转**。
3. **直读 `dRailItems`**（`railTarget()` 选中的节点本身，高度绕不开），
   与「落点几何」**互补保留**：几何判端到端落点，直读判条上挂了什么。
   ⚠️ 这是本套件**唯一**读页面内部变量的地方，理由写在文件头；
   读不到时**报红**（不静默跳过）。

## ⑧ 本轮踩的坑

1. **★★★ 「展示用的 id」与「取数用的 id」不是同一个东西**（→ 铁律 84）。传错了不报错，
   只是恒返回 0 条，且**看起来和「这款确实没有」一模一样**。排查手法：hook `window.fetch`
   打出真实 URL，比读代码找参数快得多。
2. **★★ 「有内容」不能用 `> 0` 判；而只测「有数据」的样本会漏掉空壳场景**（→ 铁律 85）。
   修可见性判据时**必须同时补反例样本 + 阳性对照**，否则断言空转。
3. **★★ 媒体查询断点之间会留「谁也不管」的缺口**（→ 铁律 86）。「响应式做过了」≠「所有宽度都覆盖」；
   判据要**扫一遍宽度**。定位法：`scrollWidth` 恒为某个**与视口无关**的数 = 某元素的**内容固有宽**。
   ⚠️ 扫「最右元素」时必须排除 **fixed 子树**，否则浮层会一直冒充最右。
4. **★★ 断言里不许钉「样本自身的名字」，也不许写死「容差量」**（→ 铁律 87）。
   ⑨c 钉了名字、⑩ 写死了 `n-1`，两条都因为**数据/版式一变**就红，而它们守的东西其实**一条都没守**。
5. **★ 断言被「自己写错的样本调用方式」带偏**：`openDetail(url, encodeURIComponent(jidi), false)`
   第二参不是 JSON ⇒ `fb = {}` ⇒ 与被测的真实路径（`data-fb` 是 JSON / `openDetailById`）**不一致**。
   ⇒ 套件调用被测函数时，**必须走真实入口**，否则测的是另一条代码路径。
6. **★ 浏览器套件不能并行跑**：`_probe-railitems.js` 与正在跑的三套件抢占同一浏览器，
   报 `Navigating frame was detached`。教训：**一次只跑一个用浏览器的东西**。

## 三、踩坑与根因

### ① 标题有**四种**不一致形态，只匹配一种会漏 35/39 份

第一版规则只写了 `/^# CODEX-DONE-v10\.(\d+)/`，dry-run 立刻暴露：39 份里只有 **4 份**命中。
实测全部形态：

| 形态 | 份数 |
|---|---|
| `# CODEX-DONE v10.N`（**空格**，不是连字符） | 20 |
| `# CODEX-DONE-v10.N`（连字符） | 7 |
| `# GameHub v10.N`（更早的写法） | 2 |
| `# v10.N`（已规范，无需改） | 10 |

⇒ 改成统一归一化 `/^#\s*(?:CODEX-DONE[-\s]+|GameHub\s+)?v10\.(\d+)/` 一次覆盖。

### ② `report.js` 是**功能性破坏**，不是文档问题

```
- fs.readdirSync(ROOT).filter((f) => /^CODEX-DONE-v10\.\d+\.md$/.test(f))
+ fs.readdirSync(path.join(ROOT, LOG_DIR)).filter((f) => /^v10\.\d+\.md$/.test(f))
```
不改它，五项汇报的第 ⑤ 项会**变成「0 份」** —— 目录还在、只是找错地方，**不报错**。
这正是本项目反复踩的「静默失效」形态，所以顺手把判据加进了 `test-report.js`。

### ③ 结构闸只扫根目录 ⇒ 归档 = 把文件移出守护范围

闸里原本是 `fs.readdirSync(ROOT)`（非递归）。39 份日志一搬走，它们就**再也没被守过**，
而且**不会有任何提示**。已扩展为「根目录 + `docs/versions/`」并新增 6 条守卫。

### ④ 闸把「代码段里的示例」当成了真链接（假红）

`docs/versions/README.md` 在表格里用**行内代码**演示「根目录该怎么写链接」，
闸把它当真链接去解析 ⇒ 必然找不到。与「围栏里的 `#` 不是标题」是同一类问题，
因此新增 `stripCode()`：查链接前先剥掉围栏块与行内代码段。

## 四、新增的 6 条守卫（`tools/test-doc-structure.js`）

| # | 判据 | 守什么 |
|---|---|---|
| ① | 根目录无 `CODEX-DONE-*.md` | 旧命名回潮（有人按老习惯在根目录新建） |
| ② | `docs/versions/` 下无 `CODEX-DONE-*.md` | 「只搬文件没改名」漏掉的那一半 |
| ③ | 无 `` `CODEX-DONE-v<版本>.md` `` 活引用 | 引用改了一半；★ 判据收窄到**具体文件名**，规范里的通配写法 `CODEX-DONE-v*.md` 不算 |
| ④ | 版本号 v10.min → v10.max 连续无缺号 | 文件被误删/漏迁 |
| ⑤ | 每份日志 H1 与文件名版本号一致 | 复制模板忘改版本号（人眼扫索引看不出来） |
| ⑥ | 所有 md 相对链接目标存在 | 迁移时漏改引用 —— 纯文本形态本就不报错，改成链接后才露出来 |

## 七、★ 顺带完成了卡了 4 天的发布（v10.32 → v10.40）

v10.39 起发布一直被 connector-proxy 故障阻塞（09-25 实测 5 次全失败，含「空目录 + 假 appId」也 `fetch failed`）。

| # | 原先的失败原因 | 本轮做法 |
|---|---|---|
| 1 | **载荷太重** —— 直接发项目根（994.2 MB / 14290 文件）⇒ `MCP -32001 Request timed out` | 发**发布载荷**：80.1 MB / 260 文件（**8.1%**），MUST 11/11 |

★ 另一条判据说明代理层已恢复：09-25 的报错是 `fetch failed`（请求没到工具），
本轮同一个调用变成 `timed out`（请求到了、只是载荷太大）—— **错误形态变了，就不该再按老结论走**。

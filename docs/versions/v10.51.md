# v10.51 —— Mod / 修改器页签也能在弹窗里看原贴 + 防线自身补一道覆盖性守卫

> **一句话结论**：详情页「下载与资源」弹窗里，**Mod 与修改器**两个页签从「整行外链（点一下跳机地源站）」
> 改成 **整行可点开原贴** —— 复用 v10.50 已建好的 `#postPop`（标题 + 正文 + 截图，按原贴布局铺开），
> 行内保留「源站 ↗」出口且**点它不会顺带弹窗**。数据侧零改动：`content` 本来就在手上
> （mod 7,824/7,825、modifier 1,118/1,118 = **100%**），改的是渲染。
> 收尾时顺手补了**防线自己的一条缝**：`run-all` 现在会断言每个 `test-*.js` 都已登记，不再有「红了没人知道」的孤儿套件。

## 一、改了什么

用户口径原文：

> 「Mod和修改器也同样，变成下载链弹窗能看到获取贴内容」

| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| ① | 弹窗「Mod」页签行 | `<a class="d-dl-it" href=源站 target=_blank>` **纯外链** | 整行 `div.d-dl-it.has-post[data-post-open][data-src=mod]`（`role=button` + `tabindex`），**点行即开原贴** |
| ② | 同上 行内 | 只有「源站 ↗」 | 「源站 ↗」保留 + 行内多一个 **「原贴」按钮**（`button.po-btn`） |
| ③ | 弹窗「修改器」页签 | 同 ① | 同 ①（共用 `dlModRowsHtml(items, kind)`，`kind` 决定文案） |
| ④ | 弹窗「存档」卡片 `.svf` | 只有文件/路径按钮 | 有正文的卡片多一个 **「原贴」入口**（`data-src=yx`） |
| ⑤ | 「原贴」按钮样式 | 写死在 `.emu-card.grp .gl-lk button.po`（卡内作用域） | 收成**通用类 `.po-btn`**（换到弹窗就得抄第二份 ⇒ 铁律 17） |
| ⑥ | 数据层 | —— | `data/savesYx.js` 抽出并导出 **`hasPost(x)`**（判据唯一真源），`slim()` 与 `res-groups.fromYx()` 共用 |

**关键实现细节**：`[data-post-open]` 的 document 级委托里，**必须先让开行内外链**：

```js
const po = t.closest('[data-post-open]');
if (po) {
  if (t.closest('a[href]')) return;   // ★ 此行必须排在 postOpen 之前
  postOpen(po.dataset.src, po.dataset.id);
  return;
}
```

判据用 `a[href]`、**不是**给每个链接挂 `data-stop` —— 链接是渲染时生成的，挂标记等于要在三处渲染函数里各记得补一次（铁律 17）。
⚠️ 顺序反了就会出现「点源站也弹原贴」⇒ 两个弹窗叠一起；而**光验「能弹出原贴」看不见这个 bug**，所以另配了一条断言钉住它。

## 二、根因与数据（全部实测）

**「界面缺字段 ≠ 数据源没有」的第 3 次现场**（前两次：v10.48 `official_url`、v10.50 `mods.json.content`）：

| 来源 | 字段 | 覆盖 |
|---|---|---|
| 机地 MOD 帖 | `data/mods.json` → `content`（`kind=mod`） | **7,824 / 7,825 = 100.0%** |
| 同上（`kind=modifier`） | 同上 | **1,118 / 1,118 = 100.0%** |
| 游侠存档帖 | `saves-youxia.json` → `desc` / `steps` / `shots` | 有正文/步骤/截图之一即给入口（`hasPost()` 判据） |

修改器帖与 Mod 帖**共用同一个接口**：`GET /api/res/post?src=mod&id=<id>` 实测可取到正文（样本 `1460840573` → **1,014 字**），
所以 `dlModRowsHtml()` 里 `kind` 只影响文案，取数一条路。

⇒ 结论：**改的是渲染层，不是采集层**。前端也不需要新字段 —— `slim()` 只多下发一个布尔 `hasPost`，**正文照旧不下发**（投影的初衷不变）。

## 四、踩到的坑

1. ★★ **`let` 顶层绑定不挂 `window`** ⇒ 探针写 `window.dlUni` **恒 undefined**，
   四条新断言首跑假红（`expWith=0`，而页面实际 60 条都有入口）。裸写 `dlUni` 反而可达；
   仍要 `try/catch` 兜 TDZ。**与铁律 38 同族**：探针读不到 ≠ 页面没有。
   已补 **铁律 51**。
2. ★★ **`\bpo\b` 测不出 `po-btn`**：`-` 是非单词字符 ⇒ 词边界在 `po` 后照样成立 ⇒
   反向断言「类名不该再叫 `po`」**恒真**。必须用 `classList.contains('po')` 判整串。
   已补 **铁律 52**。
3. ★★ **一条早就失效的旧断言**：`test-v1025-dlstrip.js` ⑩b 写的是「存档模块给的是『放哪』而不是『下什么』」
   （判据 `#dlBody .dl-sv-row > 0 || empty`），但 v10.46 已按用户口径把这一屏**反过来**
   （主区铺文件卡 `.svf`、路径让位到 `#svLoc`）⇒ `.dl-sv-row` **恒为 0** ⇒ 该断言**自 v10.46 起一直是红的**。
   不是本轮改坏的，是**没人跑**（它要真浏览器，不在 `run-all` 的 SUITES 里）。
   按项目规矩处理：**先确认新口径要保什么**（「**能下载的文件**摆在主区」）**再改断言**，
   而不是看到红就删。
4. ★ **`schtasks` 被沙箱黑名单拦**：改用 `node tools/restart-server.js` 重启 8123；
   重启后复测 `/api/saves-yx/match?id=xd-191` → `count=48 ｜ 首条 hasPost=1`。
   （后台任务通知里那条 `node server.js failed` 是旧服务被正常杀掉，非故障。）

## 五、★★ 本轮真正的架构性收获：防线自己有一条「没人看」的缝

### 5.1 症状

`test-v1025-dlstrip.js` 那条 ⑩b 红了 9 个版本（v10.46 → v10.51）**没人发现**。
根因不是断言写错，而是**它压根不在防线里**：

> 这句话是**纯注释，没有任何东西验证它**。

### 5.3 修法：把「要不要纳入防线」变成机器必须回答的问题

`tools/run-all.js` 新增 **`checkCoverage()`**（放在最前面，先于前置闸）：

| 表 | 含义 | 自带的可观测判据（防「塞错类别」） |
|---|---|---|
| `SUITES` | 静态层，默认恒跑 | ——（原有） |
| `BROWSER` | 浏览器实拍层，`--browser` 才跑 | 源码必须 `require('./browser')` |
| `COUNTERPROOF` | 反证脚本（失败才是通过） | 文件名必须含 `counterproof` |
| `SHIM` | 兼容壳（复用另一个套件） | 源码必须 `require('./test-…')` |

断言：`tools/` 下每个 `test-*.js` 必须**恰好**出现在四张表之一，否则直接报错退出。
另加两个开关：`--browser`（把第二层并进同一次记账/汇总）、`--guard-only`（只跑守卫，给反证和 CI 用）。

**反证 13/13**（`tools/_counterproof-v1051.js`）—— 故意制造三类违规，每一类都必须被抓出来：

| 反证 | 做法 | 结果 |
|---|---|---|
| A 孤儿文件 | 新建一个没登记的 `test-*.js` | 红，文案点名「**未登记**」+ 文件名；且**不**误报其它两类 |
| B 错放表 | 临时副本把普通文件塞进 `BROWSER` | 红，文案是「**没有 `require('./browser')`**」；且**不是**兜底那条 |
| C 清单陈旧 | 临时副本留一个已删除的文件名 | 红，文案是「**在 tools/ 下不存在**」 |

★ 反证脚本**第一次跑是 11/13** —— 挂掉的两条是**它自己的 bug**：B 段建了临时文件却没删，
导致收尾那条「还原后必须恢复通过」变红。**正是那条自检把它抓出来的**（若没有这条自检，
它会把「留下垃圾文件」当成「反证成功」并一路绿下去）。

### 5.4 顺带发现的两个**真缺陷**（本轮**未修**，如实记下）

跑 `BROWSER` 层时另外三套的红，逐条定性如下 —— 两条是**真缺陷**，一条是**口径过时**：

| 缺陷 | 证据（全部实测） | 性质 |
|---|---|---|
| **A. 空壳区块仍被收进定位条** | 艾尔登法环 `counts={mod:0,saves:0,trainers:0}` ⇒ `#trBlock`/`#svBlock` `innerHTML=''`（h=0），但外层 `.d-pair` 仍留 2 个空 DIV ⇒ **`#trSvSlot` h=12px**；`railTarget()` 的可见性判据是 `offsetWidth>0 && offsetHeight>0` ⇒ 12px 通过 ⇒ 定位条上出现「修改器/云存档」，点进去什么都没有 | **真缺陷**（探针 `tools/_probe-trsv.js` 可复现） |
| **B. 合并项落点与邻项只差 12px** | 同一条：`#trSvSlot` docTop=1903、`#relSlot` docTop=1915 ⇒ 点第 6 项滚到 1830，此时第 7 项也已越过高亮线（抽屉顶 + 90px）⇒ **高亮跳到「同分类」**（实测轨迹 `6→7`） | **真缺陷**，根因是 A（空壳把两项压到相距 12px） |
| **C. `more` ⑦/①b 的样本已空** | 怪物火车2（`xd-10584`）现测 `counts={mod:1,saves:0,trainers:2}` ⇒ 两块都 ≤3 ⇒ 不触发卡头版「更多」⇒ 拿不到 `d-more-hd` 样本。**v10.47 把存档区从 Ludusavi（路径）改成「可下载的存档」后条数变少**，样本选择是数据依赖的 | **断言口径过时**（`dMoreHd` 产出函数仍在，L4410/L4444 都在调） |
| **D. `search-ui` 行密度 3 条 + 1 条窄视口** | 常见行高 **86px**（限 70）· 最高 **101px**（限 85）· 首屏完整可见 **6 行**（需 ≥8）· 820px 视口抽屉 **845px** 溢出（限 820） | **待定性**（需先确认「86px 是本版可接受口径」还是退化） |

⇒ 这四条**都还没改**（改 A/B 是改 UI 行为、改 C/D 是改判据口径，都该先拍板）。
判据与探针已留给 v10.52：`tools/_probe-rail-offsets.js`、`tools/_probe-trsv.js`。

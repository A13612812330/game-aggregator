## 二、② FR 遗弃：为什么必须「先落 SOP，再删」

用户 2026-10-10 拍板遗弃、2026-10-12 执行。**执行顺序是硬要求** ——
FR 的抓取方式是**实测换来的**（CF 四条路怎么试、参数怎么定标、阶段② 为什么必须一次跑完），
不落档就删，下一个人会**原样重踩一遍**。

### 2.1 落档：`docs/sop/FR-fearlessrevolution-抓取SOP.md`

12 节，其中**只有 §十一「复活手册」是"将来照做就能重做"的真正载体**：

### 2.3 ★ 为什么摘掉是**零影响**（不是推断，是实测）

`data/fr.json` **从未产出**（阶段② 从未跑）⇒ `data/fr.js` 的 `ensure()` 读不到文件 ⇒
`stats()` 返回 `{ total: 0, missing: true, why: 'ENOENT…' }` ⇒ `fromFr()` 实际贡献 **0 条**。
摘除前实测确认：`res-groups.libIdsFor('trainers')` 的 **3,692** 款里 **FR 贡献 0**。

### 2.4 ★ 为什么必须给 FR 配**负向守护**（本版最容易被忽略的一点）

项目里到处是「**三源合并（GCM + GTrainers + FR）**」的历史注释 —— 那是 v10.47 的**真实口径**。
下一个人读到它，很可能**顺手把这个源接回来**。而 FR 遗弃是**不可逆的信息损失**，
所以 `test-v1058.js` 的 A / B / B2 / C 四组做的是**负向断言**：

- A：4 个文件实体**不许存在**（含「缓存复活」——`_fr-list-raw.json` 回来了就意味着阶段② 可能被顺手跑起来）
- B：`server.js` / `res-groups.js` 里**不许再有 FR 接线**（四路拼接**恰好四路**，少一路不报错所以必须钉住）
- B2：四页**剥注释后**零「FearlessRevolution」
- C：**SOP 在位** + SOP 里的**版本档引用都真实存在**（防幻觉引用）

## 三、③ 首页「库范围」三视图

### 3.1 ★ 先查出口径矛盾（本轮最重要的技术发现）

上一轮（v10.57 §六）建议的是「**合并视图只放已挂 `libId` 的 1,685 款**，1,645 条留手机专区」。
按那个口径做出来，「合并」会**恰好等于端游视图** —— 因为**挂 `libId` 的 1,685 款逐条都在端游库里**。

**现测实证**（`tools/_probe-1685-confirm.js`，只读探针）：

```
手游池总数 3,330 · 已挂 libId 1,685 · 手游独有 1,645
已挂 libId 且端游库确有 1,685 / 例外 0
```

⇒ 用 AskUserQuestion 请用户定，用户选「**手游全部并入（推荐）**」⇒ 合并 = **21,110**。

### 3.2 三视图的数字与口径

| 视图 | 键 | 口径 | 现测 |
|---|---|---|---|
| 端游库 | `pc` | 与改动前**完全一致**（缺省值不变，不是新默认） | **19,465** |
| 手游中心 | `mob` | 手机端**有数据**的游戏（含与端游库重合的 1,685） | **3,330** |
| 合并 | `all` | 端游全量 ∪ **手游独有 1,645** | **21,110** |

★ **`all` 为什么只并「独有」**：重合的那 1,685 款**本来就在端游库里**，并进来就是同一条出现两次。
这条口径**写在服务端注释里**（`server.js` `/api/library/browse`），并被 `test-v1058.js` E 组钉住。

### 3.3 实现要点

| 位置 | 改动 |
|---|---|
| `data/mobilehub.js` | 新增导出 **`all()`** —— 走 `itemsView(ensure())`，与手机专区**同源**（不是 `list()`，那是手机专区的排序口径） |
| `server.js` | `scope` 参数分三支；`all` 走 **`mergePick(pcAll, mol, keyOf, offset, limit)`** —— **归并取页，不拼接全量**（否则每请求都要拼 21,110 条） |
| `public/index.html`（主源） | `SCOPES` 常量 + `curScope` + 筛选条第 4 行「库」+ `#scopePills` + `filterQuery()` 带 `scope` |
| `tools/emulator-sections.js` | 手机专区支持 `?q=` |

### 3.4 两个「不做就会骗人」的细节

1. ★ **手游视图下分类行必须整块换掉**：手游条目**没有分类字段**（社区/实测记录里就没有），
   留着按钮就是**点了没反应**。⇒ `renderCats()` 加 `mob` 分支换成说明文字。
2. ★ **手游独有卡点了不能开空抽屉**：端游库根本没这款 ⇒ 跳手机专区。
   而**只跳过去是不够的** —— 必须带 `?q=<游戏名>`，否则把人送到 3,330 款的列表头。

### 3.5 ★★ `?q=` 落地链路：一个必然踩的坑（实测数字）

手机专区**默认开着「仅看匹配端游」**，而**手游独有恰恰就是没匹配上的那 1,645 款**
⇒ 只填 `q` 不关这个开关，**搜出来必然 0 条**。

| 请求 | 结果 |
|---|---|
| `/api/mobilehub/list?q=Pro Evolution Soccer 2013&stats=all`（= 关掉开关） | **10 条** |
| `/api/mobilehub/list?q=Pro Evolution Soccer 2013`（= 默认开关） | **0 条** |

⇒ `initEmu()` 里**同时**置 `emuState.matched = false`，且**位置必须在
`bindToggle('emuToggleLib','matched')` 之前**（那一步会按 `emuState` 画开关态）。
端到端实拍：点「📱 仅手机端」的卡 ⇒ `emulator.html?q=Pro Evolution Soccer 2013`
⇒ 搜索框带值、开关自动关、**搜到 10 款**。

## 六、踩到的坑（6 条）

1. ★★ **`gamesDb.all()` 不 `load()` 会静默返回 0 条** —— 第一版 `_probe-1685-confirm.js` 忘 `load()`，
   于是输出「已挂 libId 且端游库确有 **0** / 例外 **1,685**」—— 与真结论**完全相反**，而**探针不报错**。
   差一步就会把「合并只并独有」这个正确设计**当成错的改掉**。
   ⇒ **修法两件**：探针里补 `gamesDb.load()` + **加自检**（id 集合 `< 19000` 直接 `exit 2` 并打「结论不可信」）。
   ⇒ **规矩：任何「全 0」或「全例外」的结论，先证明探针读得到真值。**（与 v10.56 那条同源，第 2 次踩。）
2. ★ **「`SIZES` 的第一项也叫 `k: 'all'`」** —— 断言「三个视图键是 pc → mob → all」写成**全文件扫描**，
   扫出 `all,pc,mob,all`（容量区间表 `{ k: 'all', nm: '不限' }` 是 v10.1 的老代码）⇒ **假红**。
   ⇒ 修法：**先把 `const SCOPES = [ … ];` 那一块切出来**再匹配，并补一条「块能被切出来」的自检。
   **判据的作用域没框住**，这是本轮第 2 次同类问题。
3. ★ **断言写了不存在的字面量** —— 断言 `c.dataset.mol === '1' … emulator.html?q=`，
   而代码是**拼接**的：`location.href = 'emulator.html' + (mq ? '?q=' + … : '')`，
   两段之间隔着 `' + (mq ? '` ⇒ **字面量永远匹配不上**（第 3 次同类问题）。
   ⇒ 修法：拆成两条——「去手机专区」与「带 `?q=` + `encodeURIComponent(mq)`」各自断言，并**再补一条反向**
   （手游独有卡**不再走** `openDetail`，否则开出空抽屉）。
4. ★ **`stripComments` 的行注释正则过度贪婪** —— 写成 `[^\n]*?\/\/[^\n]*` 会把
   `const x = 1; // 注释` 的**整行**吃掉 ⇒ 所有「代码里有没有这行」的断言**全部假红**。
   ⇒ 必须与 v10.57 逐字一致：`(^|[^:])\/\/[^\n]*`（`(^|[^:])` 是为了**放过 `https://` 里的 `//`**）。
5. ★ **反证脚本是**新建**不是修改 ⇒ 还原 = 删除** —— `data/fr.js` / `data/_fr-list-raw.json` 在反证期间被
   **创建**，`finally` 里必须写 `fs.rmSync(f, { force: true })`，只写「写回原内容」会**污染下一次基线**。
   ⇒ 另加**前置检查**：反证开始前若临时产物已存在，直接 `exit 1`（否则「变红」是继承来的、不是本分支造成的）。
6. **`_shot-scope.js` 首屏读到 0 卡**（上一轮）—— 固定 `sleep(1400)` 不够 ⇒ 误判「默认视图坏了」。

### 9.3 ⑦ 模组名称未清洗

根因：`tools/fetch-mods.js:103` `title: s.title` —— **零清洗**，源站帖标题一路透传到界面。
实测脏点（全库 8,943 条）：含年份 **746** · 【】/[] 前缀 **1,600** · 整合包/合集 **174** ·

**改法：只洗显示层，数据一个字节不动。**
原始标题是「去源站搜同一条帖」的凭据 ⇒ `title` 保持原样，只在返回层派生 `dtitle`；
原始标题继续挂在悬浮 `title=""` 与原贴弹窗里。

规则本体收口在 `data/name-normalize.js#cleanModTitle`（**唯一真源**），四处消费：
`data/mods.js`（`deco()` 浅拷贝派生，**不原地赋值**以免污染 `ensure()` 的缓存对象）·
`data/res-groups.js`（聚合层）· 前端 `dlModRowsHtml` · 前端 `dResRow`。

保守档只砍四类：① 开头【…】分类前缀 ② 重复的游戏名 ③ 尾部营销话术 ④ 残留空白与首尾分隔符。

**★★ 本轮最贵的一处修正：只有「长度护栏」不够，还要「信息量护栏」**

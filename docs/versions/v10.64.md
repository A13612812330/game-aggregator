## ③ 改了什么

### A. `--top` 参数化：不再把 20 写死

| 旧 | 新 |
|---|---|
| `const TOPN = 20;`（常量） | `const TOPN = Math.max(1, Number(getArg('--top', 50)) || 50);` |
| 产物名 `core-games-live20-*` | 产物名 `core-games-live<N>-*`（快照 `_core-live<N>-*`） |
| `tools/_gen-core-live20.js` 等 3 个脚本 | **改名**为 `_gen-core-liveN.js` / `_gen-core-liveN-html.js` / `_shot-core-liveN.js` |

理由：文件名里写死 20，扩到 50 后**文件名会说谎**（比 `README` 里写错更糟的是产物名字错，因为产物会被转手）。改名同时把日志前缀 `[live20]` 换成 `[core<N>]`（运行时自报款数）。

### B. 加「本体大小」列

数据源：`data/games.json` 的 **`size`** 字段（各条目**自带**，非跨源挂载；全库覆盖 **19,012 / 19,465**，四条件池 **165 / 168**）。

| 位置 | 改法 |
|---|---|
| **CSV**（用户在看的那份） | 表头 `… "端游库id", "本体大小", "热度" …` —— **紧跟 id 后一列**；行值 `r.size \|\| ''` |
| **HTML** | 表头 `# / 游戏 / 本体大小 / 热度 / …`，`<td class="sz">` 紧随「游戏」列（id 在「游戏」列内，显示顺序一致） |

★ **口径必须写在页面上**（已写进 `t1` 的说明段）：

> **本体大小**取自源站列表页的**声明值**（`data/games.json` 的 `size`），**不是我方实测** —— 它是源站标注的安装体积概数，与实际下载包可能略有出入；缺值显示 `—`，不用 0 占位。

「实测值 ≠ 声明值」必须分清谁的值，否则下轮有人会拿它去「修正」实测数据。

### C. ★★ 修一个真 bug：熔断把「源站没有」当成了「我们抓挂了」

```js
// v1（错）            // v2（对）
if (b.st !== 'ok') {   const isNetErr = b.st === 'err';
  failStreak++;        if (isNetErr) failStreak++; else failStreak = 0;
```

`bodyOne` 的失败态有两种，性质完全不同：

| 状态 | 含义 | 该不该计入熔断 |
|---|---|---|
| `err` | 网络层失败（超时 / 连不上） | **该** —— 可能是源站真挂了，继续扫只是白等 |
| `nobody` | 机地本体专区为空 / XDGAME 需登录 | **不该** —— 这是**源站现状**，重试无用但也**不代表我们抓挂了** |

v1 把两者一起数 ⇒ **连续 6 款热门款恰好都缺本体就提前收工**，后面能合格的款全被丢掉。20 款时没撞上（前 30 位里「缺本体」是散的），**50 款必撞** —— 本轮实测扫到 20-25 位附近就出现「明末 / 黑神话」连续 `nobody`，再往后还有成段缺修改器的款。

★ 这条与既有铁律同源：**熔断只数真故障**；熔断条件一旦宽松到「把正常结果算失败」，它就从保护变成**静默截断**（结果少而**不报错**）。

### D. 两个「防再次踩」的自证

1. **快照 ↔ 参数自证**：渲染脚本读快照后校验 `snap.criteria.topn === TOPN`，不一致直接抛错 ——
   防「拿 20 款的快照渲染成 50 款的页」这种**不报错**的错配。
2. **投影字段清单**：`buildPool` 里给 `size` 补了注释 ——「投影里漏了它，页面那一列就会**整列空着而不报任何错**」。
   （同一个坑 v1 已经踩过一次：漏 `jidiId`/`source` ⇒ 20 款全判「未关联机地话题」，看着像源站没数据。）

### E. 顺手修掉一处硬编码

```js
// v1：只对 2026-10-12 这天成立
const bodyToday = picked.filter((r) => /2026-10-12/.test(r.body.date || '')).length;
// v2：跟着交付日走
const bodyToday = picked.filter((r) => String(r.body.date || '').startsWith(STAMP)).length;
```

代价：v1 那种写法**换一天跑就会静默变成 0**（KPI「本体为今天新帖」显示 0，看着像源站今天没更新）。

## ⑥ 坑（3 条）

1. **★★ 熔断把「源站现状」也算失败**（见 ③C）—— 20 款时是**潜伏**的，扩到 50 款才暴露。
   规矩：熔断只数**网络层**错误；「源站没有」是**结果**，不是**故障**。
2. **★ 硬编码日期会静默变 0**（见 ③E）—— `2026-10-12` 写死那天没报错，换天跑 KPI 就变 0，
   而 0 看着像「源站今天没更新」，会被当成事实写进结论。
3. **★ 产物文件名里写死数字 = 会说谎的名字** —— 扩款后若沿用 `live20` 命名，
   「50 款的表」叫 `live20`，下轮接手的人（或我自己）会先怀疑数据错。改名成本 3 条 `mv`。

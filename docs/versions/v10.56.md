## 二、逐件展开

### ① `verify-online.js`：6 条「永远不会再绿」的死断言

**症状**：线上验收长期 **25 / 31**，6 条红，而**每一条的本意都仍然成立** ——
死断言与「真红」长得一样，第三层防线实际已失去区分力。

**两类成因，两种改法**：

| 类型 | 条数 | 原写法 | 改法 |
|---|---|---|---|
| 陈旧特征串 | 2 | `'启动前先运行 Cheat Engine'` + `'是占位符。<br>'` | 前者 v10.47 起本地已无此字样 ⇒ **删掉**；后者换成现行文案 `'是占位符，按自己的账号替换'` |
| 写死的魔数 | 4 | `>= 9`（3 处）+ `spKeys.length >= 9`（1 处） | 收口成常量 **`UPSTREAM_SUMMARY_MAX = 6`**，判据改成「**严格多于上游摘要**」 |

**为什么 6 才是那个界**：这些断言的本意一直是「我们展示的是**并集全量**，不是上游摘要那个
**6 台**上限」—— 6 是**语义上的界**，`9` 只是当年某次实测的偶然值。数据源一变（8 台）就永远红。

**顺带加了两条更有区分力的判据**（原写法既漏判又假红）：

- `/api/device/specs`：「数量 ≥ 9」→ 「**逐台**带回 chip 且**台数 == 机型清单台数**」
  （旧写法在「接口少返几台」时照样通过）
- 弹窗：「行数 ≥ 9」→ 「行数 **> 6** 且 **== 入口声明数**」
  （只看 `> 6` 会漏掉「入口写 8 台、弹窗只画 6 行」这种**截断**）

**反证**（`tools/_counterproof-v1055-live.js`，**6 / 6**）：魔数放大 / 特征串退回失效串 /
接口逐台性打坏 / 弹窗自洽打坏，四条各打坏一次都必须红；还原后必须复绿**且文件逐字节一致**。

> ★ 死断言的镜像坏法是**恒真断言** —— 看着在跑、其实什么都没判。
> 所以「改完变绿」不算完成，必须逐条证明它**真的参与判定**。

本版**逐项实测**后发现该转述**走样**了 —— 原文自己写的是「**不是护栏太严，

**两侧实测**：

- **收益端**：游侠 3,581 条里 1,625 条能提取游戏名，其中含中文数字 **280 条**，
  而**真正未匹配的只有 12 条**（去重 7 个名字）——逐条看**没有一条**是「中文数字当序列号」：

### ④ 外部源主动巡检（`tools/check-sources.js`）

**为什么**：本步之前的 10 个 daily-sync 步骤只验「**我们自己的**接口通不通」，
**完全不验上游还认不认我们**。9 个外部源改版会**静默失效** —— 抓取器不抛异常、
只把空结果落盘。已发生过：**机地搜索连续 6 日不可用，无人发现**（用户先察觉）。

**三层判据**（★ 关键：不能只看 HTTP 200 —— 本项目「200 判不出新旧」同样适用于上游）：

| state | 含义 |
|---|---|
| `down` | 网络失败 / 4xx / 5xx |
| **`degraded`** | **HTTP 200 但内容特征不符** ← ★ 改版的典型形态、也最难发现 |
| `stale` | GitHub 类源最后提交过久（上游停更） |
| `ok` | 拿到预期内容 |

**10 个源**：机地官网 · 机地 MOD 页 · XDGAME · 游侠存档列表 · GTrainers ·
Ludusavi manifest · BannerHub 配置库 · MobileModels 机型库 · kalvo · Steam store API。

两条判据特别值得记：

- **游侠存档列表**：断言页面含 **≥5 个 `showpatch/\d+` 链接** —— 列表页若改版，
  抓取器会照常返回 0 条而**不报错**，这条正是为它写的。
- **Steam store API**：固定 appid `550` 做**限流哨兵** —— Steam 429/空响应时抓取器会静默少数据。

**接入**：`daily-sync` 的 `STEP_DEFS` 第 2 位（紧跟服务体检，先知道上游在不在再跑写库步骤）；
**非关键**（源挂了不该阻断我们自己的管线），但**失败不静默降级**，照实报 `fail` 写进摘要。
`--dry` 下照跑（只读，无 `write` 声明）。

**反证**（`tools/_counterproof-v1056-sources.js`，**6 / 6**）：200 但无特征 → 必须 `degraded`；
不存在的 appid → `degraded`；404 路径 → `down`；不存在的域名 → `down`；还原复绿 + 逐字节一致。

复现：`node tools/check-sources.js`（人读）/ `--json`（机器读）

## 四、踩到的坑（5 条，全部会静默出错）

1. **★ 抽样探针漏一层 JSON 包裹 ⇒ 差点得出完全相反的结论。**
   首版 `_probe-pcreq-gap.js` 直接取 `d.pc_requirements`，而 Steam 响应的结构是
   `{ appid: { success, data: { pc_requirements } } }` —— 少了一层 `.data`
   ⇒ **30 / 30 全判「页面无 pc_requirements」**，眼看就要写下「源站都没有推荐配置」。
   ⇒ 修好后加**阳性对照**（库里已有 `rec` 的条目必须读得到）。
   **规矩：任何「全 0 / 全假」的抽样结论，必须先证明探针本身能读到真值。**
2. **★ 量化探针把「普通汉字」当成数字 ⇒ 这本身是有用的信号。**
   E 的首轮试算把「一 / 十 / 三」逐字替换成阿拉伯数字，得到 **570 条「误拒」** ——
   逐条看全是 `一起` / `十字军` / `三维` / `四重奏` 这类词。
   ⇒ 这个「探针缺陷」**恰好**量化了那个改法的**真实风险**，直接支撑了「不做」的决策。
3. **★ 记忆里的数字会在转述中走样。** 「约 11 条**被代际护栏误拒**」实为
   v10.46 原文的「23 条被拒里约 11 条**名字写法没对上**」（匹配通道 ≠ 护栏），
   且四个样本里 1 条已自愈、3 条已不在数据中。
   ⇒ 引用旧结论前**先回去读原文那一节**，别读二次摘要。
4. **反证里「坏法不成立」≠「断言失效」。** A 分支把游侠列表页换成 `patch.ali213.net/` **首页**，
   结果断言正确地判了 `ok` —— 因为**首页也含 ≥5 个 `showpatch` 链接**。
   ⇒ 换成确实不含该特征的页面（XD 首页）才构成有效反证。
5. **本版自己的防线断言写得不严谨（2 条先红后修）**：
   ① 「源站日期格式单一」把 294 条错位值也算成另一种格式 ⇒ 改成只对**有效日期**要求单一；
   ② 「`>= 9` 已清零」把**说明注释里的引用**也数进去 ⇒ 必须先**剥注释**再数
   （并补一条对照断言，证明「剥注释」这一步是必要的）。

## 五、架构性收获

1. **「改完变绿」不是完成，「能被打红」才是。** 死断言的镜像坏法是**恒真断言** ——
   本轮 6 条死断言 + 源巡检 10 条判据，每一条都单独打坏过。
2. **上游巡检的判据必须分层**：`200 ≠ ok`。真正难发现的是 **`degraded`**（200 但内容改版），
   只判状态码的巡检会在源改版时**全绿**。
3. **「不做」也要有数据支撑。** E 的价值不在写了代码，而在用两侧实测
   （收益 0 / 代价 570）把一个**悬了很久的待办**关成了明确结论，并留下负向守护防它被重新捡起。
4. **派生字段可以「读时补」而不是「落盘补」**。GT 的 `ts` 放在 `ensure()` 里补：
   零数据重跑、所有消费方自动受益、且**不会因为忘跑重建脚本而漂**。
   落盘侧复用同一个 `tsOf` 即守住「一份实现」。

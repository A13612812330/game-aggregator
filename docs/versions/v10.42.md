## 二、根因：「README 重复」的真相 —— 同一批摘要写了两次

不是「README 里有重复段落」，而是**两份文档各自维护了一份同款摘要**，谁都说不清哪份才算数：

| 文档 | 版本摘要块 | 覆盖范围 | 块所在位置 |
|---|---|---|---|
| `CODEX-INDEX.md` | **41 个**（v10.1 → v10.41，**无缺号**） | 全量 | L211 → L1854（1,644 行） |
| `README.md`（旧） | **34 个**（v10.41 → v10.1） | **缺 v10.11 ~ v10.17 共 7 版** | **L1 → L1978**（1,978 行 / 145.9 KB） |

两份块是**同一批内容的两次书写** ⇒ 并存只会各自漂移：CODEX-INDEX 补到 41 版，README 停在 34 版，
**差额那 7 版只有一处有**；反过来 README 里的措辞又与 CODEX-INDEX 不同。

★ 真正让用户看不出「这文件干什么用」的是**第二个后果**：README 顶部只往上长、从不删，
于是**唯一 H1（`# GameHub 游讯聚合（机地 × XDGAME）`）被挤到第 2011 行** ——
GitHub 首页打开第一屏全是「v10.41 增量…v10.40 增量…」，**看不到「这是什么项目」**。

而全量说明本来就有更合适的地方：

| 位置 | 体量 | 职责 |
|---|---|---|
| `docs/versions/v10.N.md`（41 份） | 518.9 KB | **逐版完整说明**（改了什么 / 真实对照数据 / 踩过的坑 / 验证结果） |
| `docs/versions/README.md` | 7.1 KB | **唯一索引**（一行一版） |

⇒ 收敛方向：**README 只留「最近 5 版摘要 + 指针」**，历史摘要不再在 README 里维护第二份。

### 优化 2：端口不再静默自增（治 v10.41 踩到的 8124 副实例）

原实现：`EADDRINUSE` 就 `listen(port + 1, triesLeft - 1)`，最多退 30 次 ⇒
「杀完立刻启动」会**静默**在 8124 起一个副实例，三个后果：用户以为重启成功（8123 还是旧进程）、
两个实例共写同一份 `data/**`、线上诊断以 8123 为准看到的却是旧代码。

现在改成**闸门 + 逃生开关**：

```js
const ALLOW_PORT_SHIFT = process.env.GAMEHUB_PORT_SHIFT === '1';   // 默认 false
...
if (ALLOW_PORT_SHIFT && triesLeft > 0) { listen(port + 1, triesLeft - 1); return; }  // ★ 只有显式开闸才自增
console.error(`[GameHub] ★ 端口 ${port} 已被占用 —— 本次不会自动换端口（v10.42 起）。`);
process.exit(1);
```

| 改动 | 内容 |
|---|---|
| `server.js` | 默认**响亮失败**：打印「最可能是上一次的服务还在跑」+「先跑 `stop-gamehub.cmd`」+「要让位到下一端口请设 `GAMEHUB_PORT_SHIFT=1`」 |
| `启动聚合站.cmd` | 新增 `:WAITFREE` 循环：**最多等 20 s**，仍在占用则打印占用 PID 并 `exit /b 1`，**不 fallback 到别的端口** |
| `启动聚合站-静默.vbs` | 启动后**轮询核实真监听上了**（`Do While n < 15`），起不来就 `MsgBox` 说明原因并 `WScript.Quit 1`（旧行为是固定 sleep 后直接开浏览器 ⇒ 开一个打不开的死页面） |

★ `.cmd` 的等待计数必须用 **goto 循环**：塞进 `( )` 块里时 `%WAITS%` 在**解析期**就展开成初值 ⇒ 死循环。
这条已进防线（`test-launcher.js` H 段）。

### 优化 3：`report.js` 加「运行期缓存对照」（只提示，不判定）

v10.41 的「机型恒 6 台」之所以漏过验收，是因为 `report.js` 只有两条判据 —— 前端 md5 + `/api/spec/dict`，
两者都只回答「**代码是哪一版**」，回答不了「**线上这份运行期数据还活着吗**」。

新增两个探针 + 一个纯函数：

```js
const RUNTIME_PROBES = [
  { key: 'bhparams.items',   path: '/api/bh/params?k=ULTIMATE_MARVEL_VS__CAPCOM_3&limit=12', pick: (j) => (j.items || []).length },
  { key: 'mobilehub.devices', path: '/api/mobilehub/match?t=终极漫画英雄vs卡普空3',            pick: (j) => ((j.hit && j.hit.devices) || []).length },
];

function runtimeCacheRow(local, live) {
  if (!local || !local.ok) return '取不到本地值 ⇒ 不比较';
  if (!live  || !live.ok)  return '取不到线上值 ⇒ 不比较';
  if (local.v === live.v)  return '一致（' + local.v + '）';
  if (live.v <  local.v)   return '⚠️ 线上 ' + live.v + ' < 本地 ' + local.v + ' ⇒ 疑似线上运行期抓取/缓存退化（不参与判定）';
  return '⚠️ 线上 ' + live.v + ' > 本地 ' + local.v + ' ⇒ 线上比本地多（本地可能需重跑抓取；不参与判定）';
}
```

★ **只提示不判定**是刻意的：线上/本地的运行期缓存**本来就允许不同**（各自联网、各自复算），
把它接进判定会让汇报本身变成新的漂移源 —— 这条「不判定」本身也被断言守住了。

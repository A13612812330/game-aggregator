### ② 手机专区那个开关：**开关与 chip 各叫各的**

v10.53 把口径从「库里有没有这类记录」改成「**能不能下到**」时，改了**卡面 chip**，漏改了**筛选开关**：

```
开关 #emuToggleSv  →  💾 有云存档      ← v10.5 的旧文案，漏改
卡面 .tg.has-sv    →  💾 有存档        ← v10.53 已改
```

后果：用户看到「开关说有云存档，卡面说有存档」，**同一个数据源两个词**。本轮统一为「💾 有存档」。

★ 顺带查清一个**结构事实**：`emulator.html` 里有**两套筛选条** ——
一套是手机专区的 `emuToggleLib/Both/Tr/Sv`（真实渲染），另一套是从 `index.html` 复制来的
首页筛选条（`svToggle` 等）。后者在手机专区**不渲染**，判据是 `emulator.html` 里
`id="colMain"` 出现 **0 次** ⇒ `renderList()` 取不到容器、`filterBarHtml()` 永不执行。
（这一点在反证里被真实撞到，见 §四.3。）

### ④ 「手游独有 1,645 条」到底是什么（回答用户的前提）

用户判断「**大部分手游都是端游，可能是游戏名称模糊等原因**」。查证结果：**方向对、原因不对**。

手游中心 3,330 条里未挂端游 id 的 1,645 条，分层如下（`tools/_probe-mh-unmatched.js`，只读探针）：

| 层 | 条数 | 占比 | 说明 |
|---|---|---|---|
| ① **垃圾名**（无游戏语义） | **115** | 7.0% | `unins000` / `Setup` / `2016` / `GIANTS Engine` / `EasyAntiCheat Launcher` / `OpenAL Installer` |
| ② 可信可救（属匹配失败） | **32** | 1.9% | 精确 key / 英文段 / 库名以查询名开头 |
| ③ 可疑可救（多为噪音） | **292** | 17.8% | 松散子串（`Resident Evil 4 2005`→`TEVI` 这类，**不采信**） |
| ④ **端游库真没有** | **1,206** | **73.3%** | 见下 |

**④ 里混着三类，逐条看过**：
1. **exe 名 / 启动器名，端游库其实有对应游戏** —— `PlayGTAV`（GTA V，cfg 119）、`gta-sa`（圣安地列斯）、`AC3SP`、`iw3sp`/`iw3mp`（COD4）。**这类就是用户说的「名称对不上」**，需要**缩写/别名表**才能反查，自动化做不了。
2. **真游戏名，但端游库确实没有这一代/这一款** —— `Pro Evolution Soccer 2013`（库里只有 2019/2020/2021）、`F1 2013`（库里 23/24/25）、`MotoGP17`、`NBA 2K14`、`Need for Speed 9`、`Mafia II Classic`、`Mortal Kombat Komplete Edition`、`Hitman Absolution`、`Wolverine`。**这是端游库的内容缺口，不是匹配问题**。
3. **纯工具** —— `rpcs3`（PS3 模拟器）、`Roblox Bootstrapper`、`GIANTS Startup`、`Microsoft Visual C…Redistributable`。

**内容占比（决定「进首页」值不值）**：未挂条贡献 `configs` **7,041 / 16,833 = 41.8%**、`records` **362 / 1,037 = 34.9%** —— **不是长尾噪音**（`Pro Evolution Soccer 2013` 单条 cfg **3,042**，全库最高）。

**但这批数据的形态决定了它不能进首页**：端游库没有对应条目 ⇒ 进了首页就是**空卡**（无详情页、无本体下载、无 MOD/修改器/存档，只有模拟器配置），与首页端游卡的形态对不上。

⇒ **建议：首页合并视图只显示已挂 libId 的 1,685 款**，1,645 条留在手机专区。
⇒ **可另立课题**：`PlayGTAV`→GTA V 这类 **exe 名反查**，但要有缩写表 + 代际护栏，成本高于收益，本轮不做。

### ⑤ 历史注释**刻意不回改** + 术语声明

全项目「云存档」60+ 处，**大多数在注释里**，且许多是**当时口径的原始记录**（如 `★ v10.5 有修改器 / 有云存档`）。改了会让历史失真；不改又会让下轮读注释的人把它捡回界面。

**做法**：
- **用户可见文案**（剥注释后）→ 断言零残留（`test-v1057.js`）
- **历史注释** → 原样保留
- **另加术语声明** → 主源 `groups` 数组前写明「自 v10.57 起一律称「存档」，历史注释里的「云存档」均指同一物，不逐条回改」，`data/xref.js` / `data/saves.js` 头部各加一条

## 四、踩到的坑（5 条）

1. ★ **`grep … | head -30` 被 `.workbuddy/memory/` 的内容占满** —— 扫「云存档」时前 30 行全是历史记忆文件，差一步就写下「`public/` 里没有云存档」。**教训：多目录扫描先排除非项目目录，或改用工具侧 Grep。**
2. ★ **`grep -c "💾 存档"` 在 Git Bash 里返回 0** —— emoji 多字节串被 shell 处理坏，**假阴性**；换 Grep 工具立刻查到 12 处。**教训：含 emoji / 多字节的计数别信 shell 结果。**
3. ★ **`patch()` 目标命中 2 次** —— `…关联）">💾 有存档<` 在 `emulator.html` 里出现 **2 次**：手机专区的开关 + **从 `index.html` 复制来的首页筛选条**（`svToggle`，在该页不渲染）。**这正是 `patch()` 唯一性检查（铁律 58）该拦的**；修法是把 `id="emuToggleSv"` 前缀带上。**副产：查清了「emulator.html 里有两套筛选条」这个结构事实。**
4. **测试里写死了旧文案** —— 改完文案，**7 条断言变红**（`test-related-dl` 1 · `test-v1015` 2 · `test-v1029-detail` 1 · `test-v1032` 3）。**教训：用户可见文案有第 5 份副本 —— 测试里的期望串。**改文案必须连带扫它，否则防线红给你看。
   ★ 还有**第 6 处**：`tools/preview-v1032.js` 的 `MAP` 用**项名**当键取 DOM（`'修改器/云存档': ['#trSvSlot']`），而取不到时会**静默退回默认选择器**（`MAP[nm] || ['#reqSlot']`）—— 不报错、只是量错了地方。本轮一并改掉（键 + 断言文案）。
5. ★ **`test-shared-destructure` 的正则不认 `.js` 后缀** —— 新建探针写了 `require('../data/name-normalize.js')`（**完全合法的 Node 写法**），而该套件的正则要求模块名后**紧跟引号**，于是「已解构」被读成空 ⇒ 报**假红**「用了 `normKey` 却没解构」。修法两件：① 探针改成项目惯例（不带 `.js`）② **测试正则加 `(?:\.js)?` 并补一条自检断言**（用构造样本钉住，不指望仓里恰好有这种写法）。

## 五、架构性收获

1. ★★ **「用户可见文案」是 5 份副本，不是 1 份** —— 主源 + 3 张派生页 + **测试里的期望串**。只改主源会（a）派生页漂移、（b）防线变红。**负向断言可以做成「剥注释后零残留」，这样既守住界面、又允许历史注释原样保留。**
2. ★★ **假红与假绿一样贵** —— `test-shared-destructure` 那条假红若不修，下次真有人漏解构时，这条断言会被当成「又是那个误报」而忽略。**误报会训练人忽略防线。**
3. ★ **反向断言要跟着改名一起加强** —— `!/nm: '云存档'/` 在改名前只禁「**单独**的云存档项」，改名后组合项 `修改器/云存档` 也成了违规写法 ⇒ 升级为 `!/nm: '云存档'/ && !/nm: '修改器\/云存档'/`。**只改正向断言，反向断言会留一个越改越松的口子。**
4. **「不改」也要留痕** —— 历史注释刻意不回改 + 术语声明一处，是「不改」但**看得见**的做法；比「全改」（历史失真）或「全不改」（下轮捡回）都好。

## 七、追加交付物：核心资源游戏表（用户 10-12 追加要求）

用户原话：「**可以，并推送，并且给我一个表，我需要的** ①有本体下载链接+Mod+修改器+存档+存档位置
②…+有手机实测记录的。这部分需要按照热度/下载倒序」。

**产出**：`docs/reports/core-games-2026-10-12.html`（＋ `.csv` / `-mobile.csv`），
生成器 `tools/_gen-core-tables.js`（可重跑）。

**规模（现算，非估计）**：

| 表 | 判据 | 款数 |
|---|---|---|
| ① | Mod ∩ 修改器 ∩ 存档(可下) ∩ 存档位置(有路径) ∩ 端游库有条目 | **153** |
| ② | 表① ∩ `mobilehub.records > 0`（手机实测记录） | **9** |

**★ 关于「本体下载链接」—— 这是六个字段里唯一必须打源站的，实测结果是个硬事实**：

| 状态 | 款数 | 占比 | 含义 |
|---|---|---|---|
| `ok` 可直取 | **7** | 4.6% | 真的拿到了网盘地址（如「天国：拯救2」10 个盘口全解出） |
| `auth` 需源站登录 | **143** | 93.5% | XD 回「你没有权限下载」——**源站策略，不是抓取失败** |
| `nobody` 源站未放本体 | 3 | 2.0% | 机地来源：话题页「本体」专区 `count = 0` |

⇒ 三态**如实标注、不合并**。把 `auth` 写成 `ok` 就等于给用户一列点不开的假链接
（这与 v10.56「定『不做』也要两侧实测」是同一条纪律）。

**★ 表② 热度偏低不是筛错**：手机实测记录全量 **663 款**，其中 `hot > 10000` 的**只有 9 款**
—— 实机跑 PC 游戏的人天然集中在中低体量作品上（实测记录里最热的是「小丑牌」30,394）。
页面里附了一张「**放宽哪个条件能换来多少**」对照表（去掉存档位置 ⇒ 168/10；
只留 Mod + 修改器 ⇒ 258/17，最热 3.0 万），把取舍摆给用户，而不是让他以为筛选写错了。

**本轮新增的两条坑**：

1. ★★ **熔断判据把 `auth` 当成失败** —— 探针首跑写成「连续 N 款**无 ok** 即判定限流」，
   于是 11 款连续的 `auth` 让它 **12/153 就自停**。`auth` 是源站**策略**：重试多少次都还是 auth，
   但它**是有价值的结论**（要写进表里）。⇒ **熔断只能数 `err`**。修正后 153 款全测完、73 秒。
2. ★ **XD 详情页「正文里的网盘链接」不是本体** —— 只狼页面的 HTML 里确实有 1 个
   `pan.baidu.com/s/...`，一度让人以为绕开了权限门槛。查上下文发现它在**用户评论区**里
   （某用户留言贴的）⇒ **不能当下载源**。凡「页面里搜到链接」，先看它在哪个区块。

> 发布日：2026-10-21 · 上一版 v10.92 · 分支 `feat/v10.92-fitgirl-download-ui`

## 一、用户这两个问题，一个否掉、一个做成

| 用户原话 | 结论 | 证据 |
|---|---|---|
| 「FitGirl Repack 中直链下载不是直接下载」 | **做不到，且永远做不到**（在不绕验证码的前提下） | 三个镜像站 2026-10-21 逐个实测，见 §2.1 |
| 「磁力链能否把 Komo-Convert 的下载工具学习并入」 | **能，已并入并跑通全链路** | 服务端 aria2 RPC，见 §3、§5 |

所以本轮的产品动作是**承认前者、兑现后者**：
- 「⬇ 直链下载」**改名为「⬇ 镜像分卷」**，弹窗里写明「三站都要过验证码 / 等倒计时，本按钮不可能做成一键直下」。
- 「⧉ 磁力链」**升级为「☁ 云下载」**：服务器替你下，下完点「保存到电脑」，用户不装任何客户端。

## 二、实测：直链为什么不是直链

### 2.1 三站逐个走（有效链接取自 `/api/fitgirl/parts?slug=doll-impostor`）

| 站 | 请求 | 响应 | 卡点 |
|---|---|---|---|
| `datanodes.to` | `GET /95f2yocxjm8h/…part01.rar` | `200`，落地页含 `<form>`：`op=download1`、`id`、`rand=jvyvg7lr4mz5oywdi2w5p5klcl7lkvpnpmorhky2mm` | — |
| `datanodes.to` | `POST /download` 带 `op=download2` + `rand` | `200` 但页面内出现 **`<p>Wrong captcha</p>`** | **免费下载必须过验证码** |
| `fuckingfast.co` | `GET /b6ytzy435txm` | `403` + `Cf-Mitigated: challenge` + `<title>Just a moment...` | **Cloudflare 人机验证** |
| `filekeeper.net` | `GET /5w89cwj6lgkw/…part01.rar` | `302 → /download`（同类 xfilesharing 落地页） | 同 datanodes 流程 |

### 2.2 由实测得出的三条硬事实

1. **服务端拿不到文件直链**：datanodes 缺 captcha、fuckingfast 缺 JS 挑战、filekeeper 同构。
   唯一路子是服务器上跑无头浏览器替人过验证码 —— 脆弱、随时被打死，且属于绕过访问控制。**不做。**
2. **「直链」这个词在这个体系里是误称**：它指的是「网盘文件页」，不是可 `curl` 的地址。
   按钮叫「直链下载」＝对用户空承诺。
3. **磁力是唯一可被服务端独立完成的路径**：不经过镜像站，直接走 BT 网络。

## 三、实现：三个模块 + 七条接口

### 3.1 模块分工（为什么这样切）

| 文件 | 行数 | 职责 | 为什么单独成文件 |
|---|---|---|---|
| `data/download-guard.js` | 165 | 磁力判据 / 体积 / 磁盘水位 / IP 配额 / 清单净化 | 全是 `(输入)=>{ok,code,reason}` 纯函数 ⇒ 静态套件能穷举边界 |
| `data/download-tasks.js` | 168 | 任务表 + 原子写 + TTL 清理 | 落盘失败不能让服务起不来（坏文件改名留证 + 退回空表） |
| `data/download-engine.js` | 386 | aria2 进程生命周期 + JSON-RPC + 元数据 + 增量对账 | 进程管理有副作用，必须与其他两层隔离 |
| `server.js` | +330 | 七条路由 | — |

### 3.2 移植自 Komo-Convert 的部分（按语义，不是翻译）

| 源文件（.NET，本机只读参考） | 落到哪 | 保留了什么 |
|---|---|---|
| `Aria2Session.cs` | `download-engine.js` | 启动参数逐条对齐、随机端口 + 随机 secret + 仅回环、`bt-metadata-only`+`bt-save-metadata`、`select-file`、`--save-session` 恢复 |
| `DownloadProbe.cs` | `preview()` | 「只取元数据不取正文」、文件数上限、路径边界 |
| `TrackerList.cs` | 未移植 | 本版只放行磁力、不开放自定义 tracker ⇒ 白名单暂时无用武之地（留待 EXE 形态） |

**三处因部署形态不同而刻意改掉**：

1. 桌面版 `aria2c.exe` 随包分发；线上是 linux 容器 ⇒ **无则 `apt-get install aria2`**，且只试一次（`installTried` 记住，不会每个请求都去装）。
2. 桌面版允许 HTTP / 本地种子；这里**只放行磁力** —— 少一条入口就少一类 SSRF 面。
3. 桌面版 gid 只活一次进程；容器会被平台回收 ⇒ **用 `infoHash` 对账恢复**（gid 会变，文件名会被自动改名，只有 infohash 稳定）。

### 3.3 七条接口

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/downloads/previews` | 磁力 → 只拉种子 → 文件清单（不发 `torrentPath`） |
| POST | `/api/downloads/batches` | 凭 `previewId` 入队（服务端发的 id，前端传不了路径） |
| GET | `/api/downloads/tasks` | 任务列表（默认只自己的，`?all=1` 需管理员） |
| POST | `/api/downloads/tasks/:id/actions` | `pause` / `resume` / `cancel` |
| GET | `/api/downloads/tasks/:id/files/:fid` | 保存到电脑（`res.download`，自带 Range） |
| GET | `/api/downloads/quota` | 剩余配额 + 上限（前端先问，避免点完才被拒） |
| GET | `/api/downloads/debug` | 管理员诊断：aria2 现场 + 最近 4KB stderr |

### 3.4 为什么 preview 与 batches 必须分两步

磁力链接**不含体积**。要判「≤ 30 GB」必须先把元数据拉下来（实测 4.1–4.9 秒）。
合成一个接口 ⇒ 用户等 8 秒才被告知「太大」，而这 8 秒已经吃掉了当天的配额。
分两步 ⇒ 看到清单就能放弃，不占配额。

### 3.5 前端（`public/index.html`）

- 行内两按钮：`⬇ 镜像分卷` / `☁ 云下载` + `↗ 原站` 小字。
- 新增弹窗 `#fgCloud`，**z-index 125**（高于 `#fgDl` 的 120）。
- 渲染拆纯函数：`fgcBodyHtml(s)` / `fgcFootHtml(s)` 不碰 DOM ⇒ 静态套件可 `new Function` 注入验九种形态。
- 状态机：`loading → files → starting → downloading/paused → ready`，另有 `error` / `too-large`。
- 「⧉ 复制磁力」**常驻**：服务器不可用时（死种、磁盘满、引擎挂）用户仍有出路。

## 四、踩坑

| # | 坑 | 根因 | 解法 |
|---|---|---|---|
| 1 | preview 90s 超时，一度以为 DHT 不通 | **选的磁力没有 seeder**（Doll Impostor：`conn=0 seeders=0`）；同一引擎换 Astrobuilder 5.0s 成功 | 不是代码问题。诊断必须看 `numSeeders`，不能看「有没有报错」 |
| 2 | `--dht-listen-port=49152-65535` + `--listen-port` 同宽范围 | 宽范围会让 aria2 在大量端口反复绑定，防火墙逐端口丢包 | 去掉这两个参数，用默认端口（PoC 验证过的形态） |
| 3 | debug 端点报 `Failed to parse URL from ` | 直接调 `rpc()` 但没 `ready()` ⇒ `rpcUrl` 是空串 | 诊断端点自己必须先 `ready()`，否则连「引擎起不起得来」都测不出 |
| 4 | 进度条分母比真实文件大 0.8 MB | 用 aria2 的 `totalLength`（含块对齐/元数据），实测 5.09 MB vs 文件 4,270,111 B | 分母改成「选中文件之和」，`dlSync` 不再覆盖 |
| 5 | 任务里挂着 7 个文件，实际只下 1 个 | `tellStatus.files` 返回种子内**全部**条目，只用 `selected` 标记 | 建任务时按 `selected` 过滤；兜底「过滤后为空则取全部」 |
| 6 | `--enable-dht=true` 但拿不到元数据 | 见 #1；另有 `.session` 恢复时 `--pause=true` 让新任务也挂起 | 恢复任务保持 paused（容器回收不该自动跑满带宽），用户点「继续」 |
| 7 | `(cmd &)` 起的 8124 在 Bash 调用结束后被回收 | 子 shell 的进程随父进程退出 | 用后台任务方式启动（`run_in_background`），不要 `( … & )` |

## 六、边界与待办

### 6.1 已知边界（写清，避免下轮当成 bug）

- **速度取决于全网 seeder**：实测这个包只有 1 个 seeder、~130 KB/s。这不是引擎慢，是 BT 网络现状。
  小包（< 2 GB）体验可以；大包两段带宽叠加反而更慢 ⇒ 30 GB 上限就是为此设的。
- **死种无解**：aria2 报 `error` 时前端会提示「可能是死种」，用户只能换一篇或用镜像分卷。
- **`30 GB` 是拍板上限**，不是技术极限；改 `download-guard.js` 的 `MAX_TASK_BYTES` 即可，但磁盘水位（40 GB）要同步调。
- **写盘是否跨容器重建存活 —— 仍未验**（要两次发布比对，v10.92 就没做，本版也没做）。
  若 data 目录不在持久卷上，容器重建后任务表与正文都会丢。**这是上线前必须补的一条事实。**

### 6.2 待办

- ⬜ 线上实测：`apt-get install aria2` 在容器里的耗时、`numSeeders` 是否可达、出口带宽。
- ⬜ 重启恢复的真实演练（`kill` 引擎后 `reconcile` 能否用 infoHash 找回 gid）。
- ⬜ 任务列表 UI：目前只在「同一篇 repack」的弹窗里看进度，没有全局任务中心。
- ⬜ 打包 EXE / 切本机执行端：`vendor/aria2/` 探测路径已留（`.gitignore` 已忽略二进制），接口未定。

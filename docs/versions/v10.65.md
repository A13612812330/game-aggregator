## ① 用户口径

> 「字段未置顶，其次我想多选筛选」（附截图，红框圈出滚动后消失的表头行）

拆成两条：
1. **表头要吸顶** —— 滚动后字段名（来源 / 大小 / 热度 / 更新时间 / 本体 / 修改器 / MOD / 存档 / 链接）必须一直可见；
2. **筛选要多选** —— 平台与资源两组当前只能各选一个。

## ② 根因：表头早就写了 `sticky`，但被祖先的 `overflow` 吃掉了

`.card` 上有一条 `overflow:hidden`（原意是给卡片做圆角裁切）。**`hidden` 会让它成为一个「不可滚动的溢出容器」**，
而 `position:sticky` 的吸附上下文正是「最近的滚动容器」⇒ 表头变成**相对卡片盒吸附**，可卡片自身从不滚动，
吸附**永远不触发**。

**先量化，再改**（`tools/_probe-roster-ui.js`，判据 = 滚动 1500px 后 `th.getBoundingClientRect().top`）：

| 检查 | 实测 |
|---|---|
| 修前 `th.top` | **-1180 px**（表头跑到视口上方 1180px，彻底脱顶） |
| 最近的 `overflow` 非 visible 祖先 | **`DIV.card{overflow:hidden}`** |
| **阳性对照**：只注入 `.card{overflow:visible}`，其它一律不动 | `th.top = 58` ✅ **恢复吸附** |

> 对照坐实根因：不是「没写 sticky」，也不是「`--topbar-h` 算错」，就是这一个词。

## ③ 多选：改前确实是单选（实测基线，不是推测）

| 动作 | 改前结果 |
|---|---|
| 点「有 MOD」 | 选中 `mod`，当前筛选 **325** |
| 再点「有存档」 | 选中**只剩下** `saves`，当前筛选 **1,377** ⇒ **MOD 被顶掉了** |

## ④ 改法

### 表头吸附
`.card` 的 `overflow:hidden` → **`overflow:clip`**。
`clip` 与 `hidden` 的**裁切效果相同**，但 **`clip` 不创建滚动容器** ⇒ 既不破坏 sticky，又保住圆角裁切。
（`visible` 也能修好吸附，但会丢掉圆角裁切 —— 见 ⑥ 的负向守护，这两件事被拆成两条断言分别守。）

另外给表头补了一道 `box-shadow`：吸附时与下方内容有清晰的分离线（否则滚动的行会贴着表头，视觉上像粘连）。

### 多选筛选
- 两组 chip 由「单选按钮组」改为**独立的 toggle**（`aria-pressed` 同步，页面自证多选）；
- **平台 = 并集（OR）**：「端游」与「手游可玩」是两个不同维度，一条记录可同时属于两者，取并集才是「我要看端游 + 手游」的本意；
- **资源 = 组合方式由下拉框显式决定**：`需同时具备`（AND，默认，逐项收窄）/ `任一满足`（OR，取并集）。
  ★ **不设隐式默认** —— AND 与 OR 结论完全不同（实测 181 vs 1521），必须让用户看得见自己选的是哪种；
- **最后一个具体项被取消时自动落回「全部 / 不限」** —— 否则会出现「一个都没选」的空语义死区（用户以为筛掉了全部，实际是没筛）；
- 「全部 / 不限」按钮语义 = 清空选择（等价于不限制），点具体项会自动取消它。

### 文案自证
页面新增 3 处「可多选」提示（两处 chip 组标签 + 说明区第 ③ 条）与第 ③ 条口径说明。
★ 多选是**「看不出错」**的需求：仍写成单选也能点、也出结果，只是永远只能选一个 ——
所以必须让页面自己写清楚，否则下一轮（或下一个人）会把它当单选用。本轮的需求正是这么来的。

## ⑥ 防线：新增 H 段 7 条 + 反证 9/9

`tools/test-roster.js` 40 → **48** 断言。新增 H 段专守「坏了也照样能用」的两类：

| 断言 | 守什么 |
|---|---|
| **H1** | `.card` 的 overflow **不能是 hidden / auto / scroll**（会夺走 sticky 吸附上下文） |
| **H1b** | `.card` 用 `clip`（兼顾圆角裁切 + 不吃 sticky）—— **实现偏好**，与 H1 分层 |
| **H2** | `thead th` 仍是 `position:sticky` |
| **H3** | 吸附位置用 `var(--topbar-h)`（与 topbar 同一真源，不会各自漂移） |
| **H4** | 9 个 chip 都有 `aria-pressed`（多选自证钩子） |
| **H5** | `#resMode` 存在且默认「需同时具备」 |
| **H6** | 页面文案含 ≥3 处「可多选」 |
| **H7** | 每个资源按钮都有对应判定分支（漏一个 ⇒ 点了没反应，不报错也不红） |

`tools/_counterproof-roster.js`（新建）**9 / 9** —— 5 个坏法 + **1 个负向守护** + 基线 + 复绿 + md5 逐字节还原：

| 坏法 | 打坏什么 | 结果 |
|---|---|---|
| A | `overflow:clip` → `hidden` | 恰好红 **H1** ✅ |
| B | 去掉 7 个 `aria-pressed="false"` | 恰好红 **H4** ✅ |
| C | `#resMode` 默认改「任一满足」 | 恰好红 **H5** ✅ |
| D | 吸附位置改硬编码 `58px` | 恰好红 **H3** ✅ |
| E | `RES_T` 的 `saves` 分支改名 | 恰好红 **H7** ✅ |
| **F** | **负向守护**：`overflow:clip` → `visible` | **H1 红 0 次 / H1b 红 1 次** ✅ |

★★ **负向守护抓出了我自己的过度断言**：H1 第一版写的是「必须含 `overflow:clip`」，
于是 `overflow:visible`（**同样不吃 sticky、吸附完全正常**）也会被判红 ⇒ 这是**过度断言**，
它会让未来任何一次合理的实现替换都无故变红。改成「不能是滚动容器」后分层正确：
**H1 = 能力（吸附不能失效，结构性）· H1b = 实现（用 clip 兼顾裁切，可替换但要显式）**。
反证脚本的 `hit()` 也同步改用 `❌\s*H1\b` **词边界精确匹配** —— 否则 `H1b` 的红会污染 `H1` 的绿，负向守护就失效了。

静态防线全量 **49 套 / 3711 通过 / 0 失败**（roster 由 40 → 48，其余无变化）。

## ⑦ 坑：本轮 3 处「我自己造的假红」

1. **探针把 `overflow:clip` 当成可疑祖先** —— 我遍历祖先时判据写的是「computed overflow ≠ visible」，
   而 `clip` 不是 `visible` ⇒ 明明吸附正常，探针仍报「最近 overflow 祖先是 .card」。
   改成只认 `auto|scroll|hidden`（**只有这三种会创建滚动容器**）——
   ★ **探针自己的判据也必须精确**，否则会造出一类看起来像证据的假报告。
2. **截图 `clip` 用的是文档坐标** —— 滚到 1500px 后按 `clip:{y:0}` 截图，截到的是**页面顶部**而不是
   滚动后的视口，于是「表头看不见」这个**截图本身**差点被我当成缺陷。
   改成不带 `clip` 直接截视口。
3. **探针 ⑥⑧ 的判定写错**（先是测平台并集时没清掉资源筛选、又只点掉一项就断言「落回不限」）⇒
   连报两次假红。★ 规律：**探针的「动作序列」和「期望值」都要跟被测语义严格对齐**，
   否则红的是探针不是产品。

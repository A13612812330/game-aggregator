## 六、v10.87.1 发布当轮修正：线上鉴权真漏洞（反代让回环判断失效）

**现象**：v10.87 发布后线上实测，`GET /api/admin/log`、`GET /api/admin/hide-overrides`
**不带任何令牌返回 200** —— 读豁免、读日志、以及共用同一 guard 的 POST 写豁免全部对公网开放。

**根因**：托管反代把 socket 的 `remoteAddress` 变成回环，而 `adminGuard` 的第一条判断是
`if (ip === '127.0.0.1' || '::1' || '::ffff:127.0.0.1') return true` ⇒ 令牌轨根本没被走到。
「回环放行」在反代后面等于**没有鉴权**。

**修法**（server.js `adminGuard`）：
1. 回环豁免改成**三条件 AND**：socket 回环 **且** Host 是本地三形态（`localhost`/`127.0.0.1`/`[::1]`，可带端口）
   **且** 无任何转发头（`x-forwarded-for`/`x-real-ip`/`forwarded`/`x-forwarded-host`/`cf-connecting-ip`）。
   任一不成立 ⇒ 走令牌轨。
2. 令牌取**三通道**：`X-Admin-Token` 头 > `?token=` > `body.token`（反代若剥自定义头仍有路）。
3. 日志 `via` 改取 `req._adminVia`（guard 判定结果），不再在写端点重判 IP。
4. `public/admin.html` 的请求封装改为「正常只发头，403 才降级一次带 query/body 令牌」——
   令牌默认不进 URL、不进访问日志。

**验证（全部现测）**：
- 本地探针 `_probe-v1087-admin.js` **24/24**，新增 19–23 用 `node:http` raw 请求伪造
  `Host` + `X-Forwarded-For` 复现反代形态（`fetch` 禁设 Host）：
  - 19 回环 + `X-Forwarded-For` ⇒ **403**（修复前是 200，这条就是漏洞复现）
  - 20 回环 + 非本地 Host ⇒ 403
  - 21 反代形态 + 正确令牌头 ⇒ 200
  - 22 反代形态 + `?token=` ⇒ 200
  - 23 反代形态 + 错令牌 ⇒ 403
- 静态防线 `test-v1087-admin` **32/32**（新增 B6–B9 钉住 Host 校验、转发头校验、三通道、`_adminVia`，
  删掉任一条件即红，防止后人"简化"回单 IP 判断）。
- run-all 复跑 **4386/4**（4 红 = youxia-match 1 + v1018 3 已知数据漂移，与基线一致）。
- **线上实测（发布后）**：`/api/admin/log` 无令牌 **403** · `/api/admin/hide-overrides` 无令牌 **403** ·
  带 `X-Admin-Token` **200** · `?token=` **200**。六页 md5 全 MATCH

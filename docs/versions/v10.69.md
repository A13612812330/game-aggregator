## ② 实施：折叠筛选面板

### 2.1 结构（静态，`tools/test-v1069-filter-fold.js` S1–S7 守着）

```
.filter-bar
├─ .filter-row            ← ① 排序（常显）   ＋ 生效计数 #filterCount ＋ 折叠按钮 #filterToggle
└─ .filter-body (#filterBody, 默认 .off)
   ├─ .filter-row         ← ② 容量
   ├─ .filter-row         ← ③ 库范围
   └─ .filter-row         ← ④ 资源筛选
```

- **排序行常显**：它是高频操作，且**带着 `#filterCount`** —— 而 `#filterCount` 本身就是
  「当前生效筛选的清单」（收起时实测文案 `命中 19,497 款`）⇒ 收起态**不丢信息**。
- 收起用 **`display:none`**，不是 `max-height` 动画。理由见 ⑤ 铁律 92。

### 2.2 ★★ 折叠态必须是**模块级变量**（本版唯一的技术核心）

`renderList(true)` 用 `col.innerHTML = filterBarHtml() + …` **整块重建** `#colMain`，
而**点任何筛选开关都会调它**（`.size-pills` / `#libToggle` / `#trToggle` 全走这条路）。

⇒ 折叠态如果只写在 DOM class 上，用户**每点一次筛选面板就自己弹回收起**。
所以状态存在模块级变量里：

```js
let curFilterOpen = false;          // ★ 模块级；模板按它渲染，点击只切 class、不重渲染
```

```js
const ft = $('#filterToggle'); if (ft) ft.addEventListener('click', () => {
  curFilterOpen = !curFilterOpen;   // ★ 真翻转（反证坏法 B 打的就是这一行）
  const bar = $('.filter-bar'); const body = $('#filterBody');
  if (bar) bar.classList.toggle('open', curFilterOpen);
  if (body) body.classList.toggle('off', !curFilterOpen);
  ft.classList.toggle('on', curFilterOpen);
  ft.setAttribute('aria-expanded', curFilterOpen ? 'true' : 'false');
  ft.title = curFilterOpen ? '收起筛选面板' : '展开筛选面板（容量 / 库范围 / 资源筛选）';
  if (ft.firstChild && ft.firstChild.nodeType === 3) ft.firstChild.nodeValue = curFilterOpen ? '收起' : '筛选';
});
```

★ 「只切 class、**不重渲染**」是刻意的：重渲染一次会丢掉滚动位置与懒加载状态，
而折叠本身只是显隐，没有必须重建的内容。

### 2.3 总账（★ 全部**现测**，`tools/_probe-fold-ab.js` 同页同视口并排量）

| 指标 | 展开态（= v10.68 状态） | 收起态（v10.69 默认） | 差 |
|---|---|---|---|
| **桌面 1440×1000** 面板高 | **167px** | **50px** | **−117px** |
| **桌面** 首卡 top | **718px** | **601px** | **−117px** |
| **桌面** 首屏完整可见 | **3 条** | **5 条** | **+2 条** |
| **移动 390×844** 面板高 | **236px** | **86px** | **−150px** |
| **移动** 首卡 top | **779px** | **630px** | **−149px** |
| **移动** 首屏完整可见 | **1 条** | **3 条** | **+2 条** |

- 桌面「面板省 117 / 首卡上移 117」**逐像素吻合**。
- 移动「省 150 / 上移 149」差 1px：面板是页内区块，`86 → 50` 之间那 1px 来自
  整数取整（`getBoundingClientRect` 是浮点，探针各处 `Math.round` 一次）。**记录，不修**。
- 文档里 v10.68 留档的移动首卡 top 是 **776**，本轮现测展开态 **779** —— 差 3px 属
  **动态内容抖动**（首屏那几张卡的标题行数/日期分隔行会随数据变），不是回归。

## ③ ★ 顺手修掉一个真缺陷：移动端排序行被拆成 **3 行**

折叠按钮加进排序行之后，移动端实测 **93px**（pills 32 + 计数 18 + 按钮 26），
**比 v10.68 的 115px 只小 22px**，而且分成三行、视觉上比原来更乱。

根因在 **760 断点里原有的一条规则**：

```css
/* 改前 */
.filter-count{flex:1 1 100%; …}   /* ⇒ 计数整行独占 ⇒ 折叠按钮只能再另起一行 */
```

`.filter-count` 是上一版为了让长文案不截断才写成整行独占的。改为：

```css
.filter-count{flex:0 1 auto;min-width:0;margin-left:auto;text-align:right;white-space:normal;line-height:1.35}
.filter-toggle{height:24px;padding:0 9px;font-size:11.5px}
```

- `flex:0 1 auto` ⇒ 与按钮**同行**；
- 放不下时**计数整块换行**（不逐字拆）；
- `white-space:normal` 是刻意的：计数文案是「生效筛选的清单」，**宁可折行也不能被截掉**
  —— 收起状态下它是唯一能看到「筛了什么」的地方（E1/E4/E5 三条断言守着）。

修后移动面板 **86px**（比 v10.68 展开态 236px 小 150px），首卡 **630**、首屏 **3 条**。

## ⑤ 本轮踩的坑（三条已升级为铁律 91–93）

### 91. ★★ 反证脚本自己也有「我以为的数」：期望红几条不能写死

第一版 `_counterproof-v1069.js` 跑出 **6/11**，五条红**全在反证脚本自己身上** ——
它把「期望红几条」写成了字面量 `hit(r, c.expect) === 1`。

可浏览器套件是**每视口跑一遍**（桌面 1440×1000 + 移动 390×844）⇒ 只要那条断言在两个
视口都成立，打坏后必然红 **2** 条 ⇒ 写死的 1 **永远不成立**。

★★ **v10.68 的 11/11 是运气，不是设计**：它命中的那条（`B ② hero 榜单同排`）
在移动端 `.rk-grid` 已被换成**横滑 flex 行** ⇒ 移动端不红 ⇒ 恰好凑成 1 条。
**换一条断言就会当场现形。**

修法：把 `hits`（patch 串在源码里的出现次数）与 `redHits`（期望红几条）**拆成两个字段**，
后者按「这条断言每个视口跑几次」写（本轮 4 个坏法全写 2）。

> 通用形态：**测试夹具本身没有防线** —— 它写的每个期望值都是「我以为的数」，
> 而且没有谁守着它。这类错的味道是「被守护的行为明明是对的，却报红」。

### 92. ★★ 状态不能存在「会被整块重建」的容器上

见 2.2。守护它的断言必须**跨过一次重建**：`C1`（点一下能开）**看不出来**，
`D1`（展开态下点筛选开关、内部整块重建后仍展开）才看得出来。

两条同源细节：

1. **收起用 `display:none`，不要 `max-height:0` 动画** —— 后者把隐藏控件留在**可聚焦序列**里
   （Tab 能跳进看不见的按钮），且 `getBoundingClientRect().height` 报 0 但元素**仍在布局中**。
2. ★ **展开态下模板属性会被点击处理器覆盖** ⇒ 坏法 D 的期望目标**与直觉不同**：

| | 直觉 | 实测 |
|---|---|---|
| 写死 `aria-expanded="false"` 后，谁红？ | `B3`（展开后 aria） | **`D1`** —— `B3` **不红** |

   原因：模板上的属性在首次渲染后就被 `ft.setAttribute('aria-expanded', …)` 覆盖了，
   而默认态本来就是收起 ⇒ 写死的 `"false"` 与正确值**在首屏完全等价**，
   只有**重渲染后仍处展开态**时才暴露。而 `D1` 的断言里恰好带了 `aria === 'true'`。
   ★ 这是**更强的证据**（说明「重渲染」这条路径同时守住了 aria 语义），
     但**期望目标与直觉不同时必须先解释清楚**，再改反证脚本的 `expect`；
     解释不通就说明守护真有缺口。

### 姊妹条：`saveMin` 的教训（承接 v10.68 同型）

`saveMin` 阈值第一版两个视口都写 `120`，桌面**没先测就拍的数** ⇒ 实测省 **117** 直接报红。
它不是「真回归」，是把阈值定在了实测值之上。正解：把**规格**写成判据
（`barMax`：收起后就是「一行」的高度），把**收益**写成下界（`≥100`）。

### 93. ★★ 判「两个元素是不是同一行」要比「垂直区间重叠」，不能比 `top` 相等

做 2.3 的 A/B 实测时，我想确认「`命中 19,497 款` 与折叠按钮是否同行」，
在探针里写了 `Math.abs(a.top - b.top) <= 2` —— **桌面上明明同一行却报「在下一行」**：

| 元素 | top | 高 | 真位置 |
|---|---|---|---|
| `.sort-pills` | 516 | **32** | 同一 flex 行 |
| `#filterCount` | 523 | **18** | 同一 flex 行 |
| `#filterToggle` | 519 | **26** | 同一 flex 行 |

三个 `top` 差 **3~7px** —— 因为**同一行里各元素高度不同，垂直居中后 `top` 天然不等**。
⇒ 正解：`a.top < b.bottom && b.top < a.bottom`（垂直区间相交）。改对后实测：

| 视口 | 排序行 | pills ↔ 计数 | pills ↔ 按钮 | 计数 ↔ 按钮 |
|---|---|---|---|---|
| 桌面 1440×1000 | **32px（一行）** | 同行 | 同行 | 同行 |
| 移动 390×844 | **64px（两行）** | 换行 | 换行 | **同行** |

★ 与 ③ 的描述一致（「计数 + 按钮同行；放不下时那一组**整块**落到下一行」），
但它**差点让我写下一句错话** —— 差一步就把「同行」写成「三行」。

⚠️ **既有代码里有同族写法**：`tools/test-filter-layout.js` 的 `togglesSameLine` 与
「同一行判定留 2px 容差」那两处 —— 它们**当前没错**（比较的是同款同高的按钮），
但**判据对输入敏感**：其中一个按钮因文案变长而变高 ⇒ `top` 差越界 ⇒ **假红**；
两个元素**真换行却恰好 `top` 接近**（高度差 ≈ 行高）⇒ **假绿**。
⇒ 新写统一用「垂直区间重叠」；老的地方**改的时候顺手改**，不专门去翻（避免为改而改）。

# v10.111 首页「管理后台」入口 + 管理台配色回初版

> 2026-10-23 · 用户原话：
> 「首页在名单下给一个直接进入管理页面的按钮，其次管理页面我要最开始的那种颜色样式」

两件事互不相干，一起改、一起测：① 首页侧栏加一个入口；② 管理台配色退回 v10.88 初版。

---

## 1. ① 首页：名单下面加「管理后台」

### 位置

首页侧栏 `<details>站点状态与维护</details>` 里，原来最后一条是
`📋 完整名单 · Roster（2.1 万款体检表）↗`。新入口就加在它**正下方**：

```html
<a class="mini-btn" href="/roster/" ...>📋 完整名单 · Roster（2.1 万款体检表）↗</a>
<a class="side-admin-link" href="/admin" target="_blank" rel="noopener">🛠 管理后台 · Admin ↗</a>
```

`target="_blank"`：管理页是另一套操作界面，不该把当前浏览/筛选状态顶掉。

### ★ 为什么不用 `.mini-btn`

这是本版第一个坑，静态层就能拦，但**看不出来**：

```js
function setBtnsDisabled(v) { $$('#colSide .mini-btn').forEach(b => { b.disabled = v; }); }
```

`setBtnsDisabled()` 是「增量更新 / 校准续跑 / 同步机地」三个按钮共用的置灰开关。
管理入口如果图省事复用 `.mini-btn`，那么**用户在跑增量更新时，管理入口也会被置灰点不动** ——
它不是那个操作的状态，却跟着一起废掉。而且这事在正常情况下完全看不出来（只有跑更新时才复现）。

所以新增独立类 `.side-admin-link`，视觉比 Roster 那条重一档（Roster 是白底灰字＝浏览向，
管理是白底主色字＝操作向），hover 变主色实底 + 白字。

钉子：`test-v10111` 的 A3/A4/A5 三条，判据是「入口那条 anchor 的 class 里没有 mini-btn」
「禁用选择器没被扩到 .side-admin-link」—— 不看类名长什么样，看**关系**。

### 派生页

`renderSide()` 在主源 `public/index.html` 里，四张派生页（emulator / resources / unpack / extract）
都内联了同一段。改主源 ⇒ **必须重建四张**，否则只有首页有入口。已重建，`test-v10111` B 段 5 条钉住。

**也没有回滚整个文件**：v10.106~v10.109 在 `admin.html` 上加的是真实功能
（页面管理并入游戏库、资源管理合并入口、新游检测入口）。整文件 checkout 回旧版 = 静默丢功能。

### 蓝主色与陶土色的关键差别

陶土 `#e79379` 对白字只有 **2.6:1**，所以 v10.105/v10.108 必须把它拆成两档：
`--pri` 做浅底/描边、`--acc`（压深到 `#a9553c` / `#bf6a50`）做可点文字与实底。

蓝 `#2563eb` 对白字是 **5.17:1**（AA 正文级），**可以直接做实底 + 白字**。
所以本版 `--acc` 与 `--pri` 同值，不再有两档。

相应地，旧断言「主色不许做实底（< 3.0:1）」翻成「主色必须够做实底（≥ 4.5:1）」——
**判据方向反了，强度是升的**（原来只要它弱，现在要求它强）。

## 4. 踩坑

### 4.1 G4 被同色系的「背景」误伤

G4 原判据是「CSS 里不许出现 `rgba(…,.22)`」。本版侧栏环境徽标用了 `rgba(37,99,235,.22)`
做**背景**（不是焦点圈），撞上同一个色号 ⇒ 假红。

改法不是把徽标改成 `.16`（那是在迁就断言），而是**把判据收窄到语义**：
从 CSS 里抽出所有「带 box-shadow 的 `:focus` 规则」，断言每一条都是 `.16`。
收窄后反而更贴原意：问的是「每条焦圈是不是 16%」，不是「这个色号出现过几次」。

同型教训见铁律 220（断言绑变量名 = 实现改名就假红）——这里是「断言绑色号 = 别处用同色号就假红」。

### 4.2 文档断言不许让整套崩

`test-v10111` 第一版直接 `readFileSync('docs/versions/v10.111.md')`，文件还没写 ⇒ `ENOENT` 整个崩掉
（exit=2，一条断言都没打印）。改成读不到返回空串，让它**红一条**而不是整套崩。
这是铁律 221 的同一条思路：exit=2 比断言红严重一个量级。

### 4.3 固定等待的第三个案例 —— 这次直接崩，不是红

全量跑完，`test-emulator-page` 报 `exit=1`，栈是：

```
TypeError: Cannot read properties of undefined (reading 'documentElement')
    at init (http://127.0.0.1:8123/:5097:12)
```

第一反应是「页面坏了」，但页面单跑 100/100。真实机制是：

1. `makeDom()` 里写死 `await sleep(1800)` 就认为页面就绪了；
2. 全量跑时 CPU 争抢，`init()` 里的几段 `await fetch` 还没回来；
3. 断言段落一路跑完，执行到 `home.window.close()`；
4. `init()` 的异步续体这时才回来，执行 `document.documentElement.setAttribute(...)` ——
   `document` 已随窗口销毁 ⇒ 抛错。

**页面本身完全没问题，是测试把窗口在别人干活时关掉了。**

关键发现：五张页面（index / emulator / resources / unpack / extract）的 `init()` **末尾**都在设
`document.documentElement.setAttribute('data-ready','1')` —— 这个就绪信号**早就存在，但从没被任何测试读过**
（`grep data-ready tools/*.js` 只有一条静态断言在验它「存在」）。

改成轮询这个信号（上界 20s，超时也判红并把耗时打出来）：

```js
async function waitReady(dom, limit = 20000) { /* 每 100ms 查一次 data-ready，命中后再等 250ms 收尾 */ }
```

效果不只是不崩，还**更快**：ready 实测 **478ms**（原来死等 1800ms），机型匹配 **134ms**。

同段里另有一条 `点「📋 社区配置」按钮` 写死 `sleep(1100)`，也改成有界轮询（面板 **123ms** 就绪）。

**这条的普适教训**：「页面自己会报告就绪」时，不要再在测试里猜时间。
猜短了会假红（断言跑在数据回来前），猜长了既慢又会在 `window.close()` 与异步续体之间留下窗口
—— 后者不是「红一条」，是**整套 exit=1**，比断言红严重一个量级（铁律 221）。

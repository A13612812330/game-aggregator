### ★ 为什么「本体」必须现抓（本轮实证）

上一版缓存 `_core-dl-probe.json` 里 **鬼谷八荒 = `ok`（可直取）**，
本轮现抓同一款：**机地本体专区为空 + XDGAME 全部渠道需登录** ⇒ 已变成**拿不到**。
照抄缓存就是给一列点不开的链接。**缓存只能当对照物，不能当交付依据。**

### ★ 404 回退机制

只按时间取最新一条时，实测踩到**真 404**（游侠那条带中文文件名的直链）。
「最新」与「能下载」是**并列**条件 ⇒ 首选实测 404 时，按从新到旧在同类的 6 条候选里
换一条**真能打开**的，并记下「曾回退」：
- 战锤40K：星际战士2 的存档：`2026-08-13` 实测 404 ⇒ 回退到 `2024-11-06` GTrainers 直链（HTTP 206）

## ⑥ 踩到的三个坑（都会静默出错）

### 坑 1 ★★ 投影时丢字段 ⇒ 结果全变成另一种样子，且不报错
第一版把 `gamesDb` 记录裁成「页面要显示的字段」时，**漏了本体抓取要用的 `jidiId` / `source`**。
后果：20 款全部判成「该款未关联机地话题」，30 款里 **0 款合格**，还被熔断提前打断 ——
**看起来像「源站没数据」，其实是自己的取数错了**。
规矩：**凡是下游还要用的字段，投影时必须留**。

### 坑 2 ★ 拿 `jidi-*` 的 id 去拼 XDGAME 页面 ⇒ 自己造出一个 404
`jidi-187859173`（18 位话题号）拼成 `xdgame.com/game/jidi-187859173.html` 必然 404。
这个 404 是**我们自己造的**，写进排除理由就成了**假证据**（实测明末的真实原因是机地本体专区为空，
却显示成「XDGAME 抓取失败：HTTP 404」）。修法：非 `xd-*` 条目**不走 XDGAME 兜底**，如实返回。

### 坑 3 ★★ 宿主的「安全删除守卫」会拦下发布载荷重建
`fs.rmSync(载荷目录)` 报：
`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":474,"threshold":50,"scope":"turn"}`
—— 一轮内累计删除超 50 个文件即要确认，而载荷有 474 个。
**但重建载荷并不需要真的删目录**：`copyDir` 覆盖同名文件就已经达成「载荷 = 当前项目」。
修法：`_build-deploy-payload.js` 改成**试清空 → 被拦就降级「保留 + 覆盖」**，
并**逐条列出载荷里多出来的文件**（不让它静默带走）。
本轮残留实测 **1 个**：`public/gamehub-overview.xlsx` —— 正是那个**幽灵子页**
（只在载荷里、项目里没有），**降级模式反而保住了它**。

## 一、需求拆解

| # | 用户原话 | 落点 | 判断依据 |
|---|---|---|---|
| ① | 分开管理 | 六个资源域各占一个侧栏条目，各有独立列 / 筛选 / 分页 | 现在所有动作都从「游戏库」一张表进，管理「某类资源」要先在 2 万条游戏里翻 |

## 二、后台：六个资源域（`public/admin.html` + `server.js`）

### 六域与真实规模（2026-10-20 现测，`overview.domains`）

| 域 | 侧栏键 | 条数 | 取数端点 |
|---|---|---|---|
| MOD 帖 | `rm-mod` | **7,825** | `/api/mods/list?kind=mod`（复用） |
| 修改器 | `rm-modifier` | **3,713**（+ 机地修改器帖 1,118） | `/api/trainers/list`（复用）+ `/api/mods/list?kind=modifier` |
| 存档位置 | `rm-save` | **6,334** | `/api/saves/list?stats=all`（复用） |
| 云存档 | `rm-cloud` | **5,335** | `/api/saves/list?stats=all&cloud=1`（复用） |
| FitGirl 资源包 | `rm-fitgirl` | **5,813** | `/api/admin/res?kind=fitgirl`（**新增**） |
| Thunderstore | `rm-ts` | **4,331**（252 社区） | `/api/admin/res?kind=ts`（**新增**） |

### 三条设计决策

1. **只新增两个端点**。`mod / modifier / save / cloud` 四个域继续用 `/api/mods/list`、`/api/trainers/list`、`/api/saves/list`
   —— 它们本来就带 `q/limit/offset` 且行里有 `libId`。再包一层统一端点等于同一语义两份实现（将来口径漂移比没有端点更难查）。
   只有 FitGirl 与 Thunderstore 原本是「按 libId 反查」形态（`byGame` / `byLib`），没有扁平列表 ⇒ 只有这两路补。

2. **六个域共用一个 section（`#view-resm`）**，差异全收进前端 `RM` 表的四个字段
   （`url` / `cols` / `norm` / `src`）。六个域各复制一份 HTML 会立刻漂移 —— 改一处样式，另外五处留在旧版。
   加第七个域 = 往 `RM` 加一项，不动渲染器、不动 HTML。

3. **`gameId` 是第一列，且只在非空时可点**。未匹配的行如实写「未匹配」——
   管理的第一价值是看清缺口，不是把所有行都装成"正常"。

### 端点的三处约束

| 约束 | 为什么 |
|---|---|
| 走 `adminGuard` | 铁律 161：管理视图会持续加私有字段，不能因为「数据本来公开」就不设防 |
| 非法 `kind` 明确 400 | 静默返回空表会把「参数写错」误报成「没有数据」 |
| 游戏名查库带缓存 | ts 域 4,331 个包只对应 252 个游戏，逐行 `byIdGet` 是白烧 CPU |

`overview` 新增 `domains`（七项计数）：全部**现算**，不写死 —— 各源产物每天都在刷新，写死下一轮就变成谎报。

## 三、FitGirl 分卷清单接进详情页（`public/index.html`）

### 交互

```
[FitGirl] Call of Duty: Modern Warfare 4 – v13.1.2      2026-10-19
   ↗ 打开 Repack 页    ⧉ 复制磁力    ▸ 分卷清单        ← 新增第三颗按钮
   ┌ 点开后 ───────────────────────────────────────────
   │ 分卷清单   3 组 · 主包 72 卷（单站口径）· 缓存
   │ ┌ 主包  Ready or Not UNCENSORED  72 卷  [datanodes][fuckingfast][filekeeper]  ⧉ 复制全部 72 条
   │ ├ 变体  Ready or Not              13 卷  ...       ⧉ 复制全部 13 条
   │ └ 可选  bonus soundtrack           1 卷  ...       ⧉ 复制全部 1 条
   └──────────────────────────────────────────────────
```

- **默认收起**：磁力是主路径，分卷是「不用 BT / 只补几个分卷」时的备选。
- **按需拉取**：点开才打 `/api/fitgirl/parts`（服务端单篇解析 + 24h 缓存），回包在 `FG_PARTS[slug]` 里缓存，切镜站/重开不再请求。
- **只给一个镜站 + 切换**：三站是同一套分卷的镜像，全列等于把冗余放大三倍。
- **复制的是当前镜站的完整 URL 列表**（换行分隔），粘进 IDM / JDownloader 批量任务即可。
- **三态如实**：`inline` 给分卷组；`container` 只说「只有镜像清单页」并给外链；`none` 给可操作提示（不是「加载失败」）。

### 改主源必须重建四张派生页

```
node tools/build-emulator-page.js && node tools/build-resource-page.js
node tools/build-unpack-page.js   && node tools/build-extract-page.js
node tools/test-pages-sync.js     # 58/58
```

⚠️ **是四张不是三张**。本轮只重建了 emulator / resources / unpack，`test-pages-sync` 报
「解压助手（extract.html）缺函数 fgPartsHtml, fgToggleParts」——共享脚本是从主源抽取的，
漏一张就漏一份。

## 五、本轮踩到的坑

1. **★ 用 Edit 改 `server.js` 时把相邻端点的函数头吃掉了**：`old_string` 取到
   `app.get('/api/hots', async (req,res) => { ...` 这一行，`new_string` 忘了原样带回 ⇒
   `await is only valid in async functions`。**教训：`old_string` 一旦跨到相邻代码块，
   新串必须原样带回那部分**（或改用只含目标行的最小锚点）。当次靠 `node --check` 立刻抓到。

2. **切片窗口跨端点 ⇒ 假红**：`test-v1088` 的 B14 用固定 600 字符窗口取 `overview` 函数体，
   把下一个端点 `/api/admin/log` 的 `adminGuard` 切了进来，判据恒假。
   改法：切到**下一个端点的起始位置**为止。

3. **`class="view"` 正则漏匹配 `class="view on"`**：数 section 时少算 1 个（首页那个带 `on`）。
   改 `class="view[^"]*"`。

4. **四张派生页 != 三张**：见第三节。

5. **ts 域纯按下载量排序 = 前几页全是同一个包**：Thunderstore 每个社区都带 `BepInExPack`
   （3,300 万下载），按 downloads 排首页 50 条里 30 条同名，管理时看不出「哪款游戏挂了哪些包」。
   改成**按游戏分组 + 组内按下载量降序**（现测前 50 条游戏切换次数 3）。

6. **container 形态样本不能拿成人帖**：`.cache` 里只有两篇是 container ——
   `immortality`（正常）与 `seed-of-the-dead-sweet-home`（成人）。预览页要能公开给人看，取前者。

7. **★ 分域之后暴露出一批真实错配**（这是管理后台的直接价值，不是新 bug）：
   `GET /api/admin/res?kind=fitgirl` 第一条是 `xd-237「使命召唤1」` 挂着
   `Call of Duty: Modern Warfare 4 – v13.1.2` 的 repack。同类错配在 FitGirl 域里可以直接按
   游戏名逐条核对（以前只在详情页单点可见，翻不到全貌）。**已记入待办，本轮不动匹配算法**
   —— 跨源匹配改动影响面大，要单独一轮带反例集做。

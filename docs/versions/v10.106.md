## 1. 本体：为什么只剩一个来源

### 1.1 实测（改前）

`GET /api/download?url=https://www.xdgame.com/game/15568.html`（渔力全开）：

```
ok=True  needAuth=True  count=0
items=6  每条 {server:"百度网盘", serverUrl:"…/plus/download.php?…", real:null, needAuth:true}
```

页面实测（无头浏览器打开 `?open=xd-15568&dl=body`）：

```
「这款游戏暂时没有可直接打开的网盘地址」
XDGAME 官方盘口 · 0 / 6 条可用 · 一行都没有
```

`GET /api/download?url=https://jidiyouxi.com/topic/detail/2117239899`（同一款游戏的机地条目）：

```
ok=True  items=88  real=88  sections: body 35 / mod 1 / modifier 1
```

⇒ 机地那一路是好的；**XD 那一路一条都没显示**；而 `xd-15568` 的
`jidiUrl` 是 `null`，所以打开 XD 这条时也拿不到机地的 35 帖。

### 1.2 三个独立缺陷（缺一个都能复现）

| # | 位置 | 现象 | 根因 |
|---|---|---|---|
| ① | `dlUniFetchBody` | XD 6 个盘口全不显示 | `xdItems = items.filter(i => i.real)`；XD 要登录时 `real` 全是 `null` ⇒ 整类丢光 |
| ② | `dlGroupByPost` | 就算显示也只剩 1 行 | 归帖键退到 `'u:' + it.real`，`real` 为 null ⇒ 6 个盘口的键**全等** |
| ③ | `dlUniFetchBody` | 打开 XD 条目看不到机地 | 跨源只认库里的 `jidiUrl`，而它只在同步时合并过一部分；`xd-15568` 恰好是 null |

### 1.3 改法

- **①** 过滤条件改成 `i.real || i.serverUrl` —— 盘口页地址本身就是出口
  （登录源站后即可取件），只是拿不到最终直链。
- **②** 归帖键改成 `it.postId || it.postUrl || ('u:' + (it.serverUrl || it.real))`。
- **③** 缺机地那一路时现查 `GET /api/library/twin?id=`（精确键 + 名称兜底闸门都在后端），
  命中 `source === 'jidi'` 才补；**失败静默**，不影响 XD 那一路。
- 渲染层：没有直链但有 `serverUrl` ⇒ 渲染成**可点的 `<a>`**，带 `登录` 角标 + 虚线内圈
  （不用变灰：变灰 = 不可点，与事实相反）。
- 统计文案：区分「直链」与「盘口页」，不再一律写「链接均为源站实时解析」。

### 1.4 实测（改后）

同一款游戏 `xd-15568`：

```
页签：XDGAME 盘口 6 · 本体 35
盘口：全部 41 · 迅雷 29 · 夸克 29 · 百度 22 · 磁力 6 · 天翼 1 · 移动 1 · Steam 1 · 其他 1
文案：共 90 个可打开的下载入口（含 6 条磁力）
     （来自 35 个机地资源帖 + 6 个 XDGAME 官方盘口）
     · 其中 6 条是源站盘口页（标「登录」的需登录 XDGAME 后取件）
XD 页签 6 行：渔力全开-百度网盘 / 天翼 / 迅雷 / 夸克 / 移动 / 正版购买，逐行可点
```

机地那条 `jidi-2117239899` 保持 35 帖 / 84 地址不变（这条路径没动）。

## 2. 后台：页面管理并入游戏库

### 2.1 为什么该合

两者查的是**同一个端点** `/api/library/browse`，差别只有两处：

- `group=1` 折叠同款多帖（游戏库）vs 不折叠（页面管理）
- 列里露不露「资料完整度」

同一张表看两遍，用户口径：「页面管理跟游戏库应该是一样的」。

### 2.2 合并后

- 侧栏 11 项 → **10 项**；section 8 个 → **7 个**（`view-pages` 彻底删除）
- 折叠变成一个页内开关 **⧉ 同款合并**（默认开）；关掉 = 原「页面管理」的逐条视角
- 列：封面 / 游戏名 / 游戏ID / 平台 / **评分** / **更新** / 资料 / 状态 / 备注 / 操作
  （评分、更新是原「页面管理」才有的信息，合并后不能丢）
- 行尾只留一个 **编辑**；「游戏资料 / 爬取字段」两种形态改成**弹窗内页签**
  （两个按钮在 1440 宽下会竖排堆叠，把行高撑开）
- 冷门从状态列的一个角标改成标题后的 🌙：状态列同时装「隐藏 + 冷门」两个角标必然折行

### 2.3 实测

| 项 | 值 |
|---|---|
| 侧栏项数 | 11 → 10 |
| section 数 | 8 → 7 |
| 折叠开（默认） | 18,749 条 |
| 折叠关 | 19,764 条（多出 1,015 条同款版本） |
| 表格列 | 10 列，1440 宽零横向溢出 |
| 页面错误 | 0 |

## 3. 视觉：这一版没换皮

上一版（v10.105）把参考站的 cream 主题整块抽过来照搬。用户口径是
**参考它的页面组织，不是套皮** —— 所以这一版改的是**信息架构**（菜单与页面怎么分、
一张表放哪些列、两种视角怎么切换），配色沿用 v10.105 已上线的那套，未再做视觉改动。

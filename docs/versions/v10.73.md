## ② 这一版真正难的地方不是「加功能」，是**语义反转**

v10.72 的 `downloadTo` 有一条 `opts.expectArchive`：**不是压缩包就中止、且一个字节都不落盘**。
那条行为是配着**并列的第二个按钮**（「🗜️ 解压」）设计的 —— 点错了没关系，旁边还有一个「⬇ 直接下载」。

本版只剩**一个按钮**，它就是「下载」本身 ⇒ 再丢弃就等于「**点了没结果**」，比 v10.72 更糟。
所以：

| | v10.72 | v10.73 |
|---|---|---|
| 是压缩包 | 解压 | 解压（不变） |
| 不是压缩包（二进制/图片/…） | ❌ 丢弃 + 不落盘 | ✅ **照存**（`state=saved`，进度 100%） |
| 是 HTML 网页 | ❌ 丢弃 | ❌ 丢弃（**唯一残留的丢弃分支**） |

★ **只有 HTML 仍然丢弃**：存一个 146 字节的错误页/登录页进用户目录是**纯垃圾**，
不是「他想要的文件」。这条留成了唯一的例外，并在防线里显式守着
（`test-v1072-download.js` 的 E5：`not-archive` 时**连目标目录都不许被建出来**）。

新增终态 `saved` 与既有 `error` **必须分开**：报成 `error` 会让浮层飘红，
用户以为没下到，转头去点网盘 —— 白折腾一趟。

## ③ ★★ 新引入的攻击面：文件夹名掺了**外部数据**

v10.72 只往**一个固定目录**里落文件，压根没有「目录名」这个东西。
本版要拼 `游戏名_类别_原链名`，而前两段来自**源站标题**、第三段来自 **URL** —— 全是**别人可控**的字符串。

一个叫 `..\..\..\Windows` 的游戏名（或一条 `..%5C..%5Cevil.zip` 的链接）就能让解压写到落点**之外**。
所以加了两道：

**第一道：`sanitizeSeg(s, maxLen)`（`data/extractor.js`）—— 清洗**
去控制字符 → `\/:*?"<>|` 换 `_` → `\.{2,}` 换 `_` → 去首尾空白与点 → 限长 →
整段只剩 `_`/`.` 视为空 → 只收字符串与数字（对象会被 `String()` 变成 `[object Object]`）。

**第二道：`taskDir(rootDir, opt)` —— 二次边界校验**
```js
if (!full.startsWith(root + path.sep)) return { ok: false, error: '目录名越出落点根目录，已拒绝：' + name };
```
★★ **判据必须带 `path.sep`**：写成 `startsWith(root)` 的话，兄弟目录 `…\GameHub-evil`
会被 `…\GameHub` 这个前缀骗过（分离比较的经典写错法）。防线 `T5` 就盯这一条。

**实测（14 个恶意样本）**：上跳 / 正反斜杠混用 / 盘符绝对路径 / UNC `\\server\share` /
空字节 / 通配非法字符 / 保留设备名 / 尾部点空格 / `../` 重复 60 次 / 纯点点 ——
**零逃逸**，且 `rejected === 0`（每一个的正解都是「清洗成一个合法名字」，没有一个该被下游拒绝）。

## ④ 实现（四段改动）

### `data/extractor.js`
* 新增 `sanitizeSeg` / `taskFolderName` / `taskDir`（导出，纯函数，**不建目录**）。
* `sanitizeSeg` 的参数名用 **`cat`** 不用 `kind` —— server 里 `kind` 已经是「任务类型」（download / run），
  两个 `kind` 撞在一起读代码的人迟早搞混。
* `downloadTo`：
  * **删掉开头的 `fs.mkdirSync`**，改成**落盘前一行**才建（原因见 ⑤ 坑 (a)）。
  * 循环内**只剩 HTML 一条** early-bail；`other` 那条已删。
  * 返回值加 `archive`（`hv.kind === 'archive'`）与 `head`（`zip`/`html`/`other`）。
  * `opts.expectArchive` **删除**。

### `server.js`
* `EX_HISTORY_MAX = 200`；任务对象加 `dir` / `archive`。
* `/api/extract/download`：原链名**由服务端自己从 URL 推**（`fileNameFromUrl(url, b.name)`，
  不采信前端传的 `name`）→ `taskDir` 算子目录 → 失败即 `400` 拒绝 → 下载 →
  非压缩包走 `saved`、压缩包才 `exExtractFile(t, dl.file, passwords, sub.dir)`。
* **历史留档**：`Downloads\GameHub\_下载历史.json`
  * 落盘（`EX_TASKS` 是**内存态**、只留 24 条、重启即丢，而用户恰恰是**重启之后**才想起来找「解到哪了」）。
  * 文件名 `_` 前缀 + `.json` 双保险：`scanDir` 只认魔数，JSON 永远不会被当压缩包收进去。
  * ★ **按 `id` 覆盖不追加**：任务可能跑两趟（填密码续跑），追加会让同一次在历史里出现两条、
    前一条永远停在「待密码」，看着像失败。
  * ★★ `exHistoryPush(t)` 放在 `exRun` 的 **`finally`** —— 保证**没有一条出口能绕过它**
    （散在分支上加迟早漏掉新加的那条，本项目已经出过同族的账）。
  * 写历史失败**绝不许**影响已完成的解压（`try` 裹住、不抛）。
* 新增 `GET /api/extract/history?n=`（**倒序**返回，带 `file` / `total` / `max`）。
* `/api/extract/run` 也补 `t.dir = d.dir`（否则这条入口在历史里路径是空的）。
* `exSnapshot` 多带 `dir` / `archive` / `game` / `cat`。

### `public/index.html`（主源）+ 四张派生页
* `exdBtn(url, name)` → **`exdAttr(url, game, cat)`**：返回**属性串**而不是整个按钮。
  → 属性挂在**已有**的 `<a class="pri" href=…>⬇ 直接下载</a>` **本体**上，**不新造按钮**。
  非本机返回空串 ⇒ 线上仍是浏览器原生下载（线上是只读的，不能走服务端）。
* 两处挂载点（都是已有一个 `<a>` 的地方）：
  * 存档卡 `svfCard(x)`：`exdAttr(f.direct, game, '存档')`
  * GT 资源行 `dlResRowsHtml(items, cat)`：首通道 `exdAttr(l.url, gname(x), cat)`
* ★ **文件夹名第 1 段用 `x.game`（纯游戏名），不用 `svfTitle(x)`** —— 后者是**存档条目名**
  （`赛博朋克2077边缘行者帮瑞贝卡报仇存档下载_游侠网`），拼出来是 `…报仇存档_存档_ALI213-…`：
  类别重复 + 带运营后缀。**这是实拍照出来的**（属性值一眼不对），不是推理出来的。
* 删掉整段 `.exd-go` 按钮样式与其尺寸覆盖；新增 `.exd-path`（浮层里**常驻**显示产物路径，运行中清空）。
* `exdPaint` 加 `saved` 分支 + `not-archive` 文案改写 + `done` 带 `· 源格式 rar`。

### `tools/extract-sections.js` + `tools/build-extract-page.js`（解压助手页）
* 新输入框 `#exGame` / `#exCat` + `datalist#exCatList`（本体/Mod/存档/修改器预设）。
* 新容器 `#exHist` + `ST_TX` 中文名映射 + `loadHistory()` / `renderHistory()` / `histRow()` /
  `copyPath()` / `fallbackCopy()` / `openDir()`；每条历史都带「复制路径」「打开文件夹」。
* 终态文案补齐 `saved`（「已保存（非压缩包）」）与 `not-archive`（「不是文件」）。

## ⑤ ★★ 踩的坑（两条是**真 bug**，都是实测/反证照出来的）

**(a) `downloadTo` 一进门就 `mkdirSync` ⇒ 网页地址也留下空目录。**
v10.73 首轮实测照出：`taskDir` 先给每个任务算好子目录，而 `downloadTo` 开门第一件事就是建它 ——
于是拿一条网盘页去打，**磁盘上多出一个空文件夹**（真目录里那个 `测试网盘页_存档_VP0_…`），
「一个字节都不落盘」的承诺被打脸。
⇒ 改成**落盘前一行**才建。防线 `T6` 是**位置断言**（`mkdirSync` 必须在 `Buffer.concat(chunks)` 之后），
不是裸子串 —— 裸子串拦不住「挪回开头但代码还在」。

**(b) ★★★ 保留设备名逃逸写在「段」上、被下游的「收口」抹掉。**
`sanitizeSeg` 对 `con`/`aux`/`com1`… 加前缀逃逸：`sanitizeSeg('con') === '_con'` ✓
但 `taskFolderName` 紧接着的收口 `replace(/^_+|_+$/g, '')` **把这个前缀又抹掉了**：

```
taskFolderName({game:'con'}) === 'con'      ← 目录名还是保留设备名
```

Windows 上叫 `con` 的目录**根本建不出来**。实测 6 个设备名（`con`/`aux`/`nul`/`com1`/`lpt9`/`prn`）**全部中招**。
⇒ 把逃逸**挪到 `taskFolderName` 里对最终目录名做一次**（这也更符合语义：Windows 的保留名规则看的是
**整个目录名**，中间段叫 `con` 完全没问题，`G_con_x` 是合法目录）。
★ 这个 bug 是**反证 ⑪ 打坏时才暴露的**（详见 ⑥）—— 正常写代码/读代码都看不出来。

**(c) 假红：负向守卫被注释里那句「已删除」判红。**
`!/expectArchive/.test(server.js)` —— 代码确实删干净了，但**注释里必须留着**
「★ v10.73：`expectArchive` 已删除」这句说明 ⇒ 判据把注释当代码，V14 假红。
⇒ 只拦「真的加回来了」的**代码形态**（`expectArchive\s*:` / `opts.expectArchive`）。
注释里的历史说明是**资产**，不是噪声。

**(d) 探针自己踩了「陈旧产物」。**
`_e2e-v1073-download.js` 打的是**真实落点目录**，用固定名 `测试网盘页_存档_…` 去判
「目录没被建出来」。修复前那次留下的空目录 mtime 是 `14:14`，修复后复跑时这条**永久变红**，
而红的是**陈旧产物**、不是本次行为。
⇒ 样本名加**一次性后缀**（`Date.now().toString(36)`），让「存在」只可能由**本次**造成。
（与既有「工作目录按 pid 唯一化」同一条思路。）

## ⑥ ★★★ 反证照出 **4 条假绿 + 1 个真 bug**（本版最有价值的一节）

`tools/test-v1073-download-counterproof.js`：**12 个打坏点**，每个都要求**精确到断言名**变红。
首轮结果 **8/12 通过、4 项报「反证不充分」** —— 那 4 条**不是反证写错了**，是**断言写歪了**：

| 打坏点 | 期望变红的断言 | 首轮结果 | 真因 |
|---|---|---|---|
| ② 清洗整体放宽 | `E1`（14 样本零逃逸） | ❌ **没红** | E1 只判「没爬出去」，而清洗被放宽后 **`taskDir` 兜底拒绝**了越界样本 ⇒ 被算成「安全」。**这条要证明的是「清洗层自己扛得住」** |
| ⑨ `exSnapshot` 丢 `dir` | `V10` | ❌ **没红** | V10 用了裸子串 `dir: t.dir \|\| t.params.dir` —— **历史记录里也有一份**（`\|\| ''` 那一支），删掉 snapshot 那行仍能匹配 |
| ⑩ 收口被删 | `N3`（段为空不留 `__`） | ❌ **没红** | N3 那三个样本的段**本来就被 `.filter(Boolean)` 挡掉**了，收口删掉它们也照样绿 ⇒ 补 `N3b`（段内 `__`）/`N3c`（段自带首尾 `_`） |
| ⑪ 保留名逃逸被删 | `N4`（保留名转义） | ❌ **没红** | N4 拿的是 `con_本体_aux` —— **整名不是保留名**，逃逸有没有被抹掉都一样 ⇒ **直接指向 ⑤(b) 那个真 bug** |

修法（都是**改断言、不是调松**）：
* `E1` 加 `rejected === 0`（「靠下游兜底拒绝**不算过**」）。
* `V10` 收窄到 `^\s*dir:\s*t\.dir \|\| t\.params\.dir \|\| null,` 这一支（行锚 + 唯一后缀）。
* `N3` 拆出 `N3b`/`N3c`（真正让收口干活的两档）。
* `N4` 拆出 **`N4b`**：判**单段** `{game:'con'} === '_con'` —— 并把 `sanitizeSeg` 里那条逃逸
  搬到 `taskFolderName`（= 修 ⑤(b) 的真 bug）。

**二轮结果：12/12 全绿 + 还原后复跑 54/54。**
⚠️ 反证套件**一次只跑一个，绝不并发**（铁律 113：它们改的正是被断言的源文件，
两个实例同时跑会撞出 `EPERM errno -4048`，症状看着像「权限/锁/代码 bug」）。

### 顺带：v10.72 的反证也要跟着改锚点
`test-v1072-download-counterproof.js` 的 **①②⑤⑥⑦ 五个锚点随语义升级失效**
（`exdBtn` 改名 `exdAttr`、`.exd-go` → `.exd-path`、bail 文案改了、`expectArchive` 删除、
`if (f.direct)` 后面紧跟的不再是 `ks.push`）。
★ 它自己的**「靶子存在性预检」直接把这一版拦住了** —— 这个预检就是专为「反证静默失效」设的
（v10.71 出过：格式改了没跟着改，整步失效）。改完 **10/10 全绿**。

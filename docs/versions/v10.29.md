### ③ 右侧悬浮定位条「好像没更新」——两个真根因

用户反馈「好像没更新」不是错觉，是两个独立的真问题：

**根因 A：缺了「评分参数」这一项。** v10.28 的 `D_RAIL` 是 8 项，评分与参数表
（厂商 / 发行日期 / 大小）在正文里已经占了两个区块，条上却没有对应入口。
⇒ 本轮补上，`D_RAIL` **8 项 → 9 项**，并用 `.d-body >` 限定选择器
（否则会命中别处的同名 `.kv`）。

**根因 B：排序键取错了坐标系。** 原来按 `getBoundingClientRect().top` 排序 ——
而条上有一项锚到 `.dl-strip`，它是 `position:sticky`：**一旦吸附，`rect.top` 恒等于视口底部**，
于是 XD 源的「下载」被排到条上第 3 位。

⇒ 改用文档顺序：

```js
found.sort((a, b) => (a.el.compareDocumentPosition(b.el) & Node.DOCUMENT_POSITION_FOLLOWING ? -1 : 1));
```

|---|---|
| 条目数 | **9 项**：评分参数 / 游戏介绍 / 游戏预览 / 配置要求 / 手机配置 / 修改器 / 云存档 / 同分类 / 下载 |

## 三、本轮抓到的三个真问题（都不是测试问题）

### ★ 1. XD 源定位条把「下载」排在条上第 3 位

`rect.top` 对 `position:sticky` 元素是**吸附位置**，不是它在文档里的位置。
断言如果只判「条上 9 项都在、顺序递增」，这条会**全程绿**——因为它确实递增，
只是从错误的锚点算出来的。改用 `compareDocumentPosition` 后，首/末项才对上真文档顺序。

### ★ 2. 点靠下的分区反而往上滚

sticky 顶图滚动中会收窄 **250px → 62px**（差 188px）。落点用 rect 算 ⇒ 一趟差一阶。
这条也**不会让任何存在性断言变红**：按钮点了、有反应、滚动条也动了。

### ★ 3. 三条「既有假红」——用「回退 HEAD」当判据

`test-v1025-dlstrip.js` 的 ⑧⑨⑪ 在改动前就是红的。判定方法不是读代码猜，
而是**把 `public/index.html` 回退到 HEAD 再跑同一套件**：

```
HEAD 版本：通过 9/12 — 三条 FAIL 的报错详情与当前版**逐字相同**
  ⑧ {"open":false,"title":"赛博朋克2077 · 下载资源"}
  ⑨ rows=0 rowVis=false
  ⑪ {"open":true,"title":"赛博朋克2077 · 下载资源","rows":0}
```

根因是 v10.28 起 `.ds-mf` / `.ds-mo` 的落点变了：

| | 旧（套件按它写的） | 新（v10.28+） |
|---|---|---|
| 函数 | `openModList` | `openDlSecPop` |
| 标题 | 拼 kind 名（含「修改器」/「Mod」） | 固定「`<游戏名>` · 下载资源」 |
| 行类 | `.d-dl-it` | `.df-list .dl-it` |
| 区分点 | —— | `.df-tab.on` |

⇒ 换成**有区分度**的判据：不再断言「标题里有没有 kind 名」，
而是断言「**点哪个专区，`.df-tab.on` 就是哪个**」（⑧c / ⑪b）。
这个判据更强：默认落 `secs[0]`（本体），把 `sec: key` 写成 `sec: ''` 就会红（已验证）。

★ 顺带修掉一半真相：`open:false` 是**竞态** —— `openFullPop()` 走 `requestAnimationFrame`
才加 `.on`，而旧的等待条件（`#dlBody` 文本非空）在 loading 占位符上就已成立，
于是抢在 rAF 之前读到了 `classList`。现在先显式等 `.on` 落地。

## 四、本轮改动的两类「危险写法」

### ★ 判据表达式写错会产出「看起来合理的值」

`preview-v1026.js` 首跑 2 条 FAIL（`otherSecNodes = 1`）。逐字符比对后发现写成
`}).dlGo)` —— **漏了 `.dataset`** ⇒ 恒 `undefined` ⇒ `'body' !== undefined` 恒真 ⇒
报出 1，看起来「确实有 1 个别的分区混进来了」。

修法：**当前分区只算一次**存进 `const cur`，并把 `secNodesAll` 留证。

### ★ 反向断言不能打在整个函数体上

「排序那一行里不许出现 `getBoundingClientRect`」最初写成
`!/getBoundingClientRect\(\)\.top/.test(fnBody)` —— **恒假**，
因为我自己的解释注释里就写着「`getBoundingClientRect().top` 反映的是吸附位置」。

修法：**逐行取 `found.sort(` 那一行**再判：

```js
const sortLine = railSyncBody.split(/\r?\n/).find((l) => /found\.sort\(/.test(l)) || '';
ok(/compareDocumentPosition\(/.test(sortLine) && /DOCUMENT_POSITION_FOLLOWING/.test(sortLine), ...);
ok(sortLine.length > 0 && !/getBoundingClientRect/.test(sortLine), '★★ 反向断言：排序那一行里**不许**出现 getBoundingClientRect');
```

★ `expect` 关键字还会撞标题行：`lineFor` 取**第一个**含关键字的行，
标题本身含「反向断言：排序那一行」时会取到标题 ⇒ `expect` 必须写成同一个串。

### ★ 顺带修掉的既存故障：机地源搜索连续 6 天不可用

本不在本轮范围，是查样本时撞到的：

- **现象**：`/api/search` 的 `jidi` 源恒 `ok:false, error:"normDate is not defined"`
  （HTTP 200，0.7 秒即中止，`got 0 / added 0`）；机地同步亦同。**连续 6 日**（09-16 起）。
- **根因**：`fetchers/jidi.js` 第 7 行只解构 `{ HOST_JIDI, getHtml }`，
  而第 **47 / 265 / 288** 行都在调 `normDate(...)`。
  `normDate` 早就由 `shared.js`（L149）导出 —— 是「日期归一化」重构时漏了这一处导入。
- **修**：一行补上 `normDate`。**修后实测** `jidi ok:true | count:1`（此前恒 `ok:false`）。
- **防线**：新增 `tools/test-shared-destructure.js`（7 条，已登记 `SUITES`，总闸 **29 套**）。
  它把导出清单**从 `shared.js` 源码求值**（不手抄，新增导出自动纳入），
  对 19 个引用 `shared` 的文件逐个比对「**用了但没解构**」，
  并对机地三兄弟（`jidi` / `jidiHeadless` / `jidiTopics`）做定点回归。

> ★ 这条防线**首版自己抓到了自己的 bug**：它把 `data/gamesDb.js` 误报成「缺 `dateTs`」。
> 根因是解构正则用了 `[\s\S]*?` —— **跨行吞并**，把下一条 `require('./cover-url')`
> 的解构内容并了进来（`fetchers/jidiModify.js` 更把函数参数解构也混进了列表）。
> 解构列表里不会出现 `}`，改用 `[^}]*` 后 19 个文件全部干净。

> ★ 还有一处「退出码」坑：首版写 `process.exit(fail === 0 ? 0 : 1)`，语义对但
> `run-all.js` 的 `exitTiedToFailures()` 用正则认「**标识符紧跟 `?`**」的形式，认不出，
> 总闸于是报「退出码不随失败变」（= 这套件的护栏在反证里红绿不分，等于没有）。
> 改为 `process.exit(fail ? 1 : 0)` 后实测三态：**正常 0 → 打坏 1 → 还原 0**。

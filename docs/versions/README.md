# 版本日志（GameHub 游戏聚合站）

> 本目录是**逐版完整说明的唯一留档处**：每做一轮改动，就新增一份 `v10.N.md`。
> 这里保留「改了什么 / 真实对照数据 / 踩过的坑 / 验证结果」，供以后回溯与排期。

## 一、留档规范（每次更新都必须遵守）

| 项 | 规则 |
|---|---|
| **放哪** | `docs/versions/v<主>.<次>.md` —— 只放本目录，不再放仓库根目录 |
| **叫什么** | 纯版本号：`v10.40.md`。**不再带任何工具名前缀**（早期叫 `CODEX-DONE-v10.N.md`，已废弃） |
| **必须写** | ① 改了什么 ② 真实对照数据（改动前后实测，不许写形容词）③ 踩过的坑与根因 ④ 验证结果（防线条数 / 是否反证过）⑤ 如实列出**未做**的事 |
| **标题格式** | 首行 `# v10.N —— 一句话要点`（一级标题**恰好 1 个**，由 `tools/test-doc-structure.js` 守着） |
| **引用方式** | 别处引用一律写成可点击链接：`[v10.39](docs/versions/v10.39.md)`（根目录里用这个相对路径） |
| **更新索引** | 新版写好后，在下面的表里补一行；并在 `README.md` 的「更新日志」节换上前一版摘要（只留最近 5 版） |

> 为什么这么严：本项目踩过「整份文档被复制进另一份文档中间、活了 3 个版本没人发现」的事故
> （见 [v10.39](v10.39.md) 第五节）。文档只要没人守，怎么坏都不会报错 ——
> 所以现在 `docs/versions/` 与根目录的文档都在结构闸的覆盖范围内。

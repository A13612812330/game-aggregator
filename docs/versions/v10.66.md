## ① 用户口径

> 「①给我一个可分享的链接
>  ②优化弹窗显示效果，可以每个最多显示5条，最好增加一个跳转到该项目详情页以及弹窗的功能」

拆成三条：
1. **名单页要有对外可分享的链接**（此前只交付本地文件）；
2. **弹窗每类最多 5 条**（此前修改器 22 条、MOD 最多 200 条会铺满整屏，要滚很久才看到下一类）；
3. **弹窗里要能一跳进那一款游戏的详情页 / 资源弹窗**。

第 3 条不是纯前端能做的 —— 站点此前只支持 `?q=` / `?c=` / `?sort=`，**没有按 id 直达某一款**的参数，
所以必须同时加一个 `?open=<本地库 id>`。

## ② 链路设计：roster 只负责「给出 id」，跳转由站点负责

| 环节 | 实现 |
|---|---|
| roster 弹窗按行动作 | `lk.detail` = `/?open=<id>` · `lk.pop` = `/?open=<id>&dl=1` |
| 每类「还有 N 条」 | `/?open=<id>&dl=modifier|mod|save` —— **直达对应页签**，不用落地后自己再点一次 |
| 站点侧 | boot 里读 `?open=`：无 `dl` → `openDetailById(op)`；有 `dl` → `gotoResTab(op, '', DL_UNI_KEYS.includes(dlv) ? dlv : 'body')` |
| 手游中心独有条目 | 本地库没有同款记录 ⇒ 退化为 `/?q=<名称>`（搜索），按钮文案同步改为「在站内搜索这款」 |

★ **为什么走 `gotoResTab` 而不是自己拼 `openUniDownload`**：`gotoResTab` 内部
「先 `await openDetailById` 再 `openUniDownload`」—— 弹窗靠抽屉的会话上下文取 id，
顺序颠倒会出现「弹窗拿到**上一款**游戏的 id」。这条顺序契约由 `test-v1066.js` C2 守着。

## ③ 改法

### roster 页（`tools/gen-roster.js`）

1. `SEC_MAX = 5`；`secHtml(head, arr, moreHref)` 只渲染前 5 条；
2. 超出时渲染 `.more` 区块：「仅显示前 5 条 · 本类共收录 N 条」+「还有 M 条，去详情页看全部 ↗」（带 `moreHref`）；
3. 弹窗新增动作条 `#dActs`（常驻在正文之上，不随内容滚走）：`打开游戏详情页 ↗` / `直接打开资源弹窗 ↗`；
4. **API 基址改同源自适应**：`location.protocol === 'file:' ? 'http://127.0.0.1:8123' : ''`
   —— 上一版写死 127.0.0.1，页面放到 https 站点里就是混合内容，本体实时查询会**静默失败**；
5. 产物同时写 `docs/reports/gamehub-roster-<日期>.html`（归档）与 **`public/roster/index.html`**（线上短链落点）。

### 站点（`public/index.html`，boot 段）

```js
const op = (sp.get('open') || '').trim();
if (op) {
  const dlv = sp.get('dl');
  if (dlv) gotoResTab(op, '', DL_UNI_KEYS.includes(dlv) ? dlv : 'body');
  else openDetailById(op, '');
}
```

改完**必须重建三张派生页**（`build-emulator-page` / `build-resource-page` / `build-unpack-page`）——
共享脚本段会同步过去，四页都带上 `?open=`（由 `test-v1066.js` B 段守）。

## ⑥ 本轮踩的坑（都留在注释里，避免下轮重犯）

1. **★ 又踩一次「模板串里写裸反引号」** —— 这次是在内联 JS 的注释里写了 `` `dl=<页签>` ``，
   整段 HTML 就是模板串 ⇒ 提前结束、语法报错。`test-roster.js` G3 早就在防这个，
   但我是「先改后跑」才被发现 —— 改成中文书名号写法。
2. **★ 探针选款不精确**：按 id 搜索是**子串**匹配，`xd-191` 先命中 `xd-1918`，
   于是「每类最多 5 条」根本没被触发，判据 ⑮ 却显示 ✅（**假绿**）。
   改为在结果里按 `dataset.id` **精确相等**挑按钮。
3. **★ I3 判据钉了文案词形**：first 版判 `includes('去详情页看全部')`，
   坏法 H 把文案改掉后 I3 竟然**没红**（说明判的是措辞不是功能）。
   收敛成「超额说明的**分支**是否存在」（`if(rest > 0)` + `.more`），坏法改为让分支永不成立。
4. **★ 反证的负向守护有两种语义**，混用会把守护自己判红：
   `guard:'other'`（该让另一条红、目标那条绿）vs `guard:'none'`（谁都不该红）。已分开。
5. **★ 产物有两份同字节副本**（归档 + `public/roster/`）⇒ 打坏必须**两份一起打**，
   否则每条坏法都顺带把 I12 打红，真正要看的那条被噪音淹没。
6. **favicon 404 不能用 console 文本过滤**：浏览器给的文本是
   「Failed to load resource: ... 404」，**不含 URL** —— 得用 `page.on('response')` 里的真实 URL 判。

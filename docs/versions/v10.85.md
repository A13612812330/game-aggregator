## 二、实现要点（为什么这么做）

1. **行结构 13→14 列**：`r[13]` = 冷门隐藏态（0/1），构建期由 `coldHide.isHidden(g)` 算好（**口径单一来源**，生成器不抄规则）；手游独有行恒 0（不参与口径）。`meta.nHidden` 与行内标记同源。
2. **静态产物没有重算输入**：hot/publishTs 不在行数据里，构建期算好的 `r[13]` 在管理动作写入后**必须用 POST 响应的 `j.hidden` 回填内存行**再 render —— 客户端猜不出新状态（⇒ 铁律 154）。roster 静态标记在下次重建（daily-sync 09:30）时与库对齐。
3. **show/hide 互斥**：设置一边时从另一边移除（cold-hide 的 `setOverride`），clear 回到规则判定；写盘 `{show:[],hide:[]}` 排序后的稳定形态。
4. **豁免文件入 .gitignore**（`data/hide-overrides.json`）：个人管理状态不入库，与 cold-hide 头注口径一致。
5. **反向筛选走同一 RES_T 表**：`nores = !(mod||saves||trainers||body可下)`，不另写一套「缺资源」逻辑 —— 同一张表就没有第二种组合语义。

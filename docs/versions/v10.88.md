# v10.88 —— FitGirl 下载源结构化（三形态归并）+ 管理后台改真后台 + 备注编辑

> 用户口径：「先给我看看列表 / 优化后的下载源是怎么样的 / 还需要游戏管理页面像真正的后台以及编辑页面弹窗」

## 一、FitGirl 下载源：从「几十条散链接」到「3 个决策点」

### 1.1 页面真实结构（实测，非推测）

一个游戏的下载区由三部分组成：

| 区块 | 形态 | 实测 |
|---|---|---|
| BT 种子 | `magnet:?xt=urn:btih:…` | **11/11 游戏页全有（100%）**；20 帖新老各 10 抽样同样 **20/20** |
| Filehoster 分卷 | 每个 host 一个 `.su-spoiler.dlinks` 折叠块，块内 `host/<id>#<名>.partNN.rar` | 564 条，**真直链 0 条**（全部中间页） |
| 容器 | `filecrypt.cc/Container/*`、`paste.fitgirl-repacks.site`、`pastefg.hermietkreeft.site` | 45 条 |

**关键发现一：三站是镜像，不是更多内容。**
564 条 host 链接 = `datanodes.to` 188 + `fuckingfast.co` 188 + `filekeeper.net` 188，
三份**同名同序**的分卷 —— 冗余 2/3。

**关键发现二：链接多不是因为「历史版本累积」，而是「多个产物组」。**
以 `ready-or-not` 为例，按分卷前缀聚类得到 3 组：

| 组 | 前缀 | 分卷 | 分类 |
|---|---|---|---|
| 1 | `Ready_or_Not_UNCENSORED_...` | 72 | main（无删减版） |
| 2 | `Ready_or_Not_...` | 13 | variant（原版） |
| 3 | `fg-optional-bonus-soundtrack` | 1 文件（同 URL 出现两次） | optional |

`elden-ring-nightreign` 是 37 卷主组 + `fg-optional-videos`（4 卷）+ `fg-optional-bonus-content`（1 文件）；
`forza-horizon-3` 是 14 卷主组 + 5 组单文件附件（4K 视频 / 5 种语音）。

### 1.2 抽样的形态分布（20 帖：新 10 + 老 10）

| 形态 | 数量 | 说明 |
|---|---|---|
| `inline` | **12（60%）** | 页面直接列出分卷 —— 能归并、能一键复制 |
| `container` | **8（40%）** | 只给 paste/filecrypt 清单页（老帖与部分成人帖） |
| `none` | 0 | 完全没有下载区（预告/汇总帖，不在匹配表内） |

**这条最重要**：只按「新帖」抽 14 个会得出「100% inline」的错误结论，
一加上老帖就掉到 60% —— **形态必须按新老两端抽样**。

### 1.3 实现

- **`data/fitgirl-parts.js`（新）**：纯函数解析器
  - 按 `host + 分卷前缀` 聚簇 → 跨 host 合并同一前缀 → 输出 `sets[]`（`main` / `variant` / `optional`）
  - 组内按 URL 去重（实测 `fg-optional-bonus-soundtrack` 同 URL 出现两次，不去重会把 1 个文件算 2 卷）
  - host 白名单（三家 filehoster）+ 容器白名单（三家 paste/filecrypt）—— 同时是防注入护栏
  - 输出 `mode: inline | container | none`，前端据此决定显示「复制按钮」还是「打开清单页」
  - 镜像一致性自检：同一组在各 host 上分卷数不等时进 `warnings`（不静默归并）
- **`GET /api/fitgirl/parts?slug=&id=&fresh=1`**（server.js）
  - slug 必须在 `fitgirl` 表内（白名单，防 SSRF）；24h 缓存落 `.cache/fitgirl/<slug>.parts.json`
  - **缓存带结构版本号 `v`**：解析器输出结构变化时 +1，旧缓存自动失效（见第五节坑）
  - `mode=none` 才 404；`mode=container` 必须 200（否则前端把 40% 的游戏判成「不支持」）

### 1.4 没做什么（明确划掉）

- ❌ **服务端扒直链**：fuckingfast 返回 `403 + Cf-Mitigated: challenge`；datanodes `302 → /download` 落地页；
  filecrypt 容器页 660KB 但正文 `part` 命中 0（JS 解密）。叠加直链绑 IP / 有时效 / 频控 —— 做不到，不是没找对方法。
- ❌ **全量落库**：5,811 游戏 × 均 ~30 卷 = 十几万条，`fitgirl.json` 从 1.26MB 涨到几十 MB，
  载荷与每日同步全变重，收益只是省一次按需抓取 ⇒ 按需 + 24h 缓存。
- ❌ 代下 / 绕风控。

- **设置**：鉴权说明 + **数据边界警示**（线上 data 每次发布被覆盖）+ 最近 5 条操作

### 2.1 备注：后台唯一的「可编辑内容」

## 五、本轮踩坑

1. **缓存必须带结构版本号**（铁律 159）：加 `mode` 字段后，旧缓存（24h TTL 内）返回没有 mode 的对象，
   探针看到 `mode=undefined` 以为是代码没生效 ⇒ 缓存内容必须自带 `v`，读取时校验。
2. **形态结论不能只看新帖**（铁律 160）：新 10 帖 100% inline，加上老 10 帖掉到 60% container ——
   抽样必须覆盖两端，否则按新帖设计出来的功能对 40% 的游戏直接失效。
3. **`pastefg.hermietkreeft.site` 是新容器域名**：只认 `paste.fitgirl-repacks.site` 会让成人帖/老帖被判「没有下载区」。
4. **roster 快照会因「近 90 天」边界滚动而漂移**：09:35 数据 + 10:16 产物，到 14:30 判据已翻 2 条
   ⇒ `test-roster` D6 红。正确处置是**重建产物**（不是放宽断言）—— 差 2 条是真漂移，不是误报。
5. **资源条目没有 `url` 字段**：`resGroups.slimItem` 给的是 `page`（原帖）+ `links:[{label,url,cls}]`，
   角标键名是 `trainers`（复数）。前端按 `url` 写会全是死链。
